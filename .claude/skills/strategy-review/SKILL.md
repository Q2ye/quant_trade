# 策略系统盘查（strategy-review）

> **通用方法论见 `docs/策略盘查框架.md`**（3 阶段 9 检查块完整版）
> 本 skill 是执行入口：按块收集证据 → 定位问题点 → 输出结构化报告。
> 首个验证案例：`docs/高波动动量轮动策略盘查框架.md`（含完整证据链与结论）。

## 一、触发条件

- 策略回测远低于设计目标（目标达成率 < 50%）
- 策略上线前质量验证
- 定期复盘 / 实盘绩效漂移排查
- 新策略设计评审

## 二、盘查流程（先逻辑后数据）

```
0. 填策略画像（名称/类型/目标/当前表现/触发原因）
1. A1 设计目标与逻辑闭环   ← 先做：确认收益来源与目标可达成性
2. A2 标的池 + 相关性
3. A3 Regime 判定（仅 regime 类策略）
4. A4 信号质量
5. A5 止盈止损
6. B1 执行撮合 + 流动性容量
7. B2 资金与风控交互
8. C1 数据质量
9. C2 参数稳健性
10. C3 实盘一致性与失效监控
→ 汇总问题清单（按严重度）+ 根因链条 + 建议
```

**执行顺序原则**：A1 先定性（收益来源是否成立），再逐块用数据验证；每块证据必须可追溯到代码/回测/表。

## 三、各检查块证据收集方法

### A1 设计目标与逻辑闭环（先做）

| 检查项 | 证据方法 |
|:---|:---|
| 收益来源定义 | 读设计文档 + 策略代码，明确赚什么钱、在哪个市场形态有效 |
| 目标可达成性 | **多窗口回测**：牛市段 / 熊市段 / 混合段各跑一次，目标是否稳定成立 |
| 目标过拟合检查 | 若目标只在个别极值窗口成立 → 目标过拟合 |
| **数学可行性推导** | 用实际单笔经济学反推：`单笔期望 = 胜率×avg_win − 败率×avg_loss`，乘年交易数 vs 目标收益，差距是否在 10 倍以上 |
| 哲学内部矛盾 | 检查哲学参数（如 trailing）与标的波动率是否自洽（3% 回撤 vs 日波动 3%+ 的高波动池） |

### A2 标的池 + 相关性

```python
# 波动率 + 相关性矩阵（qfq 日线）
rets = panel.pct_change()   # 18 标的日收益率
vol = rets.std() * np.sqrt(252)        # 年化波动
corr = rets.corr()                      # 相关系数矩阵
# 关注：相关性 >0.7 的对、板块标签映射是否覆盖这些簇
```

| 检查项 | 判定 |
|:---|:---|
| 池覆盖度 / 数据可用性 | 上市时间是否覆盖回测窗口；早期缺失比例 |
| 实际波动率 vs 参数 | 止损/trailing 是否匹配池的实际日波动 |
| 相关性矩阵 | >0.7 的高相关簇是否被板块标签正确规避；组合是否实质集中 |
| 集中度 | 单板块最大暴露 |

### A3 Regime 判定（仅 regime 类）

**隔离测试法**（高波动案例验证有效）：
```bash
# 关年线门 / 关组合回撤，对比收益变化，分解各因素贡献
HV_PARAMS='{"use_csi500_regime": false}' python scripts/backtest_xxx.py <start> <end>
HV_PARAMS='{"portfolio_dd_half": -0.99, "portfolio_dd_cut": -0.99}' python scripts/backtest_xxx.py <start> <end>
# 组合对比：默认 / 仅关A / 仅关B / 全关 → 分解独立压制与叠加效应
```

| 检查项 | 判定 |
|:---|:---|
| 判定准确性 | Regime 信号 vs 实际牛熊（trigger 时点是否滞后） |
| 切换频率 / whipsaw | 开关切换是否造成打脸成本（关掉反而更好 → whipsaw） |
| 与回撤叠加 | 同开压制是否 > 独立之和 → 叠加放大 |

### A4 信号质量

**trades 表配对分析**（真实回测任务）：
```sql
-- backtest_trades: direction='buy' 入场 / 'short' 离场，FIFO 配对
SELECT trade_time, ts_code, direction, price, volume FROM backtest_trades
WHERE task_id='<task_id>' ORDER BY trade_time, ts_code;
```

| 检查项 | 判定 |
|:---|:---|
| 因子 IC | ret20 vs 未来 N 日收益相关性、分层单调性 |
| 信号后收益分布 | 入场后 N 日收益；均值是否为正 |
| 按标的归因 | 哪些标的总计盈利/亏损；个股 vs ETF 贡献 |
| 假信号率 | 入场后短期即止损比例 |

### A5 止盈止损

| 检查项 | 证据方法 |
|:---|:---|
| 盈亏比 | `avg_win / avg_loss`（trades 配对）|
| 大赢家比例 | ≥+20% 离场占比（动量策略应有 >5%）|
| 离场原因分布 | 按收益推断：≤-7% 硬止损 / 0~+5% 过早离场 / +5~20% / ≥20% |
| 参数敏感性 | 放宽 trailing 测试：若更差 → 非简单参数问题 |

### B1 执行撮合 + 流动性容量

| 检查项 | 证据方法 |
|:---|:---|
| 权重落地（H2） | 查引擎 sizer：`weight × available_cash` 逐信号现金复利 → 多信号批次实际部署不足 |
| 交易成本 | `SELECT sum(value), sum(commission), sum(tax) FROM backtest_trades` → 占初始资金比例 |
| 流动性容量 | 标的日均成交额 vs 资金量（单标的下单额 ≤ 日均成交 1%，冲击可控） |

### B2 资金与风控交互

| 检查项 | 证据方法 |
|:---|:---|
| 风控恢复机制粘性 | 回测日志统计减仓天数占比（如 >30% 时间半仓 → 结构性压制）|
| 风控叠加 | 隔离测试分解独立 vs 叠加贡献 |

### C1 数据质量

- 前视：全文搜 `shift(-` / `.iloc[i+` / 缓存未来数据守卫
- 幸存者：标的池是否只用当前存活；市值/基本面用当前值筛历史
- 单位错配：`amount`（千元）/`total_mv`（万元）核对
- 复权一致性：同一天同一复权因子

### C2 参数稳健性

```bash
# 滚动窗口遍历 / 单参数扰动（±10%）
HV_PARAMS='{"momentum_window": 18}' python scripts/backtest_xxx.py <start> <end>
# 观察：最优参数在不同子窗口是否一致；结果对扰动是否高度敏感
```

### C3 实盘一致性

- 实盘序列化是否丢失回测用字段（weight/order_mode）
- 半自动执行延迟 / 人工偏差
- 失效模式：何时该停用（结构性信号 + 触发条件）

## 六、已知经验（高波动案例沉淀）

- **先数学推导再跑回测**：单笔经济学反推目标可行性，比先看回测数字更早定位"目标是否过拟合"
- **隔离测试分解风控**：默认/仅关A/仅关B/全关 4 组对比，拆出各风控独立与叠加贡献
- **大赢家比例是止盈机制健康的金标准**：动量策略 ≥+20% 离场应 >5%，若 <2% 说明 trailing 掐死趋势
- **哲学参数与标的波动率自洽性**：trailing 回撤容忍度必须 ≥ 标的典型单日波动的 2 倍
