# 策略开发全流程审计规则

> 通用检查见 `audit.md`，后端深度检查见 `audit-backend.md`，快速门检查见 `strategy-gates.md`。
> 本规则为策略文件**专属深度审计**，覆盖从需求到交付的完整闭环。

---

## 一、核心硬性强制约束（零容忍，必须 100% 遵守）

### 1.1 严禁一切未来函数

- [ ] **严禁** `shift(-1)`、`shift(-2)`、`df[col].shift(-N)` 任何负向偏移
- [ ] **严禁** `.iloc[i+1]`、`.iloc[i+N]` 访问未来行
- [ ] **严禁** `rolling().apply()` 内访问窗口右侧数据
- [ ] **严禁** 因子计算中使用 `close[t+1]`、`future_price` 等未来字段
- [ ] **严禁** `pd.merge()` 或 `join` 时引入含未来信息的列
- [ ] **严禁** 训练集包含测试集时间段数据（时间轴严格分离：train → val → test）
- [ ] **必须**：所有指标、信号、计算仅使用 `t` 时刻及之前的已确认数据

### 1.2 标准模块化拆分（四大核心模块强制独立）

策略文件必须包含以下四个独立函数/方法，逻辑互不混淆：

- [ ] **`generate_entry_signals()`** — 开仓信号：输入 df，输出开仓信号列表，仅判断是否/何时开仓
- [ ] **`generate_exit_signals()`** — 平仓信号：输入 df + 当前持仓，输出平仓信号列表，仅判断是否/何时平仓
- [ ] **`check_stop_profit_stop_loss()`** — 止盈止损：输入当前持仓成本 + 最新价格，输出是否触发止盈/止损
- [ ] **`calculate_position_size()`** — 仓位管理：输入可用资金 + 信号强度 + 风险参数，输出目标仓位数量

> **判定标准**：四个函数可通过独立单元测试验证，不依赖彼此内部状态。

### 1.3 全覆盖边界场景

- [ ] **空值 NaN**：所有 DataFrame 操作前检查 `df.empty`；计算列检查 `pd.isna()` 并填充或跳过
- [ ] **数据缺失**：因子数据缺失时，对应 Bar 不产生信号（而非用 0/均值填充后强行交易）
- [ ] **连续重复信号**：同一方向连续多 Bar 产生信号时，仅执行第一次，后续去重
- [ ] **持仓状态冲突**：已有持仓时忽略同方向开仓信号；已有空仓时忽略平多信号
- [ ] **重复开仓**：同一 symbol 已有持仓的情况下，新的开仓信号必须被拦截
- [ ] **无法平仓**：连续 N 日（参数可配，默认 5）无法成交时，强制以市场价平仓
- [ ] **停牌处理**：`suspend_date` 或 `volume == 0` 的 Bar 跳过，不产生信号也不更新止损价
- [ ] **价格跳空**：开盘价相比前一日收盘价跳空 > N%（参数可配，默认 5%），当日不交易
- [ ] **极值行情**：当日涨跌幅 > 阈值（参数可配，默认 ±9.5% 即涨跌停），不产生开仓信号
- [ ] **空数据回退**：当所需 K 线不足（如 lookback=60 但实际只有 30 根），静默跳过而非报错退出

### 1.4 严格时序状态管理

- [ ] **显式状态变量**：`position`（0/1/-1）、`entry_price`、`position_size`、`entry_date` 必须显式定义和更新
- [ ] **禁止隐式逻辑**：不允许通过 DataFrame 的某个标记列隐式推断持仓状态
- [ ] **时序闭环**：每根 Bar 按"检查持仓 → 判断平仓/止损 → 判断开仓 → 更新状态"顺序执行
- [ ] **状态持久性**：跨 Bar 状态通过显式变量传递，不依赖 DataFrame 上一次循环的副作用

### 1.5 无歧义原则

- [ ] 参数缺失 → **必须显式定义默认值**并标注 `# TODO: 待确认`
- [ ] 逻辑歧义 → **必须在注释中列出所有疑问**，不自行假设
- [ ] 需求矛盾 → **必须暂停**，提交结构化冲突报告，等待用户确认
- [ ] 禁止"合理假设"、"经验值"、"行业惯例" 等模糊依据

## 二、代码开发规范

### 2.1 功能解耦

- [ ] 每个函数 ≤ 50 行（不含注释和 docstring）
- [ ] 核心计算逻辑封装为独立纯函数（输入 → 输出，无副作用）
- [ ] 禁止单函数 > 100 行
- [ ] 信号生成、风控检查、仓位计算、订单执行 四个阶段在代码中物理分离

### 2.2 参数管理

- [ ] 所有可调参数统一在文件顶部 `DEFAULT_PARAMS` 常量区定义
- [ ] 每个参数附带注释说明：含义 + 取值范围 + 调参方向建议
- [ ] 策略文件内禁止散落魔术数字（非 0/1/-1 的字面量均视为魔术数字）

### 2.3 框架适配

- [ ] 使用 `BaseStrategy` 基类提供的方法，不绕过基类直接操作底层 API
- [ ] 因子数据通过 `DataService.get_factor_data()` 获取，不直接查询 `factor_data` 表
- [ ] 信号返回类型为 `List[Signal]`，字段完整（`ts_code`、`direction`、`confidence`、`timestamp`）
- [ ] 不导入未在 `requirements.txt` 中声明的第三方库
- [ ] 不使用废弃 API（检查基类 changelog）

### 2.4 风控配套

- [ ] **每笔开仓信号必须附带止损价**（硬止损，不允许"等信号再决定"）
- [ ] 止损比例在 `DEFAULT_PARAMS` 中明确声明，取值范围 (-1, 0)
- [ ] 止盈信号独立于平仓信号，不可将止盈逻辑隐式嵌入平仓判断
- [ ] 最大同时持仓数有显式上限
- [ ] 单标的仓位占比有显式上限

## 三、审计维度（代码生成后逐条自查）

### 3.1 未来函数 / 时序偏移

- [ ] 全文搜索 `shift(-`，确认无命中
- [ ] 全文搜索 `.iloc[i+`，确认无命中
- [ ] 检查所有 `rolling()` → `apply()` 闭包内是否有 `iloc` 访问未来索引
- [ ] 检查所有 `merge`/`join` 是否引入了含未来信息的列名
- [ ] ML 策略：确认 `train_end_date < val_start_date < test_start_date`

### 3.2 交易逻辑漏洞

- [ ] 模拟运行：同一 symbol 同一天是否会产生多个同方向信号？（去重检查）
- [ ] 模拟运行：已持仓状态下，开仓信号是否被正确拦截？
- [ ] 模拟运行：空仓状态下，平仓信号是否静默跳过？
- [ ] 模拟运行：止盈止损触发后，是否会再次触发平仓信号（双重卖出）？
- [ ] 模拟运行：连续涨跌停期间，止损是否仍能执行（或正确跳过）？

### 3.3 计算错误

- [ ] 收益率计算：`(sell_price - buy_price) / buy_price`，而非 `sell_price / buy_price - 1`（除数确认）
- [ ] 仓位计算：`position_size = available_cash * risk_ratio / (entry_price - stop_loss_price)`（风险金额法确认）
- [ ] 盈亏计算：含手续费/滑点（如有）
- [ ] 价格取值：止损/止盈用收盘价判断，执行用次日开盘价（T+1 市场）
- [ ] 复权处理：前复权因子一致性检查（同一天所有价格使用同一复权因子）

### 3.4 状态机 Bug

- [ ] 确认状态变量在每个 Bar 结束时被正确更新（不在 Bar 中途被意外覆盖）
- [ ] 确认状态初始化：回测开始时 `position=0`，`entry_price=None`
- [ ] 确认止损触发后状态归零：`position=0`，清理 `entry_price` 和 `position_size`
- [ ] 确认跨日状态不丢失：状态变量在循环外定义，循环内通过引用更新

### 3.5 边界缺陷

- [ ] `NaN` 传播阻断 → `pd.isna(df[col]).any()` 检查后处理
- [ ] 空 DataFrame → `if df.empty: return []`
- [ ] 除零保护 → 分母 `max(abs(x), 1e-8)`
- [ ] 负数底数 → `** 0.5` 前检查 `x > 0`，否则返回 `np.nan`
- [ ] 涨跌停 → `pct_change >= 9.5%` 不买入，`pct_change <= -9.5%` 不卖出
- [ ] 停牌 → `volume == 0` 或 `suspend_date` 存在时跳过该 Bar
- [ ] T+1 → 卖出日期 > 买入日期（至少隔 1 个交易日）

### 3.6 语法 / 调用规范

- [ ] `py_compile` 通过
- [ ] 所有 import 在文件顶部，无循环导入
- [ ] 所有函数有 type hints（参数 + 返回值）
- [ ] 所有公共方法有 docstring（功能、参数、返回值、异常）
- [ ] 使用 `logger` 而非 `print` 输出日志

## 五、禁止项（策略特定）

- **严禁** `shift(-1)`、`.iloc[i+1]`、`df[col].shift(-N)` — 未来数据泄露
- **严禁** 硬编码 Tushare Token、DB 密码、API key 等凭证
- **严禁** 在 `generate_signals()` 中执行网络请求 — 数据应预先存入 DB
- **严禁** 修改 `DEFAULT_PARAMS` 结构而不更新对应策略的 DB `params` 列
- **严禁** `except Exception: pass` — 至少 `logger.warning(...)`
- **严禁** 预期异常打印 ERROR 级别
- **严禁** 策略代码变更后不同步更新 DB `strategies.code`
- **严禁** 不设止损的裸策略
- **严禁** 含未来信息的列参与信号计算
