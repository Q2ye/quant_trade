# 风险管理业务流程：监控 → 告警 → 处理
整个流程分为三层闭环，由风控引擎驱动
```
┌─────────────────────────────────────────────────────────┐
│                    配置层（事前）                          │
│                                                         │
│  定义规则 → 设置阈值 → 选择动作（告警/软阻断/硬阻断）         │
│      ↑                                                   │
│      │  规则分为两级：                                     │
│      │  · 账户级规则（全局，如单日最大亏损 5%）               │
│      │  · 策略级规则（按策略，如单股最大仓位 20%）             │
│      │                                                   │
│      │  每条规则有 severity（严重度）和 action（执行动作）     │
│      │  · alert   = 仅告警，通知但不干预                    │
│      │  · soft_block = 禁止新开仓，已有仓位可平              │
│      │  · hard_block = 强制平仓，立即中断交易               │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│                    监控层（事中）                          │
│                                                         │
│  风控引擎持续轮询（或实时推送）：                            │
│  · 账户净值、持仓市值、回撤幅度                             │
│  · 策略盈亏、交易次数、持仓天数                             │
│                                                         │
│  每轮检查：当前值 vs 规则阈值                               │
│  ├─ 未触发 → 静默                                        │
│  └─ 触发 → 生成 RiskEvent                                │
│       ├─ 记录事件（rule_id, trigger_value, event_type）   │
│       ├─ 推送 WebSocket 实时消息                          │
│       └─ 按规则 action 执行：                             │
│           · alert → 仅推送通知                            │
│           · soft_block → 通知 + 拒绝新开仓订单              │
│           · hard_block → 通知 + 发起强制平仓               │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│                    告警层（事后前半段）                      │
│                                                         │
│  告警记录生成后进入处理队列：                                │
│  · 状态 = "处理中"                                        │
│  · 如果同一规则重复触发 → escalation_count 递增（x2, x3…）   │
│  · 严重级别 = critical 的告警优先处理                       │
│                                                         │
│  页面上的三张汇总卡提供快速入口：                             │
│  · "严重警报" → 点击直达告警列表 + 预筛选 critical 级别       │
│  · "活跃警报" → 点击直达告警列表 + 预筛选"处理中"状态          │
│  · "生效规则" → 点击切到规则配置页                           │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│                    处理层（事后后半段）                      │
│                                                         │
│  交易员/风控经理处理告警，三种结果：                         │
│                                                         │
│  1. 处理 → 弹出备注窗口，填写处理说明                       │
│     · 状态 → "已处理"                                     │
│     · 记录 resolved_by、resolved_at、resolution          │
│     · 示例："已止损减仓50%，剩余仓位跟踪止损"                │
│                                                         │
│  2. 忽略 → 直接标记                                       │
│     · 状态 → "已忽略"                                     │
│     · 适用于已知但无干预必要的场景                          │
│     · 示例："市场系统性风险导致，暂不干预"                   │
│                                                         │
│  3. 重新打开 → 已处理/已忽略的告警可重新激活                │
│     · 状态回到 → "处理中"                                 │
│     · 清除 resolved_by、resolved_at、resolution          │
│     · 场景：处理后被复核发现无效、或情况再次恶化             │
└─────────────────────────────────────────────────────────┘
```

# 回测验证业务流程：策略 → 配置 → 执行 → 分析 → 优化

整个流程分为**五阶段闭环**，由 BacktestEngine 驱动，通过事件系统对外广播进度。

## 页面职责划分

| 页面 | 路由 | 职责 | 定位 |
|:---|:---|:---|:---|
| **BacktestHub** | `/strategy/backtest` | 回测入口枢纽，汇总最近任务与快速入口 | 导航页 |
| **BacktestConfig** | `/backtest/config` | 单策略回测配置（策略选择、股票池、高级参数、风控约束） | 配置页 |
| **BacktestStudio** | `/backtest/studio` | 多策略对比回测 + 参数优化 | 工作室 |
| **BacktestReport** | `/backtest/report/:taskId` | 单次回测完整报告（净值曲线、交易明细、绩效指标、风险分析） | 报告页 |
| **BacktestPeriod** | `/research/backtest-period` | 预定义回溯周期管理 + 周期间对比分析 | 辅助工具 |

## 五阶段闭环

```
┌─────────────────────────────────────────────────────────┐
│                  Phase 1: 策略选择（事前）                  │
│                                                         │
│  来源渠道：                                               │
│  · 策略列表 → 选择已有策略（StrategyList）                  │
│  · 策略模板 → 基于模板快速创建（StrategyTemplates）         │
│  · 策略编辑器 → 新建/编辑策略直接回测（StrategyEditor）      │
│  · 因子库 → 选择因子组合后跳转回测（FactorLibrary）         │
│                                                         │
│  关键决策：                                               │
│  · 单策略回测 → BacktestConfig（完整参数配置）              │
│  · 多策略对比 → BacktestStudio（选策略 + 统一参数）         │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│                  Phase 2: 回测配置（事前）                  │
│                                                         │
│  必需参数：                                               │
│  · 回测周期（start_date / end_date）                      │
│  · 初始资金（initial_capital，默认 100 万）                 │
│  · 基准指数（benchmark，如沪深 300）                       │
│                                                         │
│  可选参数：                                               │
│  · 股票池（stock_pool）—— 限定交易标的范围                  │
│  · 手续费率（commission_rate）—— 默认 0.0003（万三）       │
│  · 滑点设置（slippage）—— 默认 0.001（千一）               │
│  · 印花税（stamp_tax）—— A 股卖出 0.001                   │
│                                                         │
│  高级参数（BacktestConfig 第二 Tab）：                     │
│  · 复权方式（前复权/后复权/不复权）                         │
│  · 数据频率（日线/周线/分钟线）                             │
│  · 基准货币（CNY/USD/HKD）                                │
│                                                         │
│  约束条件（BacktestConfig 第三 Tab）：                     │
│  · 单股最大仓位限制                                         │
│  · 行业集中度上限                                          │
│  · 停牌/ST 股票过滤                                        │
│  · 涨跌停板不可交易                                         │
│                                                         │
│  风控配置（BacktestConfig 第四 Tab）：                     │
│  · 最大回撤阈值（触发停止）                                 │
│  · 单日最大亏损限制                                         │
│  · 连续亏损次数上限                                         │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│                  Phase 3: 回测执行（事中）                  │
│                                                         │
│  后端事件流（BacktestEngine → EventEngine）：              │
│                                                         │
│  1. BacktestStartedEvent                                 │
│     · task_id 创建，状态 → "running"                      │
│                                                         │
│  2. BacktestProgressEvent（checkpoint 推进）：             │
│     · data_loading → 加载行情数据                          │
│     · data_preprocessing → 复权/除权/停牌处理              │
│     · strategy_initialization → 策略实例化+参数注入        │
│     · simulation_running → 逐 bar 回放（SimulationEngine）│
│       ├─ 每 bar：策略产生信号 → 模拟成交（含费用/滑点）       │
│       ├─ 记录 trade/position/equity 快照                  │
│       └─ WebSocket 推送进度百分比                          │
│     · performance_calculation → 计算收益/风险/归因指标      │
│     · report_generation → 生成报告数据                     │
│                                                         │
│  3. BacktestCompletedEvent                               │
│     · 结果持久化到 backtest_equity_curves / backtest_trades│
│       / backtest_positions                               │
│     · 状态 → "completed"，可查询结果                       │
│                                                         │
│  4. BacktestFailedEvent（异常）                           │
│     · 状态 → "failed"，记录错误信息                        │
│                                                         │
│  前端交互：                                               │
│  · WebSocket 订阅 backtest.progress → 实时进度条           │
│  · 完成后自动跳转 BacktestReport（或当前页展示结果）         │
│  · 支持中途取消（cancel_backtest_task）                    │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│                  Phase 4: 结果分析（事后）                  │
│                                                         │
│  净值曲线（BacktestHeatmapChart / MultiStrategyChart）：   │
│  · 策略净值 vs 基准指数 对比曲线                            │
│  · 回撤阴影区域标注                                         │
│  · 买卖点标记                                              │
│                                                         │
│  绩效指标（PerformanceTable）：                            │
│  · 年化收益率（annual_return）                             │
│  · 夏普比率（sharpe_ratio） / 索提诺比率（sortino_ratio）   │
│  · 最大回撤（max_drawdown）+ 回撤恢复天数                   │
│  · 卡尔玛比率（calmar_ratio）                              │
│  · 胜率（win_rate）/ 盈亏比（profit_loss_ratio）            │
│  · 年化波动率（annual_volatility）                         │
│  · Alpha / Beta / 信息比率                                 │
│                                                         │
│  交易分析：                                               │
│  · 交易明细列表（BacktestTrade 实体）                       │
│  · 持仓快照（BacktestPosition 实体）                       │
│  · 月度/年度收益分布（MonthlyReturnChart）                  │
│  · 盈亏分布直方图（ProfitDistributionChart）                │
│                                                         │
│  风险分析：                                               │
│  · VaR（Value at Risk） + CVaR                            │
│  · 压力测试（极端行情回放）                                 │
│  · 回撤对比（DrawdownComparison）                          │
│                                                         │
│  多策略对比（BacktestStudio）：                             │
│  · 多条净值曲线叠加对比                                     │
│  · 绩效指标并排对比表                                       │
│  · 回撤曲线叠加对比                                         │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│               Phase 5: 参数优化（可选迭代）                  │
│                                                         │
│  触发方式：                                               │
│  · BacktestStudio → 选策略 → 点击"参数优化"                │
│  · BacktestConfig → 点击"参数优化"                         │
│                                                         │
│  优化方法（OptimizationEngine）：                          │
│  · 网格搜索（Grid Search）—— 遍历参数组合，适合 2-3 个参数   │
│  · 遗传算法（Genetic Algorithm）—— 适合高维参数空间         │
│  · 贝叶斯优化（Bayesian Optimization）—— 采样效率高         │
│                                                         │
│  后端事件流：                                              │
│  · BacktestOptimizationStartedEvent                      │
│  · BacktestOptimizationProgressEvent（每轮迭代进度）       │
│  · BacktestOptimizationCompletedEvent（最优参数+敏感度）    │
│                                                         │
│  结果展示：                                               │
│  · 热力图（ParameterSensitivity / HeatmapChart）           │
│    —— 2D 参数网格 + 颜色映射收益                           │
│  · 参数敏感度分析表（ParameterTable）                       │
│    —— 每个参数的最优值、敏感度、稳健性                       │
│  · 最优参数组合 + 部署建议                                  │
│                                                         │
│  参数更新：                                               │
│  · 优化结果可直接"应用"到策略 → 更新策略配置                 │
│  · 或"另存为新策略"保留原版本                               │
└─────────────────────────────────────────────────────────┘
```

## 辅助工具：回溯周期（BacktestPeriod）

回溯周期是**预定义的时间区间模板**，用于在不同市场环境下批量验证策略鲁棒性。

```
策略 + 周期模板 → 批量回测 → 周期对比

示例：
  策略A ─┬─ 2023 牛市周期 → 年化 +23.5%，夏普 1.23
         ├─ 2022 熊市周期 → 年化 -12.3%，夏普 -0.45
         ├─ 2020 震荡周期 → 年化 +8.7%，夏普 0.67
         └─ 2018-2024 全周期 → 年化 +15.2%，夏普 1.10

对比结论：策略 A 在牛市中表现优异，熊市中回撤可控，整体鲁棒。
```

周期对比的指标维度：年化收益率、夏普比率、最大回撤、胜率。

## 回测工作室与回溯周期页面 — 符合性分析

### 回测工作室（BacktestStudio.vue）

| 维度 | 状态 | 说明 |
|:---|:---|:---|
| 策略选择 | ✅ 结构正确 | 穿梭框（Transfer）选策略，支持多选对比 |
| 回测参数 | ✅ 结构正确 | 日期范围、初始资金、基准指数 |
| 对比图表区 | ✅ 布局正确 | 净值曲线/绩效指标/回撤对比三 Tab |
| 参数优化区 | ✅ 布局正确 | ParameterOptimizer → HeatmapChart + ParameterTable |
| **API 集成** | ❌ 缺失 | `runMultiBacktest()` 直接赋值硬编码占位数据 |
| **实时进度** | ❌ 缺失 | 无 WebSocket 订阅回测进度事件 |
| **结果持久化** | ❌ 缺失 | 完成后未跳转报告页或持久化 |
| **exportResults** | ❌ 占位 | 显示"导出功能开发中" |
| **参数优化** | ❌ 占位 | `runOptimization()` 直接返回输入参数，未调用后端 |
| 状态覆盖 | ⚠️ 部分 | Loading/Error 已覆盖，缺少"运行中"进度态和 Empty 态 |

### 回溯周期（BacktestPeriod.vue）

| 维度 | 状态 | 说明 |
|:---|:---|:---|
| 周期 CRUD | ✅ 功能完整 | 新建/编辑/删除/搜索/筛选，表单验证齐全 |
| ECharts 图表 | ✅ 可视化完整 | 性能柱状图含年化收益+夏普+回撤三指标 |
| 周期对比 | ✅ 功能完整 | 多选周期 + 指标选择 + 柱状图对比 |
| 状态覆盖 | ✅ 完整 | Loading/Error/Empty/Data 四态 |
| **API 集成** | ❌ 缺失 | 周期数据存于本地 ref，未同步后端 DB（`backtest_scenarios` 表） |
| **回测触发** | ❌ 占位 | "回测"按钮仅显示提示，未跳转 BacktestConfig 或调用 API |
| **统计分析** | ❌ 硬编码 | `analysisStats` 为固定值，未根据实际数据计算 |
| **与工作室联动** | ❌ 缺失 | 选中周期后无法一键带入 BacktestStudio 进行批量回测 |

### 关键缺失与修复优先级

| 优先级 | 问题 | 影响 |
|:---|:---|:---|
| P0 | 三个回测页面均未接入后端 API | 回测结果非真实数据，无法验证策略有效性 |
| P1 | BacktestStudio 无进度跟踪 | 用户点击"多策略回测"后无反馈，体验中断 |
| P1 | 回溯周期"回测"按钮无效 | 功能入口存在但不可用 |
| P2 | 回溯周期统计为硬编码 | 新增/删除周期后统计数字不变 |
| P2 | 周期与工作室无联动 | 两页面功能割裂，无法形成闭环 |

### 建议修复路线

1. **BacktestConfig** 先接入后端 API（`create_backtest_task`），跑通单策略回测全链路
2. **BacktestStudio** 复用 BacktestConfig 的回测逻辑，扩展为多策略对比
3. **BacktestPeriod** 接入 `backtest_scenarios` 表，# 回测按钮跳转 BacktestStudio 并带入周期参数
4. 三个页面统一通过 WebSocket 订阅 `backtest.progress` 事件
