## 一、引擎体系设计（22 个 EngineBase 子类）

### 1.1 引擎基座（core/engines/）

```
core/engines/
├── base/engine_base.py        # EngineBase：生命周期状态机 + 依赖检查 + 后台任务
├── system/event_engine.py     # EventEngine：发布/订阅异步事件总线（max_workers=10, queue_size=10000）
├── system/main_engine.py      # MainEngine：拓扑排序加载模块、引擎注册、SystemStartedEvent
├── system/engine_registry.py  # EngineRegistry：引擎注册表
└── types/                     # entities.py（EngineConfigEntity）/ enums.py（EngineType）
```

**EngineBase 生命周期**：`initialize → start(依赖检查→后台任务→事件订阅) → running → stop(force/timeout) → destroyed`
- `_on_initialize` / `_on_start` / `_on_stop` / `_on_force_stop` 为引擎特定钩子
- `_start_background_tasks` / `_stop_background_tasks` / `_monitoring_loop` 后台任务模板

### 2.3 已知核心发布/订阅关系（代码实证）

```
strategy.StrategyManager --发布 StrategySignalEvent--> trade.SignalEngine（_on_start 订阅）
trade.SignalEngine --发布 RiskCheckRequestedEvent--> risk.RiskEngine（异步通知）
trade.SignalEngine --同步调用--> risk_engine.check_signal()
trade.SignalEngine --发布 RiskViolationEvent--> risk（风控违规）
trade.SignalEngine --发布 monitor.trading.signal--> monitor（实盘信号推送）
data.SyncEngine --发布 data.sync.completed--> market.MarketEngine（清缓存）
MainEngine --发布 SystemStartedEvent--> 各引擎（启动后台任务）
```

> 完整订阅关系以各引擎 `_on_start()` 中的 `event_engine.subscribe(...)` 为准，详见各模块设计文档（`02-功能设计/`）。

## 四、Repository 层设计（126 个 repo 文件）

## 五、数据管道实现（代码实证链路）

### 5.1 实际运行链路（2026-08 实证）

```
Tushare Pro API
  → data 模块 sync_service（batch task_id + N child task_id 两层任务体系）
  → 各 data_type 同步函数（_sync_xxx）
  → 直接调 DataQualityService.check_data_quality（handlers.py 同步完成后）
  → TimescaleDB 超表
```

### 5.2 已知实现偏差（相对设计）

| 项 | 设计 | 实际 |
|:---|:---|:---|
| Clean 环节 | Sync→Clean→Quality 三段流水线（DataManager.execute_data_pipeline） | **Clean 引擎未接入运行路径**（`data_manager.py` 流水线无实例化调用） |
| Quality 环节 | QualityEngine | 直接调 DataQualityService（不经引擎） |
| 同步任务两层体系 | batch + N child | ✅ 一致（详见 `02-功能设计/数据模块/数据同步核心逻辑.md`） |

### 5.3 因子数据链路

```
factor_definitions → factor_calculators（calculate_ma/atr/rsi/boll 等）→ factor_data 超表
  → factor_scores（stock_service.get_stock_factor_scores 365 日窗口分位）
  → 策略消费（bottom_strategy 读 atr_ratio_20/market_regime 等因子）
```
