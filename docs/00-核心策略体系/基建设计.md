## 一、价值评估结论

基于项目现状（回测已有 15 个指标卡片、月收益图、回撤图、基准对比；无失效监控），
对建议项逐一评估，区分"值得加"与"不值得加"。

### 1.1 值得加（有价值）

| # | 优化项 | 价值 | 服务什么问题 |
|:--|:--|:--|:--|
| 1 | **卡玛比率**（年化/MDD） | 高 | 回答"每担 1% 回撤赚多少"，比夏普更直观 |
| 2 | **分年度明细** | 高 | 识别策略是否只靠某一年（过拟合诊断） |
| 3 | **最大回撤区间** | 中 | 知道"何时最惨"（从哪日到哪日） |
| 4 | **连续亏损次数** | 中 | 评估策略"连续打脸"承受度 |
| 5 | **月盈亏分布** | 中 | 正/负月占比直方图（已有月收益图，增强分布维度） |
| 6 | **策略失效监控模块** | 高 | 从"事后复盘"变"事前预警"——项目完全缺失 |
| 7 | **平均持仓天数** | 中 | 评估换手是否过度 |

### 1.2 不值得加 / 已有

| 项 | 原因 |
|:--|:--|
| 单笔最大盈利/亏损 | 已有平均单笔，交易列表可看明细 |
| 波动率 | 已有 |
| 夏普 / 胜率 / 盈亏比 | 已有 |
| 基准对比全套（Alpha/Beta/信息比率） | 已有 |
| 实盘"剩余可用资金 < 保证金 200%" | A 股无保证金概念，不适用 |

## 二、回测报告增强设计

### 2.1 后端：回测 result 增加 5 个指标

在 `BacktestResult.to_dict()` 增加：

```python
# 新增指标
"calmar_ratio": 年化收益率 / 最大回撤（绝对值）              # 卡玛
"yearly_returns": [                                          # 分年度
    {"year": "2024", "return": 0.35, "max_drawdown": -0.12},
    ...
],
"max_drawdown_period": {                                     # 回撤区间
    "start": "2024-01-XX", "end": "2024-02-XX", "depth": -0.25
},
"max_consecutive_losses": 3,   # 连续亏损次数（连续负收益月数）
"avg_holding_days": 16.8,      # 平均持仓天数（从 trades 配对计算）
```

**计算来源**：

| 指标 | 来源 | 算法 |
|:--|:--|:--|
| 卡玛比率 | annual_return / max_drawdown | 年化 / \|最大回撤\| |
| 分年度明细 | equity_curve | 按年切片，逐年算收益 + 年内最大回撤 |
| 最大回撤区间 | drawdown_curve | 找最深点，回推前一次创新高日，后推修复日 |
| 连续亏损次数 | monthly_returns | 最长连续负值月数 |
| 平均持仓天数 | trades | 买入→卖出配对，平均持仓自然日 |

### 2.2 前端：BacktestReport.vue 增加

**指标卡片行**（在现有 15 卡后加）：

```html
[卡玛比率] [平均持仓]
```

**新增"分年度明细"区块**（在月度收益图旁）：

```html
<div class="metric-card">
  <h3>分年度表现</h3>
  <table>
    <tr><th>年份</th><th>收益</th><th>最大回撤</th></tr>
    <tr v-for="y in report.yearlyReturns">
      <td>{{ y.year }}</td>
      <td :class="y.return >= 0 ? 'text-rise' : 'text-fall'">{{ (y.return * 100).toFixed(1) }}%</td>
      <td>{{ (y.max_drawdown * 100).toFixed(1) }}%</td>
```

**新增"回撤区间 + 连续亏损"展示**：

```

连续亏损月份：3 个月
```

### 2.3 月盈亏分布（用户特别提到）

## 三、策略失效监控设计（新模块）

### 3.1 定位

项目 `monitor` 模块新增**策略健康度检查**，每月运行，检测运行中策略是否失效。

### 3.2 数据来源（复用现有）

| 数据 | 来源 |
|:--|:--|
| 历史回测指标 | `backtest_tasks.result` |
| 实盘信号频率 | `signals` 表 |
| 实盘净值 | `equity_curve` |
| 市场环境 | `market_state_daily` |

### 3.3 检查逻辑

```
每月末运行，对每个运行中的策略：

【预警（需关注）】
⚠ 连续 3 个月负收益
⚠ 最近 3 个月收益 < 历史同期 1/2
⚠ 最近 3 个月最大回撤 > 历史最大回撤的 80%
⚠ 信号频率异常（最近 3 个月交易次数 vs 历史平均，偏差 > 2x）

【停用】
● 最大回撤创新高且 > 30%
● 连续 6 个月净值不创新高
● 最近 1 年收益 < 0
```

### 3.4 实现

**后端**：`modules/monitor/services/strategy_health_service.py`

```python
async def check_strategy_health(strategy_id: str, months: int = 3) -> Dict:
    """
    返回策略健康状态：
    {
        "status": "healthy" | "warning" | "stop",
        "alerts": ["连续3月亏损", "回撤超历史80%"],
        "metrics": {近3月收益/回撤/交易次数, 历史平均...}
    }
    """
    # 1. 从 equity_curve 聚合近 3 月收益、回撤
    # 2. 从 signals 统计交易频率
    # 3. 对比历史基准 → 判定状态
    # 4. 返回预警原因列表
```

**前端**：`src/views/Monitor/StrategyHealth.vue`

```html
策略列表 + 健康度状态徽章（绿 healthy / 黄 warning / 红 stop）
点击策略 → 查看预警原因 + 关键指标对比
```

### 3.5 价值

把"策略失效"从**事后复盘**变**事前预警**——7.1 空仓、8.x 回测劣化这类问题，
监控模块能提前标记"策略可能失效"，避免等亏到受不了才复盘。

## 四、实盘监控设计（"三个数"）

### 4.1 定位

项目已有当日盈亏 / 回撤 / 资金的基础计算能力，缺的是**监控预警展示**。

### 4.2 三个核心数

| 指标 | 关注点 | 正常范围 |
|:--|:--|:--|
| 当日盈亏 | 今天亏了多少 | 单日 < 总资金 3% |
| 当前总回撤 | 从最高点跌了多少 | < 历史最大回撤 |
| 剩余可用资金 | 还有多少钱能交易 | 足够覆盖持仓（A 股无保证金） |

### 4.3 决策触发（仅 3 种情况）

1. 总回撤超过警戒线 → 减仓或暂停
2. 可用资金不足 → 补充资金或减仓
3. 监控模块发出预警 → 评估是否停用策略

### 4.4 实现

- **后端**：`modules/account/services/asset_service.py` 已有当日盈亏/回撤计算，增加"阈值预警"逻辑
- **前端**：实盘监控页（或账户页）展示三个数 + 异常高亮

## 六、影响范围与风险

### 6.1 跨模块影响

| 模块 | 影响 |
|:--|:--|
| `modules/backtest`（回测服务） | 增加 5 个指标计算（纯新增，不影响既有 result） |
| `modules/monitor`（监控） | 新增 strategy_health_service（新文件） |
| `modules/account`（账户） | 增加预警逻辑（可选） |
| `quant_web/src/views/StrategyCenter/Backtest` | 回测报告加卡片 + 分年度表格 + 分布图 |
| `quant_web/src/views/Monitor` | 新增 StrategyHealth 页 |

### 6.2 风险

| 风险 | 说明 | 缓解 |
|:--|:--|:--|
| 分年度明细样本短 | 回测区间不足 1 年时无法分年 | 不足 1 年显示"样本不足" |
| 卡玛比率分母为 0 | 回撤极小或 0 | 分母 < 1e-6 时显示 "--" |
| 失效监控误报 | 策略自然回撤被误判失效 | 预警（warning）与停用（stop）分级，仅 stop 才停用 |
| 连续亏损依赖月收益 | 回测区间短时月数少 | 最少 6 个月才启用该指标 |
