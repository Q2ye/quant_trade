# 核心策略体系（按策略分目录）

> 2026-11-22 重组：**一个策略一个目录，目录内只放该策略自己的文档**。
> 跨策略的架构/方法论放 `00-总览架构/`；可迁移的机制与知识放 `docs/10-可复用资产/`。

## 收录边界（唯一判据：策略生命周期，不看文档类型）

| 策略状态 | 放哪 |
|:--|:--|
| **运行中** / **在研发未证伪** / 有实盘价值（含暂停） | ✅ 本目录 `<策略>/` |
| **已淘汰**：证伪、方向作废、策略删除、R 阶段 FAIL | ❌ 全部移入 `docs/04-归档/策略历史/<策略>/` |
| 跨策略方法论/架构 | `00-总览架构/` |
| 可迁移的机制、知识、检查项 | `docs/10-可复用资产/` |

> **淘汰的策略不在本目录保留任何文档**——哪怕其中还有"设计方案""重构方案"这类看起来通用的内容。
> 理由：归档区与在用区必须能靠"目录里有没有它"一眼判断生死；留在核心目录会让后人误以为它还在迭代。
> 需要复用的内容先抽到 `docs/10-可复用资产/`，再整目录移入归档。

## 新增文档放哪

- 属于某个策略 → 放进该策略目录（没有就新建同名目录）；
- 跨策略/方法论 → `00-总览架构/`；
- 可迁移的机制/知识/检查项 → **`docs/10-可复用资产/`**（并在其 README 登记）；
- 已淘汰策略的历史 → `docs/04-归档/策略历史/<同名策略目录>/`。

## 命名

`<策略简称>-<文档类型>-<日期>.md`，例：`跨市场-优化方向台账-2026-11-14.md`。
