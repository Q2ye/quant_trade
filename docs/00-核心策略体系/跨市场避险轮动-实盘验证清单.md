# 跨市场避险轮动 — 实盘验证清单

> 2026-09-12 | 适用：`rotation/cross_market_momentum_strategy.py` 上线实盘前的逐项验证。
> 配套：`docs/02-功能设计/策略体系/策略运行分析标准流程.md`（日终通用检查）。

---

## 〇、为什么要单独验证 —— 组合的验证记录不能背书

此前在「攻防一体化」组合（高波动7.1 + 熊市防守-01）中验证过一段时间，**系统链路是通的**。
但那份记录**不覆盖本策略**，原因有三：

| 层面 | 攻防组合验证 | 本策略 |
|:---|:---|:---|
| 系统链路（数据同步→信号落库→人工确认→成交录入→持仓回显） | ✅ 覆盖 | ❌ **不用重验**（通用） |
| 组合资金分配（regime 权重 → `allocated_capital` → `context.total_assets`） | ✅ 覆盖 | ⚠️ 单独跑**没有这一层** |
| **策略自身状态机**（F1~F9） | ❌ **未覆盖**（代码不同） | ✅ **必须验** |
| **B1：无组合时的权益同步** | ❌ 组合模式掩盖了它 | ✅ **必须验** |

> **一句话：验证过的是「系统能跑」，没验证过的是「这个策略 + 这种跑法」。**

## 二、验证项清单

> 每项：**怎么造场景 → 看什么 → 通过标准**。建议每项都留一份日志片段作为证据。

### V1 — 重启不丢持仓、不重复建仓 🔴
- **造场景**：启动策略并持有一笔 → 停策略 → 重启 → 触发一次日终驱动
- **看**：日志是否出现 `恢复持仓 N 只`；是否对**已持有**标的重复发买入信号
- **通过**：`_holdings` 从 DB 正确重建，无重复建仓信号
- **关联**：F1（旧代码在实盘会每日抹掉持仓）

### V2 — T+1 守卫不误锁 🔴
- **造场景**：连续运行 ≥3 个交易日
- **看**：是否每个调仓日都无卖出信号（= 被永久锁死）；换仓是否按时发生
- **通过**：正常换仓，无「持有 X 天却一笔不卖」
- **关联**：F2（我曾把 `fill_date` 补为当日，导致实盘永久冻结；已修正）
- **⚠️ 这是最容易复发的一项**：`_restore_positions_from_db` 每日重建 `_holdings`，
  任何"补 fill_date"的改动都会立刻冻结策略

### V3 — 退出信号能重发 🟠
- **造场景**：制造一次「卖出信号发出但未成交」（如人工不执行）
- **看**：`exit_retry_days`（默认 3）个交易日后是否**重发**卖出信号
- **通过**：重发；而不是永久沉默
- **关联**：F3（旧代码 `_exit_pending` 是单向阀）

### V4 — 止损后不被买回 🟠
- **造场景**：标的跌破入场价 ×0.92
- **看**：止损卖出成交后，次日是否被重新选为目标并买回
- **通过**：不买回（至少不在同一轮）
- **关联**：F4

### V5 — 脏数据不崩 🟠
- **造场景**：数据源出现 NaN / 0 价（可手工插入一条脏 bar 到 DB）
- **看**：日志是否出现 `丢弃非法 bar`；当日是否仍正常出信号（而非整体静默）
- **通过**：该标的被跳过，其余标的正常；无 `int(nan)` 类异常
- **关联**：F5

### V6 — 停牌标的不入选 🟠
- **造场景**：某池内 ETF 停牌（`volume=0`）
- **看**：该标的是否仍被选为目标
- **通过**：被排除
- **关联**：F6

### V7 — 数据缺失不误切国债 🔴
- **造场景**：**故意让某日 ETF 行情整体缺失**（如跳过当日 ETF 同步）
- **看**：日志是否出现 `候选池无任何标的带当日(...)行情，判定为数据缺失，跳过本次调仓`；
  是否**没有**发出「卖出持仓 + 买入国债」的信号
- **通过**：当日不动仓，次日数据恢复后正常
- **关联**：F9（否则会白付两轮换手，且期间止损判据不可信）
- **⚠️ 这是最值得实测的一项**：不造场景几乎不会自然遇到，但一旦遇到损失明确

### V8 — sizing 基准随权益变动 🔴
- **造场景**：让账户权益发生明显变化（如人工调整余额，或经历一段涨跌）
- **看**：次日建议股数是否随之变化；日志是否出现 `sizing 基准同步: 策略=... 账户=... 权益 X → Y`
- **通过**：建议股数 ∝ 账户权益；不再恒定
- **关联**：**B1**（旧代码 `context.total_assets` 启动后永不更新）
- **⚠️ 这是单独跑与组合跑的唯一实质差异**

### V9 — 成交录入 → 次日可见 🟠
- **造场景**：人工确认成交并录入
- **看**：次日驱动时策略的持仓/成本是否与 DB 一致
- **通过**：一致
- **关联**：框架链路（组合阶段已验证，此处只做回归确认）

### V10 — 重启后的保守锁定期（已知行为，非缺陷）
- **现象**：重启后 `_held_days` 归零 → `min_hold_days=3` 会导致**3 个交易日内不换仓**
- **通过标准**：知道并接受它（保守方向），不要误判为故障
- **关联**：B4（低优先，未修）

### V11 — 卖出用 broker 实际数量 🟠
- **造场景**：让一笔买入被部分成交/缩减（如资金不足）
- **看**：卖出信号的数量是否等于实际持仓
- **通过**：不会因「可卖数量不足」被拒 → 资金正常释放
- **关联**：`cross-market-cash-bug-chain`（整条资金死锁链）

## 三、已知不验证项（有意接受）

| 项 | 说明 |
|:---|:---|
| **收益/回撤绝对值** | 小资金下取整损耗大，与回测不可比。验证期只看**行为是否正确**，不看收益 |
| **国债腿仓位比例** | 511010 单价 141 元 → 2 万账户只能建 **68.7%** 仓（设计 90%，损耗 23.7%）。<br>资金到 **10 万** 时损耗降到 **5.9%**，可接受，**不需要改代码** |
| 组合层面配比 | 本策略单独跑，不参与组合资金分配 |
