## 〇、一个必须先记录的**方法发现**

> ⚠️ **证据在【全量日志】里，不在 `strategy_decision.log` 里。**

本轮首次查询时，我 grep 的是 `strategy_decision.log`（经 `LiveDecisionFilter` 过滤后的决策日志），
**V8/V10 等项全部 0 命中**，一度误判为"未验证"。

改查全量 `quant_server.log*` 后，**V8 每天 1 条、V10 有完整记录**——
它们由 `modules.strategy.engines.strategy_manager` 输出，**未进入决策日志的过滤口径**。

**结论**：**验证时一律查全量日志**；决策日志是为"为什么买/为什么不买"这类归因设计的，**不覆盖运行时字段恢复类日志**。

> 同时发现：清单 V 项给出的"看什么"字符串，与实际日志文本**写法不完全一致**
> （如 V1 写 `恢复持仓 N 只`，实际是 `从 DB 恢复了 N 只股票的持仓`；V7 的字符串是**跨两行 f-string 拼接**的）。
> **建议：清单改为引用【代码行号】而非日志字符串**，比字符串更稳。

### ⚠️ 无法判定（1 项）

#### V2 — T+1 守卫不误锁 🔴

**实测**：6 次驱动**全部 0 信号**，且每次 `目标 == holdings`（均为 `159985.SZ`）。

**为何无法判定**：`min_hold_days` 守卫要验的是「**该换仓却没换**」；
而当前 `目标 = 持仓` → **0 信号属正常**（没有任何理由换仓），
**看不出是"守卫正确放行"还是"守卫把策略锁死"**。

**⚠️ 但有一个线索指向需警惕**：5 个交易日 0 信号，且期间 `走弱期=True` 恒成立
（`above=0~1 below=3~4 days=0/20`）。走弱期下 `weak_holdings_num=1` 且跳过均线/量比门，
**可能是"真的一直持有豆粕最优"，也可能是"轮动机制未生效"** → **需与回测同期信号对照才能定**。

**故 `S1 小资金实盘`（≥1 个月；2026-09-19 由原「S1 纸上交易 ≥20 交易日/≥10 笔」+「S2 ≥1 个月」合并）这条门槛，对本策略的意义不是"等够天数"，
