# 实盘策略环境隔离（Live 策略 production-only）

> 结论回填自 `REQ-20261108-live-strategy-env-guard`（2026-11-08）。
> 代码落点：`quant_server/modules/strategy/utils/env_guard.py`。

## 规则

- **只有 `ENVIRONMENT=production`** 可以恢复、驱动、启动、恢复、手动触发 `run_mode=live` 策略；
- `development` / `test` / `testing`：`paper` / `backtest` 保持可用，`live` 一律拒绝并打 WARNING；
- 未知 `run_mode`（含 `simulation` 等脏值）按 live 处理（production-only），不做放行；
- 拒绝必须发生在**写库之前**（不创建 `strategy_runs`、不改 `strategies.status`、不发事件）；API 返回 **403**。

## 覆盖入口

| 入口 | 位置 | 行为 |
|:---|:---|:---|
| 重启恢复 | `StrategyManager._recover_running_strategies` | 非生产跳过 live 行 |
| 每日驱动 | `StrategyManager.run_daily_strategies` / `_run_live_strategies` | 非生产直接返回空 |
| 启动事件 | `StrategyManager._on_strategy_start_requested` | 非生产拒绝 live |
| 恢复事件 | `StrategyManager._on_strategy_resume_requested` | 用事件 `run_mode` 判定 |
| 手动触发 | `StrategyManager.trigger_strategy` | 非生产拒绝 live |
| API 启动/恢复 | `ExecutionService.start_strategy` / `resume_strategy` → `strategy_router` | 写库前拒绝，403 |
| HTTP 入口 | `POST /strategies/{id}/start`、`/resume` | `LIVE_PRODUCTION_ONLY`（1012）→ 403 |

## 运维要求

- **dev 必须用 `python -m quant_server.main --mode development` 启动**（或显式 `ENVIRONMENT=development`）。
  用不带 `--mode` 的 `uvicorn ... --factory` 启动时，`.env` 的 `ENVIRONMENT=production` 会让进程连
  `public` 并按 production 放行 live —— 环境门无法区分「本想 dev 但配置成 production」。
- 当前生产 `public.strategies` 的 1 条 running/live 未改动；dev `dev.strategies` 的 running/live 为 0。
- dev 登录：`dev.sys_users` 已按方案 B 从 `public` 复制 `superAdmin`（同一 bcrypt 哈希），可用生产同密码登录。
