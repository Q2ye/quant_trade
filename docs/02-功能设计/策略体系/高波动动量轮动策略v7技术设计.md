## 2. 设计目标（第一性原理数学路径）

目标（docstring 第 5 行）：**年化 40-80%（不可下修）。MDD < 30%，赔率 > 2:1。**

数学路径（docstring 第 7-13 行完整摘录）：

```
月均 +5%（年化80%） = 满仓集中 1-2 只 × 盈亏比 3:1 × 胜率 40%
  单笔期望 = 0.4×(+30%) - 0.6×(-10%) = +6% → 每月 1-2 笔 → 年化 ~100%
因此三个必须：
  ① 必须集中（2×50%）—— 分散到 3×33% 单票贡献减半，够不着 80%
  ② 必须让利润奔跑（无固定止盈，ATR移动止损）—— 没有右尾就没有 80%
  ③ 必须控制亏损（2×ATR 自适应止损）—— 固定 -4% 对高波动票是自杀
```

设计要点（docstring 第 46-52 行）：全市场主板扫描无市值上限；牛市多因子打分右侧追强 Top2；熊市温和放量启动 1×25% 降仓；持有无止盈目标、2×ATR 自适应移动止损、趋势破坏兜底；Regime 用 CSI500 年线门（熊市降仓/空仓，不裸奔）。

## 3. 标的池机制

### 3.1 范围：`universe="all_market"`（DEFAULT_PARAMS）

- `on_start()` 通过 `StockBasicRepository.get_active_stocks()` 加载**全市场活跃股票**，逐只过滤后构成 `self._universe`；日志实证可加载"2879 只全市场数据"（注释）。
- 历史数据预热由 `StrategyManager._warmup_all_market` 统一负责（代码注释），策略不自载，避免与引擎双重加载。

### 3.2 前缀过滤（`_is_tradable`，类属性 ALLOW_PREFIX / FORBID_PREFIX）

| 属性 | 值（代码实证） | 含义 |
|:---|:---|:---|
| `ALLOW_PREFIX` | `('000','002','600','603','601','605')` | 主板允许前缀（深主板 000/002 + 沪主板 600/603/601/605） |
| `FORBID_PREFIX` | `('300','688','8','4','001','003')` | 禁止前缀（创业板 300、科创板 688、北交所 8/4 开头、001/003） |

`_is_tradable`：`code.split(".")[0]` 前缀命中 `FORBID_PREFIX` 即拒；未命中 `ALLOW_PREFIX` 也拒。

### 3.3 其他硬过滤（`on_start` / `_is_new_stock`）

- **ST 剔除**：名称含 "ST"（`"ST" in name.upper()`）→ 加入 `_st_stocks` 黑名单（选股时再排除）。
- **新股过滤** `new_stock_days=30`：`_is_new_stock` 中上市天数 < `new_stock_days × 1.5 = 45` 天视为新股；数据兜底 `len(df) < new_stock_days`（<30 根 bar）也视为新股。
- **数据要求**：`_score_candidate` 要求 `len(closes) >= lookback_days`（250 根）才参与牛市打分（需 MA200 + 动量）；熊市要求 ≥80 根（`_score_bear_candidate`）。
- **流动性下限** `min_daily_volume=500`：近 5 日均成交量（`avg_vol5`）< 500 手 → 剔除（`_score_candidate`）。

### 3.4 无市值上限的决策依据（docstring 第 47 行摘录）

> 全市场主板扫描，**无市值上限**（翻倍股 86% 在 200 亿以下），只设流动性下限。

即：不设市值上限，仅以流动性下限（500 手）+ 前缀过滤 + ST/新股过滤约束标的池。代码中未发现任何市值/流通股本过滤字段（代码实证）。

## 4. 入场逻辑

### 4.1 牛市：右侧追强（`_score_candidate` → `_screen_stocks`）

评分前硬门槛（全部满足才打分，任一不满足返回 None）：

1. **趋势过滤**：`price > MA200` 且 `MA50 > MA200`（`ma_short=50`、`ma_long=200`，均值口径 `np.mean(closes[-N:])`）。
2. **流动性下限**：`avg_vol5 >= min_daily_volume`（500 手）。
3. **量能确认**：`avg_vol5 / avg_vol20 >= volume_surge_ratio`（近5日均量 ≥ 近20日均量 × **1.2**）。
4. **右侧确认**：`price >= hhv20 × (1 - breakout_near_pct)`，其中 `hhv20 = max(highs[-20:])`（`breakout_window=20`，含当日最近 20 根最高），即收盘 ≥ 20 日新高 × (1-**2%**)；未创新高但距新高 ≤2% 也视为右侧确认。

多因子打分（`_score_candidate`，`_compute_market_momentum` 先更新基准）：

```
mom60 = ln(price / closes[-60-1])            # 60日动量（主因子）
mom20 = ln(price / closes[-20-1])            # 20日加速（次因子）
rs    = mom60 - market_mom60                 # 相对强度 = 个股动量 - 全市场60日动量中位数
score = mom60 + 0.5 × mom20 + 0.5 × rs       # 综合分
```

`_screen_stocks` 按 score 降序返回全量通过名单；`_recheck_buy_list` 复检：**今日量 > 0**、**未涨停**（今开 ≥ 昨收 × 1.095 剔除）、**跳空 < 5%**（(今开-昨收)/昨收 > 0.05 剔除）。

### 4.2 熊市：温和放量启动（`_score_bear_candidate` → `_screen_bear_market`）

docstring 实证依据（2022-2024）：熊市纯放量突破 20 日 avg=**-0.97%**（假突破淹没）；叠加"温和启动"过滤 → **+2.47%、胜率 49%**。

五个条件（代码实证，任一不满足返回 None）：

| # | 条件 | 阈值（来源） |
|:---|:---|:---|
| ① | 放量突破：当日量 ≥ 近20日均量 × `bear_vol_ratio` | ≥ **2.0** |
| ② | 创新高：收盘 ≥ 前 20 日新高（`max(highs[-21:-1])`，不含当日，防当日 high 恒>close 误判） | — |
| ③ | 动量温和：60日动量 `ln(price/closes[-60])` < `bear_mom60_max`（排除已暴涨高位股） | < **0.05** |
| ④ | 波动温和：ATR(20)/price < `bear_atr_max`（排除游资暴炒） | < **0.30** |
| ⑤ | 未过热：`price/MA20 - 1 ≤ bear_ma20_dev_max`（刚启动未过热） | ≤ **0.10** |

打分：`score = -mom60`（代码注释：动量越低越"温和"、更接近启动点，加分）。

### 4.3 入场执行时序（`_run_rebalance` 流程实证）

调仓日（每日一次，`rebalance_frequency=1`）顺序：① `_finalize_exits()` 结算待卖出 → ② `_annual_line_gate()` 判 regime → ③ `_check_stops_and_trailing()` 日频风控 → ④ `_confirm_pending_buys()` 确认昨日候选 → ⑤ 无空位则不再扫描 → ⑥ 选股 → ⑦ 入池 Top N 落库，**次日收盘确认后才生成买入信号**。

## 5. 出场逻辑（`_check_stops_and_trailing` / `_calc_atr`）

ATR(20)：`_calc_atr` 用 True Range 均值（`mean(TR[-atr_window:])`，`atr_window=20`），数据不足 `atr_window+1` 根返回 0.0。

每日更新持仓 `peak_high = max(旧峰值, 当日 high)`（移动止损基准）。

| 退出类型 | 牛市持仓（`is_bear=False`） | 熊市持仓（`is_bear=True`，v7.1 宽止损） | 信号类型 |
|:---|:---|:---|:---|
| **硬止损** | 现价 < 入场价 − `atr_stop_mult`(**2.0**)×ATR | 现价 < 入场价 − `bear_atr_stop_mult`(**2.5**)×ATR | `STOP_LOSS` |
| **移动止损** | 现价 < 峰值 − `atr_trailing_mult`(**2.0**)×ATR | 现价 < 峰值 − `bear_atr_trailing_mult`(**3.5**)×ATR | `TAKE_PROFIT` |
| **趋势破坏** | `MA50 < MA200` → 退出（兜底） | **跳过**（P1-2 修复，只走 3.5×ATR 宽止损） | `EXIT` |

- 止损倍数按持仓的 `is_bear` 标记选择（入场时记录），与当前 regime 无关（v7.1 起）。
- P2 保护：`atr <= 0` 时跳过止损判定，避免 `hard_stop=entry` / `trail_stop=peak` 收阴即误平仓。
- `_finalize_exits` 用退出价结算：`_nav_realized *= 1 + pnl × weight`。

## 6. 仓位管理

| 项 | 牛市 | 熊市 | 来源 |
|:---|:---|:---|:---|
| 最大持仓数 `eff_max_pos` | `max_positions` = **2** | `bear_max_positions` = **1** | `_run_rebalance` |
| 单票权重 `eff_weight` | `max_single_weight` = **0.5**（2×50%） | `bear_single_weight` = **0.25**（1×25%） | `_run_rebalance` |

- **等权**：入池候选每只权重均为 `eff_weight`（`_buy_pending[target]["weight"] = eff_weight`）。
- 空位约束：`len(self._holdings) >= eff_max_pos` 时不再扫描/确认（`_run_rebalance` 第 4 步、`_confirm_pending_buys` break）。
- 股数计算（`_confirm_pending_buys`）：`amount = capital × weight`；`shares = max(int(amount/price/min_lot_size) × min_lot_size, min_lot_size)`；`capital` 取 `context.initial_capital`，缺省 `parameters.allocated_capital`，默认 **100000**；`min_lot_size=100`（一手）。
- **入场/出场信号均 `order_mode="close"`**（`_make_entry_signal` / `_make_exit_signal`，收盘确认执行）。
- 调仓频率 `rebalance_frequency=1`（每日扫描；`on_bar_batch_end` 中 `_bar_count % 1 == 0` 且数据缓存 ≥10 只才调仓）。
- 信号字段实证：买入 `confidence=0.75`、卖出 `confidence=0.80`，`direction=LONG / CLOSE_LONG`，`strategy_id=self.name`。

## 7. Regime 判定（`_annual_line_gate`）

- **门控**：`use_annual_gate=True`（DEFAULT_PARAMS）时启用；关闭则恒判牛市（返回 False）。
- **标的**：中证 500（`000905.SH`），`on_start` 经 `IndexDailyRepository` 加载 2018-01-01 至当日的日线（失败降级：年线门关闭，日志"中证500加载失败（年线门降级）"）。
- **判定**：取 `trade_date <= 当前交易日` 的收盘序列，需 ≥250 根；`closes[-1] < mean(closes[-250:])`（CSI500 收盘 < MA250）→ 熊市（True）；否则牛市。
- 调用点：`_run_rebalance` 每日判定（决定降仓参数）、`_confirm_pending_buys` 二次判定（决定 `is_bear` 标记与 P1-1 权重封顶）。

## 8. v7.3 候选机制（代码实证）

### 8.1 候选池加深 `candidate_pool_size=4`

- 入池：`for target in confirmed[:self.candidate_pool_size]`（`_run_rebalance`）——入池 Top 4 而非"仅空位数"，当日仅落库不入场。
- 次日确认：`_confirm_pending_buys` 按入池顺序（= 打分降序）逐只确认，持仓满 `eff_max_pos` 即 break——Top 1/2 确认失败不再空仓，按序补位。

### 8.2 确认缓冲 `confirm_buffer_pct=0.015`

- 买入条件：次日收盘 `price > signal_price × (1 - 0.015)`（signal_price = 入池当日收盘）。
- 失败处理：标记 `rejected` 并回写 signals 表（reason 记录"收盘 ≤ 信号价×(1-1.5%)，确认失败"）——**v7.2 修复**：不回写则前端信号列表一直停留在"待确认"。

### 8.3 候选落库与全链路追溯（signals 表，`_persist_candidate`）

- 写入字段实证：`direction="long"`、`signal_type="buy"`、`signal_status="pending_confirm"`、`reason="高波动候选，待次日收盘确认"`、`price=signal_price`、`strength=weight`。
- 幂等：同代码已存在 `pending_confirm` 行 → 复用其行（`repo.get_by_stock` 查重）。
- 转正：`_mark_candidate_status(sig_id, "promoted", "收盘确认转正")`；买入信号 `parent_id=_cand_sid` → 候选→信号→订单全链路可追溯（与低吸/ETF 一致）。
- docstring 定位：该落库为**跨策略统一机制（v6.14 起）**：候选落库 + 前端可见 + parent_id 链路 + 重启恢复 + 重放抑制。

### 8.4 跨重启恢复（`_restore_candidates_from_db` / `load_live_state` 覆写）

- 启动时读取本策略 `signal_status="pending_confirm"` 的候选行重建 `_buy_pending`（含 signal_price/weight/signal_date/signal_id）。
- 过期处理：信号时间距今 > **5 天** → 标记 `expired`（"过期未确认"），不恢复。

### 8.5 回测不落库 / 重放抑制

- `_is_live_mode()`：仅 `context.run_mode ∈ {"live","paper"}` 才持久化，**回测不写 signals 表**。
- 重放：`not getattr(self, "_replaying", False)` 才落库/转正（防脏候选）。
- 候选 DB 写为 fire-and-forget 异步任务（`_fire_db`），事件循环未运行时跳过（debug 日志）。
