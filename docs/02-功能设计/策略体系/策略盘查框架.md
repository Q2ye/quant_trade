# 量化策略盘查框架（通用）

> 适用：系统内所有策略（动量/轮动、Alpha 因子、技术指标、AI/ML、ETF 抄底等）
> 目的：对任意策略做全链路逻辑盘查，回答三个问题——
> ① 策略能否达到设计目标？② 问题出在哪一层？③ 目标是过拟合还是真实 alpha？
> 用法：**新建策略盘查时复制本框架**，填"策略画像" + 按 A→B→C 逐块执行，结论填入执行记录表。

使用第一性原理分析策略逻辑

## 一、盘查框架总览（3 阶段 9 检查块）

```
阶段 A：策略逻辑本身
  A1 设计目标与逻辑闭环（含目标过拟合检查）
  A2 标的池 + 相关性矩阵
  A3 Regime 判定（仅 regime 类策略，其余跳过）
  A4 信号质量
  A5 止盈止损

阶段 B：执行与资金
  B1 执行撮合 + 流动性容量
  B2 资金与风控交互

阶段 C：验证与实盘
  C1 数据质量
  C2 参数稳健性
  C3 实盘一致性与失效监控
```

### 策略类型适配（哪些块最重要）

| 策略类型 | 重点块 | 说明 |
|:---|:---|:---|
| 动量/轮动 | A1, A3, A4, A5, B1 | 动量 IC、Regime 判准、容量约束 |
| Alpha 因子 | A2, A4, C1 | 因子正交/相关性、因子 IC、前视与幸存者 |
| 技术指标 | A4, A5 | 信号准确性、止盈止损匹配 |
| AI/ML | C1, C2, A4 | 数据泄露（train/val/test 分离）、过拟合、特征有效性 |
| ETF 抄底 | A1, A3, C2 | 目标可达成性、市场底判定、参数稳健 |

## 二、各检查块明细

### A1 设计目标与逻辑闭环

**核心问题**：策略的收益来源是什么？在什么市场形态下赚钱？目标是否由过拟合特定历史极值行情推出来？

| 检查项 | 证据来源 | 判定标准 |
|:---|:---|:---|
| 收益来源定义 | 设计文档 + 策略代码 | 明确策略赚什么钱（动量延续/均值回归/因子溢价/趋势突破），在哪个周期有效 |
| 目标可达成性 | **多窗口回测** | 目标年化/回撤在不同窗口（牛市段 / 熊市段 / 混合段）是否稳定成立 |
| 目标过拟合检查 | 窗口对比 | 若目标只在个别极值行情窗口成立 → 目标是过拟合产物，需修订 |
| 哲学符合度 | 投资哲学 | 赔率优先/集中/不对称止盈等是否落实 |

### A2 标的池 + 相关性矩阵

**核心问题**：标的池是否支撑策略定位？内部相关性与集中度是否带来踩踏风险？

| 检查项 | 证据来源 | 判定标准 |
|:---|:---|:---|
| 池覆盖度 | 标的基本信息 | 是否覆盖策略需要的板块/波动/市值特征 |
| 数据可用性 | 行情表 | 标的上市时间是否覆盖回测窗口；早期数据缺失比例 |
| 实际波动率 | 标的日收益率统计 | 池的实际波动 vs 止损/止盈参数是否匹配 |
| **相关性矩阵** | 标的日收益率相关系数 | 池内标的联动程度；高相关 → 同涨同跌 → 同时止损踩踏 |
| 集中度 | 持仓权重 | 单板块/单标的最大暴露；极端行情下的集中风险 |

### A3 Regime 判定（仅 regime 类策略）

**核心问题**：市场状态判得准不准？切换是否产生 whipsaw 成本？

| 检查项 | 证据来源 | 判定标准 |
|:---|:---|:---|
| 判定准确性 | Regime 信号 vs 实际走势 | 牛/熊/震荡分界判定时点是否滞后/误判 |
| 切换频率与成本 | 回测日志 | 来回开关次数；每次切换的错失行情/打脸成本 |
| 阶段分段绩效 | 回测分拆 | 牛/熊/震荡各阶段收益与风险 |
| 回撤持续/恢复时间 | equity 曲线 | MDD 只看深度，**恢复耗时**决定实盘资金占用与心理 |

### A4 信号质量

**核心问题**：信号准不准？入场后是赚是亏？

| 检查项 | 证据来源 | 判定标准 |
|:---|:---|:---|
| 因子有效性 | 因子 IC / 分层单调性 | 核心因子与未来收益的相关性、分层单调 |
| 信号后收益分布 | trades 表 | 入场后 N 日收益分布；均值是否为正 |
| 假信号率 | trades 表 | 入场后短期内（如 <5 日）即止损的比例 |
| 胜率结构 | 回测指标 | 胜率背后的单笔盈亏结构（高胜率小赚 vs 低胜率大赚） |

### A5 止盈止损

**核心问题**：止损/止盈准不准？是被洗出去还是正确兑现？

| 检查项 | 证据来源 | 判定标准 |
|:---|:---|:---|
| 止损宽度匹配 | 标的波动率统计 | 止损比例 vs 标的实际日波动；高波动池紧止损是否自相矛盾 |
| 离场原因分布 | trades 表 signal_type/reason | 止损/止盈/信号反转/调仓/regime 各占比例 |
| 盈亏比 | trades 表 | avg win / avg loss（设计目标验收核心） |
| 被洗比例 | trades 表 | 止盈/止损触发后标的继续向原方向运行的比例（过早离场） |

### B1 执行撮合 + 流动性容量

**核心问题**：目标权重 vs 实际权重是否一致？高频策略的实盘容量约束？

| 检查项 | 证据来源 | 判定标准 |
|:---|:---|:---|
| 权重落地 | 引擎 sizer/broker 代码 | 目标权重 → 实际仓位是否一致（多信号现金复利失真） |
| 执行模式 | 回测日志 | order_mode（open/close/trigger）是否正确撮合 |
| 交易规则 | 代码 + 日志 | T+1、涨跌停、停牌处理 |
| **冲击成本** | 标的盘口/折溢价 | 大额下单滑点、ETF 折溢价、申赎冲击 |
| **流动性容量** | 日均成交额 | 资金容量上限 = 单标的日均成交 × 可容忍冲击比例 |
| 持有期分布 | trades 表 | 是否大量短持/T+1；直接决定交易成本性质 |
| 换手成本 | trades × 费率 | 换手 ×（佣金+滑点）对收益的侵蚀 |

### B2 资金与风控交互

**核心问题**：风控是否"粘"？是否结构性压制收益？

| 检查项 | 证据来源 | 判定标准 |
|:---|:---|:---|
| 风控恢复机制 | 回测日志/代码 | 减仓后是否需"新高"才恢复；弱市是否长期半仓 |
| 冷却期/调仓频率 | 代码 + 日志 | 与策略周期匹配；对交易成本与信号捕捉的影响 |
| 多风控叠加 | 代码 | Regime 门 + 组合回撤 + 月度风控是否互相冲突/叠加抑制 |

### C1 数据质量

**核心问题**：回测数字可信吗？

| 检查项 | 证据来源 | 判定标准 |
|:---|:---|:---|
| 前视偏差 | 代码审计 + 回测 | shift(-/iloc[i+/缓存未来数据守卫 |
| 幸存者偏差 | 标的池构建 | 是否只用当前存活的标的；市值/基本面用当前值筛历史 |
| 单位错配 | DB 字段单位 | amount/total_mv 等单位（千元/万元/元）核对 |
| 复权一致性 | 前复权逻辑 | 同一天所有价格同一复权因子 |
| 尾部风险 | 极端日回测 | 熔断/崩盘日表现——保护还是放大 |

### C2 参数稳健性

**核心问题**：这套参数是不是只适配过去某段特定行情？

| 检查项 | 证据来源 | 判定标准 |
|:---|:---|:---|
| 滚动窗口参数遍历 | 参数 × 子窗口结果矩阵 | 最优参数在不同子窗口是否一致 |
| 蒙特卡洛扰动 | 参数 ±10% 随机扰动 | 结果分布方差；是否对微小参数变化高度敏感 |
| 样本外子集回测 | 时间切分 | 训练期参数在样本外的表现 |
| 参数高原检验 | 参数网格热力图 | 最优参数周围是否平坦（平坦=稳健，尖峰=过拟合） |
| Walk-forward | 滚动训练-验证-测试 | 业界标准时序外推验证 |

### C3 实盘一致性与失效监控

**核心问题**：实盘会复现回测吗？何时该停用？

| 检查项 | 证据来源 | 判定标准 |
|:---|:---|:---|
| 实盘序列化一致性 | 信号持久化/事件 | 实盘路径是否丢失回测用到的信号字段（weight/order_mode 等） |
| 执行延迟与人工偏差 | 实盘流程 | 信号 → 确认 → 成交的延迟；半自动人工干预 |
| 失效模式监控 | 设计 | 何时该停用（策略失效的结构性信号、触发条件） |
| 实盘漂移监控 | 实盘绩效 vs 回测 | 偏离阈值即告警 |

## 三、逻辑闭环

### 层间依赖（前层输出 = 后层输入）

```
A2 标的波动率 → A5 止损宽度（波动大的标的止损必须更宽）
A5 止损/止盈 → B1 交易成本（频繁止损 = 换手 = 成本）
A3 Regime → 仓位（regime 门决定在场/空仓）→ B2 资金
B1 实际权重 → 回测可信度 → C1 数据质量
C2 参数稳健性 → A1 目标可达成性（目标是否过拟合产物）
```

### 反馈循环（闭环关键）

```
A1 目标设定
  ↓
A2-A5, B1-B2 执行
  ↓
C2 参数稳健性 ←→ A1：若参数只在特定窗口有效 → 目标修订 → 重新迭代
C3 实盘漂移 → 触发 A1 目标/参数再评估
```

### 闭环判定方法

从 A1 出发，若 C 阶段证明 A/B 无法支撑目标（参数不稳健 / 执行吃收益 / 数据污染），则**目标修订 → 重新迭代**。盘查结论必须能追溯到具体层级的证据。

---

## 四、执行流程

1. **定义盘查对象**：填策略画像（名称/类型/目标/当前表现/触发原因）
2. **逐块执行**：A1 → A2 → … → C3，每块：
   - 收集证据（代码 / 回测 / trades 表 / equity 曲线 / 日志 / 因子统计）
   - 按判定标准下结论（✅ 通过 / ⚠️ 待改进 / ❌ 不达）
3. **汇总**：问题清单（按严重度分级）、根因定位（哪一层）、建议
4. **决策**：修订目标 / 调整参数 / 修改逻辑 → 重新验证 → 闭环
5. **记录**：执行记录表填写结论，供后续复盘与对比
