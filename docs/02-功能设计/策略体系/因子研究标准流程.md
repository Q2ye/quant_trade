```
Step 1  研究 → 定义注册 ──── factor_definitions（factor_code 唯一）  红线：未注册不得被引用
```

## 一、Step 1：因子定义与注册

### 1.1 必须登记的表

| 用途 | 表 / 类 | 位置 |
|:---|:---|:---|
| 因子定义（唯一真相源） | `factor_definitions` / `FactorDefinition` | `create_table.sql:1853` / `models/data_models.py:910` |
| 因子时序值 | `factor_data` / `FactorData`（超表） | `create_table.sql:3445` / `models/data_models.py:880` |
| 研究任务与证据 | `factor_research` | `create_table.sql:2627` |
| 特征集（ML 训练引用） | `feature_sets`（`feature_columns` = 因子代码 JSONB 数组） | `create_table.sql:1834,1850` |

登记动作落点：定义经 `FactorResearchService.create_factor_definition`（`research_service.py:912`）写 `factor_definitions`；ML 引用须把 `factor_code` 加入 `feature_sets.feature_columns`。

### 1.2 登记字段要求（`create_table.sql:1853-1870`）

`factor_code` **全局唯一**（`:1855`）；`factor_type` 五选一 `technical`/`fundamental`/`macro`/`alternative`/`custom`（`:1857` CHECK）；`category` + `factor_name`（子类 / 中文显示名）；`formula` + `parameters`（可复现公式；参数 JSONB，**默认值必须与计算实现一致**）；`data_requirements`（JSONB，如 `{"required":["close"]}`）；`calculation_frequency` + `output_type`（`minute`/`daily`/`weekly`/`monthly`；`float`/`int`/`bool`/`string`）。
基准范例：`docs/sql/seed_factor_definitions.sql`（2026-06-23 v3，声明 factor_code 与 `constants.py:745 StandardFactors` + `factor_calculators.py:134 register_factor` 严格一致）。

### 1.3 命名规范（**本次新增**）

1. **大小写唯一**：同一因子全仓只允许一种大小写形态，**禁止** `MACD` 与 `macd` 并存。
2. **形态强制小写 snake_case**：与 `FACTOR_CALCULATORS_MAP` 键一致（`factor_calculators.py:2714`），日终生产直接以该键作 `factor_code` 写入（`etf_factor_daily.py:60`）。历史大写下划线形态（`MACD`/`RET_1M`/`PB`）为遗留，不再新增。
3. **单位**：比率/收益率一律无量纲（`ret_1m`=0.05 即 5%）；金额须在 `formula` 标注单位，口径对齐 `回测分析标准流程.md:69`（`amount` 千元 / `total_mv` 万元 / `circ_mv` 万元）。
4. **方向**：本表**无 direction 列**，方向必须写进 `factor_name` 或 `description`（「越大越好」/「越小越好」），否则多空方向不可判定。
5. **参数化因子**：参数必须进 `parameters`（如 `ma_5` 的 `{"window":5}`），禁止硬编码后仍登记为无参因子。

### 1.4 红线

> 🔴 **未在 `factor_definitions` 注册的 `factor_code`，禁止被任何策略、回测或 ML 特征集引用。**

**实测缺口**（开发库只读，2026-09-15）：`factor_data` 有 **102** 个 distinct `factor_code`，`factor_definitions` 仅 **83** 行 → **28 个有数据未注册**，其中 **8 个是大小写变体重复**（`macd`/`MACD`、`pb`/`PB`、`ret_1m`/`RET_1M`、`ret_3m`、`ret_6m`、`vol_1m`、`vol_3m`、`boll`/`BOLL`），另 20 个（`atr_14`、`adx_14`、`vol_contraction`、`total_mv_log`、`pe_ttm` 等）完全未登记。

## 二、Step 2：计算与落库

### 2.1 计算入口与写入

**三个入口**：① 算法注册表 `register_factor` 装饰器 → `FACTOR_CALCULATORS_MAP`（`factor_calculators.py:134,2714`）；② **日终批量生产**（当前唯一在产路径）`compute_etf_factors()`（`etf_factor_daily.py:60,151,158`）；③ 研究型单因子计算 `FactorResearchService._save_factor_data()`（`research_service.py:1220,1245`）。

- **批量写入（强制）**：只允许 `batch_insert_factor_data(list, conflict_strategy="upsert")`（`factor_data_repo.py:84-88`）。**禁止逐条 `add()` / 逐条 INSERT**。
- **幂等**：固定 `upsert`，依赖唯一键 `uq_factor_data_code_name_date`（`create_table.sql:3457`）。重算同日必须**覆盖**而非追加。
- **NaN 不落库**：NaN/Inf 行不得写入（`research_service.py:1207-1213` 已实现 `_safe_float` + 全 None 返回空列表）。PostgreSQL `NUMERIC` 拒收 NaN，且会虚增 `calculated_count`。
- ⚠️ **ORM 命名陷阱**：`FactorData.factor_name = Column("factor_code", ...)`（`data_models.py:887`）—— 属性名 `factor_name` **实际映射 DB 列 `factor_code`**。故 `FactorDataRepository` 各方法的 `factor_name=` 形参（`factor_data_repo.py:101,131`）筛的是 `factor_code`；**不得据此认为存在 `factor_name` 列**。

### 2.2 时间对齐（PIT）—— 🔴 红线

**现状缺陷**（`review/17` §2-1，本文复核后固化）：查询时点取 `query_date = end_date`（整个区间的**末日**，`research_service.py:2317`）→ `f_ann_date <= query_date` 过滤形同虚设（`:2324`）；索引键取 `date_key = stmt.end_date`（**报告期**，`:2344`）；填充用 `pd.date_range(..., freq='D')` + `method='ffill'`（**日历日**，`:2457`/`:2462`）。三者叠加 → FY2023 年报（`f_ann_date≈2024-04-25`）自 **2024-01-01** 起即被填入，**PE / PB / PS / ROE / ROA / GM / OM / DR 等全部基本面因子最多约 4 个月前视**。

**正确做法（**本次新增**）**：
1. **索引键必须用公告日** `stmt.f_ann_date`，**禁止**用 `end_date`（报告期）。
2. **过滤时点必须逐 bar 推进**（`f_ann_date <= t`，`t` 为当前序列日期），**禁止**用区间末日。
3. **填充必须走交易日历**（`trade_calendar` 表），**禁止** `freq='D'` 日历日。
4. **回归验证**：修复后重跑 `tests/modules/test_pit_financial.py`，并**补一条断言**覆盖「按 f_ann_date 而非 end_date 对齐」——原测试测的是本地 mock 副本，恰好未覆盖该步。

### 2.3 复权价 vs 不复权价 —— 🔴 红线

**现状**：因子计算取 `stock_daily`（原始未复权，`create_table.sql:2861`）/ `etf_daily` 的 `close`（`research_service.py:1069-1076`，取 `quote.close`）；`research_service.py` 全文对 `stock_adjusted_prices`（`:3022`）与 `adj_factor` **零引用**（grep 零命中）→ 除权除息日产生**伪跳空**，动量类（`ret_*`）、波动类（`vol_*`/`atr_*`）系统性失真。

**必须用复权价的因子（**本次新增**）**：动量/收益率、波动率/波幅、均线偏离、估值/基本面（价格口径须与市值一致）、价格位置类（`price_position_250d`、`close_to_low_20d`）。
**不需复权（**本次新增**）**：量能/换手（`volume_*`、`turnover_*`，量不受除权影响；送转股除外，须在 `formula` 标注）。
**红线**：价格位置类若窗口内无除权可不复权，但**不得默认假设无除权**。复权表：`stock_adjusted_prices`（`adj_type`：`qfq`/`hfq`，`create_table.sql:3026`）+ `stock_adj_factor`（`:2980`）；ETF 用 `fund_adj_factor`（`:3224`）。

### 2.4 横截面标准化 —— 🔴 红线

**现状**：`research_service.py:1348-1352` 取「当日该因子**全量**行」写字面 SQL，**不区分标的类型**；`factor_data` 同时含 ETF 与其他标的（实测共 **48,054,818** 行、**2,001** 个 distinct `ts_code`，ETF 类约 1,606 / 其他 395）→ 混装成立。**未爆原因**：`z_score`/`percentile`/`rank` 三列**实测全为 NULL**（非空 **0** 行）→ 标准化从未写入，也无策略读取；一旦启用即爆发。

**正确做法（**本次新增**）**：
1. **分层标准化**：横截面统计按标的类型分层，至少拆 **ETF 层**与**股票层**，各自独立 winsorize + z-score；禁止混装。
2. **样本下限**：单层有效样本 < 10 **跳过并记 warning**，不写标准化列（沿用 `:1353-1358` 的 `< 10` 逻辑，作用域改为分层后）。
3. **子集禁止落库**：统计量基于当日全量，但**写入必须限定回本次研究的标的池**（`:1341-1343` 的 C1 注释已明确此设计意图）。
4. **准入**：分层改造 + 覆盖率校验通过前，`z_score` **保持 NULL 是正确状态**，不得为「让列有值」而先行写入。

## 三、Step 3：质量校验（因子入库前必过）

### 3.1 客观阈值（**本次新增**，除注明外均为硬门）

| 检查项 | 阈值 | 判定方法 |
|:---|:---|:---|
| **覆盖率** | 标的池内交易日覆盖 **≥ 90%** | 与 `stock_daily`/`etf_daily` 日期基准对比（口径对齐 `回测分析标准流程.md:58`：覆盖 <90% 且缺失 ≥20 天判定为空洞） |
| **横截面样本数** | 单日有效标的 **≥ 10**，否则该日不参与统计 | 沿用 `research_service.py:1353` |
| **NaN 比例** | 单横截面 ≤ 30%，全样本 ≤ 20% | `count(factor_value IS NULL)/count(*)` |
| **极值 / 零方差** | 5%/95% winsorize；`σ > 1e-12` 否则跳过 | 已实现：`:1370-1372`、`:1377` |
| **分布偏移** | 当月横截面均值相对**前 12 个月基线** z 偏离 **> 2σ** → 告警 | 月度聚合后比较 |
| **标记连续性** | 报告期因子在同一公告日内取值逐日恒定，跨公告日才变 | 修复 §2.2 后检查 ffill 段是否出现日历日单点跳变 |

### 3.2 IC 与分组回测证据（新因子必交）

- **收益口径 🔴**：**必须用前瞻收益** `dt_idx + forward_period`（`research_service.py:1497-1498`）；**禁止**用当日收益 `returns_data.loc[dt]`（`:1631` 分组、`:1842` 稳定性**当前即为此错误口径**）。成因与后果见 `review/17` §2-2：同一报告两套口径 → 动量类多空收益、单调性、`top_minus_bottom` 被系统性夸大。
- **`forward_period`**：必须与策略实际换手周期一致（日频 1 / 周频 5 / 月频 20），并登记在 `factor_research.parameters`。
- **IC 门槛（**本次新增**）**：`|IC mean| ≥ 0.03` 且 `ICIR = IC_mean/IC_std ≥ 0.3`；不达标不得进入 `feature_sets`。
- **分组门槛（**本次新增**）**：等分 5 组，`top − bottom` 年化差 **> 0**，组序与收益秩相关 **≥ 0.7**。
- **证据落库**：结论写入 `factor_research` 的 `ic_mean`/`ic_ir`/`top_minus_bottom`/`sharpe_ratio`（`create_table.sql:2749-2752`）。`status='completed'` 只代表任务跑完，**不代表有证据**。

### 3.3 标的池选取（对齐 `review/17` §2-4）

- 🔴 **禁止用「全样本统计量」筛池**：`scripts/data/backfill_top100_factors.py:359`（选池窗口 `WHERE trade_date >= '2024-01-01'`），再于 `:394` 回填 `2020-01-01` 起数据 → **前视 + 幸存者偏差**。
- **正确做法**：选池条件只用**选池时点之前**可得的滚动窗口，或直接采用策略的**事前固定池**（如 ETF 池常量）。

## 四、Step 4：策略消费

### 4.1 读取路径（**强制**）

合规路径三条：① `FactorDataRepository` 方法（`factor_data_repo.py`，唯一合规数据访问层，对齐 `audit.md`「一表一仓库」）；② `modules/data/handlers.py:123 get_factor_data` → `GET /factors`（`data_router.py:1266`）；③ `FactorResearchService` 公开方法（`research_service.py:3180 get_factor_data` / `:849 get_factor_metadata`）。
**禁止**：策略内 `psycopg2.connect` + 拼裸 SQL 读 `factor_data`（现状违规：`etf/bottom_strategy.py:324-338`，含硬编码口令，见 `review/17` §6-1）；以及任何直接以 `factor_data` 表名书写的其他 SQL。

### 4.2 因子变更 → 下游重算（**本次新增**）

```
改因子定义 / 算法 / 复权口径 / 标准化方式
   ↓ ① 同步 factor_definitions（磁盘 seed 与 DB 单源）
   ↓ ② 重算全部历史 factor_data（幂等 upsert，禁止只补增量）
   ↓ ③ 重跑质量校验（§三）并更新 factor_research 证据
   ↓ ④ 通知下游：feature_sets.feature_columns 引用者 + 消费该因子的策略
```

- **禁止只改增量**：口径变更后只算当日，会造成新旧口径在时间轴上拼接（`research_service.py:1341-1343` 的 C1 注释即此类问题前例）。
- **参数默认值双写**：`parameters` 改默认值必须同步 `strategy_parameters` 覆盖（本项目既有规则，见 `CLAUDE.md`「策略开发」节）。
- **代码副本**：同一因子算法可能同时存在于 `factor_calculators.py` 与多处 DB `strategies.code`，同步范式参考 `scripts/_sync_cross_market_code.py`（不带 `--apply` 只查）。

## 五、一票否决项（红线汇总）

| # | 红线 | 后果 |
|:--|:---|:---|
| 1 | 因子未在 `factor_definitions` 注册即被策略/特征集引用 | 口径不可追溯，回测结论不可复现 |
| 2 | 基本面因子按 `end_date`（报告期）而非 `f_ann_date`（公告日）索引或填充 | **未来函数**，最多约 4 个月前视 |
| 3 | 用不复权价（`stock_daily.close`）算动量/波动/估值因子 | 除权日伪跳空，因子失真 |

| 5 | 分组/稳定性分析用**当日收益**冒充前瞻收益 | 多空收益与单调性被系统性夸大 |

| 7 | 策略内裸 SQL / 直连 psycopg2 读 `factor_data` | 绕过 Repository 契约，口令与口径失控 |
| 8 | 因子口径变更后只补增量、不重算历史 | 新旧口径在时间轴上拼接 |
| 9 | 逐条 `add()` 写 `factor_data`（超表） | 性能塌陷，应走 `batch_insert_factor_data` |
