## §1 文档读取与校验方法

### 1.1 读取方式

- `WebFetch` 对 `tushare.pro` 被安全策略拦截；`curl -A "Mozilla/5.0"` 可 200。
- 文档页左侧栏含完整索引：**291 条 `doc_id → 接口名`**（含分类节点，叶子接口约 250 个）。
- 字段表在静态 HTML 内，三种表头变体：`默认显示` / `默认输出` / `仅 名称|类型|描述`。
- 抓取脚本只保留"非必选表"（`名称|类型|...|描述`），跳过入参表（含 `必选`）。

### 1.2 必须用实调校验的三类情况

1. **文档页缺失**：`fund_daily` 侧栏无入口，但 API 可用。
2. **文档字段 ≠ 返回字段**：`ths_member` 文档列 `in_date/out_date/is_new`，实调返回只有 `ts_code/con_code/con_name/weight`。
3. **源字段拼写错误**：`fx_obasic.traget_spread`（正确为 `target_spread`），入库时改名。

### 1.3 起点验证明细（2026-11-08 单日探针）

## §4 表结构定义

### 4.0 通用规范

1. **通用列**：所有表末尾统一追加：
   ```sql
   source      VARCHAR(16)  DEFAULT 'tushare',
   fetched_at  TIMESTAMPTZ  DEFAULT now(),
   created_at  TIMESTAMPTZ  DEFAULT now(),
   updated_at  TIMESTAMPTZ  DEFAULT now()
   ```
   下文 DDL 省略，按此补齐。
2. **单位**：金额=元、量=股/手（表注释写明）；价格 `NUMERIC(12,4)`，指数 `NUMERIC(14,4)`，汇率 `NUMERIC(18,6)`，比率 `NUMERIC(12,6)`。
3. **主键**：日频表 `(日期, 标的[, 维度])`；目录表 `标的代码`；事件表用业务唯一键，冲突用 surrogate `BIGSERIAL` + `UNIQUE`。
4. **幂等**：所有写入 `ON CONFLICT (主键/唯一键) DO UPDATE`。
5. **分区**：预计 >1,000 万行的日频表建 TimescaleDB hypertable（`fx_daily`、`fut_daily`、`opt_daily`、`cb_daily`、`stock_cyq_perf`、`stock_moneyflow_ext`、`index_ths_daily`）。
6. **PIT**：`ann_date`/`f_ann_date`/`in_date`/`out_date` 必落；接口不提供的表在注释中写 `NON_PIT`。
7. **时区**：业务日用 `DATE`；`fx_daily` 的源日期是 GMT，入库转北京业务日（见 4.1）。

### 4.1 P0b：直接影响现有策略（12 张）

```sql
-- ------------------------------------------------------------------
-- 外汇基础信息（fx_obasic）
-- 源字段 traget_spread 为 Tushare 拼写错误，入库统一为 target_spread
-- ------------------------------------------------------------------
CREATE TABLE fx_basic (
    ts_code           VARCHAR(20) PRIMARY KEY,
    name              VARCHAR(80),
    classify          VARCHAR(40),
    exchange          VARCHAR(20),
    min_unit          NUMERIC(18,6),
    max_unit          NUMERIC(18,6),
    pip               NUMERIC(10,6),
    pip_cost          NUMERIC(18,6),
    target_spread     NUMERIC(18,6),      -- 源: traget_spread
    min_stop_distance NUMERIC(18,6),
    trading_hours     VARCHAR(100),
    break_time        VARCHAR(100)
);
COMMENT ON TABLE fx_basic IS '外汇基础信息（Tushare fx_obasic）';

-- ------------------------------------------------------------------
-- 外汇日线（fx_daily）
-- ⚠️ 源 trade_date 为 GMT，比北京时间晚一天。
--    入库: trade_date = source_date + 1 day（北京业务日）
--    source_date 保留源值，便于回溯。
-- ------------------------------------------------------------------
CREATE TABLE fx_daily (
    ts_code     VARCHAR(20) NOT NULL,
    trade_date  DATE        NOT NULL,     -- 北京业务日
    source_date DATE,                     -- 源 GMT 日期
    bid_open    NUMERIC(18,6),
    bid_close   NUMERIC(18,6),
    bid_high    NUMERIC(18,6),
    bid_low     NUMERIC(18,6),
    ask_open    NUMERIC(18,6),
    ask_close   NUMERIC(18,6),
    ask_high    NUMERIC(18,6),
    ask_low     NUMERIC(18,6),
    tick_qty    BIGINT,
    exchange    VARCHAR(20),
    PRIMARY KEY (ts_code, trade_date)
```

### 5.4 分页 / 限速 / 幂等

- 所有全量拉取**显式分页**：`offset += limit`，直到某页不足一页（防 `index_member_all` 式静默截断）。
- 限速：按接口实测配置令牌桶；默认 300 次/分钟，`daily_basic`/`moneyflow` 留 500–600 余量。
- 单日重试 ≤3 次，指数退避。
- 所有写入 `ON CONFLICT DO UPDATE`。

## §6 门禁设计

| 模式 | 判据 | 表举例 |
|:---|:---|:---|
| `dense` | 当日行数/应有行数 ≥99%；`max(date)` ≥ 基准日；缺失日 vs 交易日历 | 行情、资金、两融、净值、期货日线 |
| `sparse` | 有数据的天数占比 + 单日行数突变（>3σ）；不设 99% | 龙虎榜、大宗、解禁、增减持、调研、KP |
| `periodic` | 最新期是否到应到报告期/月度；`min(date)` ≤ 规格起点+30 天 | 财务、index_weight、top10、宏观、PMI |
| `derived` | 计算任务成功 + 结果非空 + 与源表日期一致 | `factor_data`、`market_state_daily`、`panic_index` |

门禁配置从 `DATA_CONTRACTS` 读取，不再散落在日终函数里。

## §8 验收口径（每类必做）

1. **API↔DB 计数对照**：抽 3 个交易日，比接口返回行数与入库行数。
2. **起点校验**：`min(date)` 与 §1.3 实测一致。
3. **PIT 抽样**：按 `ann_date`/`in_date` 做 as-of 查询，确认不泄露未来。
4. **无 NaN/Inf**；金额/价格单位抽检。
5. **门禁跑通**：新表全部进 `DATA_CONTRACTS`，日终可告警。
6. **策略冒烟**：4 个回测脚本 + 相关 pytest。
