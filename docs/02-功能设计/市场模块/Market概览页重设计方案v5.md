# Market 概览页重设计方案 v5 —— 量化决策导向的市场总览

> 版本：v5.0（2026-08）｜前身：`Market模块展示方案.md` v4（2026-06，页面功能蓝图仍有效，本方案只重设计**市场总览页（MarketDashboard）**的信息架构与数据供给）
> 设计输入：现状代码审计（MarketDashboard.vue 1329 行 / market_router 32 端点）+ 业界量化平台实践调研。
> 本文档为**设计文档**，不含代码实现；实施需另行确认。

## 一、现状问题诊断

v4 的 Dashboard 采用"区块堆叠"式设计（自选股条 → 状态雷达 → 风格轮动 → 指数+涨跌统计+北向 → 行业轮动 → TOP10 双表 → 北向图表+主力订单 → 宏观+事件日历），功能齐全但存在三个结构性问题：

| # | 问题 | 表现 | 根因 |
|:---|:---|:---|:---|
| 1 | **数据混乱、无优先级** | 9 个区块平铺，宏观 CPI/PPI（月度数据）与分钟级资金数据同屏同权重；用户 3 秒内无法回答"今天能不能做、做什么" | 区块按"功能清单"组织，而非按"决策问题"组织 |
| 2 | **没有侧重点** | 没有"一屏读懂市场"的核心指标（温度/状态），自选股条与 TOP10 占首屏却对决策无直接帮助 | 缺少一个统领全局的市场状态层 |
| 3 | **缺量化需要的数据** | 有涨跌家数但无**新高新低/站上均线比例**（市场宽度不完整）；有涨停分析页但总览无**涨停梯队/炸板率**（情绪周期缺位）；有风格因子但无**拥挤度**；有波动率但无**历史分位**（不知道当前波动处于什么位置） | 数据供给以"能查到什么"为界，而非以"量化决策需要什么"为界 |

**结论**：Dashboard 需要从"数据陈列台"重构为"**市场状态驾驶舱**"——以量化交易者盘前/盘中的 4 个决策问题为主线组织信息。

## 三、设计目标与原则

### 3.1 设计目标

1. **3 秒可答**：打开页面 3 秒内回答"市场处于什么状态、该用什么姿态（仓位/方向）"。
2. **量化可用**：每个区块的数据要么直接指导仓位，要么输出到策略/回测（可钻取、可引为因子）。
3. **分层克制**：总览只放"状态级"数据；明细（个股/行业细节）全部下沉到既有子页面。

### 3.2 设计原则

| 原则 | 说明 |
|:---|:---|
| 决策四问主线 | 页面按 `① 什么状态 → ② 机会在哪 → ③ 情绪资金 → ④ 风险` 四层组织（见 §四） |
| 一屏一结论 | 每个区块顶部给**结论性文字**（如"温和进攻区 · 仓位建议 40-60%"），不只给数字 |
| 分位数优先 | 所有状态指标必须带**历史分位**（当前值处于过去 N 年的位置），绝对值无决策意义 |
| 可引为因子 | 温度/宽度/情绪等状态值预留 `GET /market/dashboard/snapshot` 结构化输出，策略可直接调用 |

### 4.7 评判基准线（温度计与四维雷达的口径说明）

**市场温度计 —— 基准线 = 各指标自身历史分布（分位基准）**

| 维度 | 指标 | 基准样本 | 说明 |
|:---|:---|:---|:---|
| 估值 | 沪深300+中证500 PE/PB | 1000 交易日 | 分位 = 当前 PE/PB 在自身历史的位置 |
| 情绪 | 涨停家数 ×0.5 + 全市场换手率 ×0.5 | 250 交易日 | 情绪热度处于近一年位置 |
| 资金 | 北向 20 日滚动净流入 | 750 交易日 | 外资流入力度历史位置 |
| 技术 | 全市场站上 MA20 比例 | 250 交易日 | 趋势健康度近一年位置 |

- 温度 = 四维等权（0~100℃）；**50 分位 = 历史中位数 = 中性基准线**。
- 带划分：<30 低温 / 30~70 中性 / >70 高温；仓位卡细分 30/50/70 三档线。
- 选分位而非绝对值的原因：绝对量纲不可比（PE 12 倍在不同年代含义不同）、不可跨维合成；分位统一到 0~100 并自带"贵/便宜、热/冷"语义。

**四维雷达 —— 短期状态基准**

| 维度 | 基准 |
|:---|:---|
| 牛熊状态 | MA20/MA60 均线体系（收盘与均线关系 + 斜率 → 牛/熊/震荡） |
| 宽度 / 涨跌停家数 / 波动率 | 近 **60 交易日**窗口分位，50% = 窗口内中位 |
| 年线门 | 中证500 vs MA250（0% = 恰好在年线） |

- 与温度计的分工：雷达 = 短期状态（60 日窗口），温度计 = 中长期位置（250~1000 日窗口）。
- **卡片可视化**：统一采用"分位条"组件（0~100 刻度条 + 50% 中线标记"历史中位"），温度计四维小字与雷达三卡均展示，卡底脚注注明各维样本窗口。

#### 4.6.5 首屏保障（验收#1 对账）与决策 D4

- **冲突**：验收#1 要求"温度计 + 仓位 + 涨停梯队首屏可见"，但 §4.0 骨架把梯队放在 L3。
- **D4 落地**：涨停梯队卡**前置至 L1**（span 3）；四维状态雷达（P1）**并入温度计卡作为 Tab2 视图**（两卡维度高度重叠：温度计四维 估值/情绪/资金/技术 vs 雷达 溢价/情绪/估值/趋势，独立占位冗余）。首屏高度 = L0(36)+L1(300)+gap ≈ 350px，任何桌面视口均一次满足验收#1。
- **备选**：若用户不接受雷达并入，则雷达保留 L1 独立位、梯队回 L3 首位，首屏保障在 ≥900px 视口仍成立。

#### 4.6.6 刷新节奏与状态覆盖

| 层 | 轮询 | 说明 |
|:---|:---|:---|

| # | 数据项 | 计算逻辑 | 依赖表 |
|:---|:---|:---|:---|

| N4 | **拥挤度** | 全市场成交额 250 日分位；行业换手率 250 日分位 TOP5 | stock_daily（sum 成交额）、industry 成分映射 |
| N5 | **波动率分位** | 沪深300 20 日实现波动率 + 750 日分位 | index_daily |
| N6 | **强弱榜** | 创 20 日新高 TOP10 / 新低 TOP10 / 连涨 ≥5 日清单 | stock_daily（窗口） |

### 5.3 API 设计（新增 4 个端点，全部 GET、只读聚合）

| 端点 | 返回 | 用途 |
|:---|:---|:---|
| `GET /market/dashboard/temperature` | `{temperature, zone, dimensions:{valuation/emotion/capital/technical 各含 value+percentile}, updated_at}` | L1 温度计 + 仓位卡 |
