## 一、任务 ID 两层体系

```
batch 记录   task_id = batch_sync_{YYYYMMDD_HHMMSS}   ← 取消令牌绑定于此
                 │  (parent_task_id)
子任务记录   child_task_id = batch_sync_{时间戳}_{data_type}  ← 每种数据类型一条
```

### 生成位置

| 层级 | 生成代码 | 文件:行 |
|:---|:---|:---|
| batch | `task_id = f'batch_sync_{datetime:%Y%m%d_%H%M%S}'` | handlers.py:1129（sync_service.py:1075 兜底同格式） |
| child | `ctid = f"{batch_task_id}_{task.data_type}"` | sync_service.py:1109 |

### 记录数量

批量同步 N 种数据类型 → DB 中共 **1 条 batch + N 条 child**。

---

## 二、任务状态生命周期

```
pending → running → completed
                 → failed
                 → cancelled
```

### 各记录状态流转

| 记录 | pending | running | completed/failed/cancelled |
|:---|:---|:---|:---|
| batch | API 入口创建 | 后台任务开始 | 汇总所有子任务结果 |
| child | 预创建（sync_service） | 子任务开始执行 | 子任务完成/失败/取消 |

## 三、取消机制

### 3.1 取消令牌

```python
_cancel_tokens: Dict[str, asyncio.Event] = {}

create_cancel_token(task_id)    # 后台任务启动时，绑定到 batch_task_id
signal_cancel(task_id) → bool   # 取消 API，直接设置 Event
cleanup_cancel_token(task_id)   # 任务结束后清理
```

### 3.2 取消流程（简化后）

```
用户点击取消
  → cancel_sync API
  → signal_cancel(task_id)        ← 优先直接 signal_cancel；失败后保留 parent 链 fallback（handlers.py:1836-1843）
  → DB: UPDATE WHERE (task_id=:tid OR parent_task_id=:tid)  ← 一次 SQL 取消自身+所有子任务
```

### 3.3 取消检测（sync_service._is_cancelled）

```
第一层: cancel_token.is_set()          → O(1) 内存读取
第二层: DB 查询 status='cancelled'     → 绕过 SQLAlchemy 缓存
```

### 3.4 关键检测点

| 位置 | 检测 | 频率 |
|:---|:---|:---|
| `_sync_one` 入口 | `_is_cancelled()` | 每种类型 1 次（sem 获取**前**，sync_service.py:1121-1128；sem 内无二次检测） |
| `_parallel_for_each` worker | `_is_cancelled()` | 每只股票 1 次 |
| 各同步方法循环内 | `_is_cancelled()` | 每批次/每页 |

## 四、批量同步子任务管理

### 4.1 预创建（sync_service.py:1105-1116）

所有子任务在启动前全部创建，status="pending"：

```
batch_sync_data():
  for task in tasks:
    ctid = f"{batch_task_id}_{task.data_type}"
    repo.create({task_id: ctid, status: "pending", parent_task_id: batch_task_id})
  commit()
```

### 4.2 执行流程

```
batch_sync_data():
  1. batch_task_id = task_id (API传入) 或 自动生成
  2. 若 DB 中无此记录 → 创建（status=running）；有 → 更新为 running
  3. 预创建所有子任务（status=pending）
  4. asyncio.gather(_sync_one for task in tasks):
     _sync_one(task):
       取消检查 → 标记子任务 cancelled
       获取信号量 → 独立 session
       标记子任务 running
       sync_market_data(data_type, ...)
         成功 → 标记 completed + 统计
         异常 → 标记 failed + error
  5. 汇总 → 更新 batch 记录 status + 统计
  6. handler 更新根记录 status
```

### 4.3 并发控制

| 机制 | 配置 | 说明 |
|:---|:---|:---|
| `asyncio.Semaphore(_type_cc)` | 默认 3，**config.yaml 实际配置 `sync_type_concurrency: 5`**（运行时并行度为 5） | 限制同时执行的子任务数 |
| `asyncio.Lock` (`_session_lock`) | — | 串行化 `self.session` 操作 |
| 独立 session/子任务 | `get_session()` | 每个子任务独立事务 |

### 4.4 四种场景

| 场景 | 子任务 DB | batch 状态 | 取消 token |
|:---|:---:|:---|:---:|
| 全部正常完成 | 全部 completed + 统计 | completed | — |
| 部分失败 | 全部存在，部分 failed | failed | — |
| 取消（未启动） | 全部 cancelled | cancelled | ✅ 命中 |
| 取消（部分运行中） | 运行的 completed，其他 cancelled | cancelled | ✅ 命中 |
| 服务器宕机 | 全部保持最后状态 | running 或 pending | 无（**已自动化**：模块启动时 `initialize_data_module` 自动将遗留 running 标记为 failed，handlers.py:3445-3457） |

## 五、同步模式

### 5.1 批量同步

```
POST /api/sync/batch
  → handlers.batch_sync_data()
    → 生成 batch_task_id = batch_sync_{timestamp}
    → DB: 创建 batch 记录 (status=pending, task_type="batch")
    → BackgroundTasks: _execute_async_data_sync(task_id, db_id, ...)
    → 返回 {task_id: batch_sync_{timestamp}}

后台 _execute_async_data_sync():
  → create_cancel_token(task_id)
  → 更新 batch 记录 status=running
  → service.batch_sync_data(tasks=..., task_id=task_id)
    → 预创建子任务 → asyncio.gather → 汇总
  → 更新 batch 记录 final status + 统计
  → cleanup_cancel_token(task_id)
```

### 5.2 单类型同步

同批量流程，但 `tasks` 只有一个元素，child 只有 1 条。

## 七、与 v1（三层）的对比

| 维度 | v1（三层） | v2（两层） |
|:---|:---|:---|
| 每批 DB 记录 | 1 handler + 1 batch + N child | 1 batch + N child |
| task_id 格式 | handler: `sync_{hex}`, batch: `batch_sync_{ts}` | `batch_sync_{ts}` |
| 取消查找 | 沿 parent 链走 3 层 | 直接 signal_cancel |
| 前端列表 | handler 记录（不显示子任务） | batch 记录（显示子任务）✅ |
| 子任务查询 | `task_type=="batch"` 不匹配 | `task_type=="batch"` 匹配 ✅ |
