### 3.3 迁移踩的 3 个坑

| # | 坑 | 现象 | 解法 |
|:--|:---|:---|:---|
| **1** | `pg_dump --data-only`（不带 `-n`）**导出 TimescaleDB 内部 catalog** | `COPY hypertable` 撞主键，装载在**第 49 行即失败** | 加 `-n public` |
| **2** | 🔴 **`pg_dump -n public` 对超表导出的是空数据** | 118 张普通表装载正确，**13 张超表全 0 行**（超表数据在 `_timescaledb_internal` 的 chunk 里，被 `-n public` 排除；父表自身堆为空） | 改用 **`COPY (SELECT ...) TO` → `COPY <超表> FROM`**：前者扫全部 chunk，后者由 TimescaleDB 路由写入 chunk |
| **3** | 迁移脚本里 `PSQL = "/d/apps/pgsql/..."`（git-bash 路径） | `FileNotFoundError [WinError 2]` | 改 Windows 路径 |

> **坑 2 是最危险的**：`pg_dump` 静默产出空 COPY 段，**不报错**，装载 EXIT=0，事后才发现 13 张超表为空。

## 六、切换到生产库（2026-09-19 20:31 完成）

### 6.1 切换机制（实测）

**选库只由 `ENVIRONMENT` 决定**：

| 环节 | 事实 |
|:---|:---|
| 选库位置 | `ConfigSettings` 的 `model_validator`（构造时），读 **`os.getenv("ENVIRONMENT")`** |
| `.env` 如何生效 | `config_manager.py:33` 有 `load_dotenv(_ENV_FILE, override=False)` → **真实环境变量优先** |
| `--mode` 参数 | **不选库** —— `main.py:1166` 只写 `server.config.mode`（日志格式 / uvicorn reload / docs 开关） |

→ 切换 = 让进程环境的 `ENVIRONMENT=production`。改 `.env` 与「启动时导出该变量」**等价**。

### 6.2 实际执行

```bash
cd quant_server
PYTHONPATH=E:/QuantitativeTrading/quant_trade PYTHONIOENCODING=utf-8 \
  ENVIRONMENT=production \
  .venv/Scripts/python.exe -m quant_server.main --config config.yaml --mode production --port 8080
```

> ⚠️ **`PYTHONIOENCODING=utf-8` 是必须的**（当把输出重定向到文件时）：
> 模块初始化日志含 `✅`/`❌` emoji，而 Windows 中文环境下重定向到文件时默认编码为 **GBK**
> → `UnicodeEncodeError` → **中断模块初始化**，表象是「data / strategy / account /
> monitor / risk / backtest 六个模块初始化失败」，**极易误判为功能故障**。
> 控制台直接运行不受影响。**排查此类"模块初始化失败"时先看有没有 `UnicodeEncodeError`。**

### 6.5 🔴 附带发现：`.env` 的生产库配置曾是**死配置** —— **已修**

**修复前**：`resolve_database_config` 生产分支读 `DB_PROD_*`，而 `.env` 定义的是
**`PROD_DB_*`** —— **前缀顺序相反**，一个都读不到、**静默**回退：

| 缺失的键 | 回退到 |
|:---|:---|
| `PROD_DB_NAME` | 硬编码 `"quant_signals"`（恰好正确） |
| `PROD_DB_HOST` / `PORT` / `USER` / `PASSWORD` | `self.DATABASE.*`，即 `.env` 的 **`DB_*`（开发库那套凭证）** |

> 注：`DatabaseSettings` 有 `env_prefix="DB_"`，所以 `.env` 的 `DB_HOST`/`DB_PASSWORD` 等
> **是被读取的**（作为基础默认值）；落空的只是「生产环境专属覆盖」。
> ⇒ 「生产库配置写没写、写对没写对，行为完全一样」，**且无任何告警**。

**修复（2026-09-19，`shared/config/config_manager.py`）**：

1. 生产分支改为读 **`PROD_DB_*`**（与 `.env` 一致）
2. **连接关键项**（`HOST` / `PORT` / `USER` / `PASSWORD` / `NAME`）缺失时打 **WARNING**，
   明确提示「已回退到开发库凭证」；`POOL_SIZE` / `MAX_OVERFLOW` 属调优参数，
   回退基础 `DB_*` 是设计意图，不告警
