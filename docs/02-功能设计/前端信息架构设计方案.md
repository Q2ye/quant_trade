# 前端信息架构设计方案 — 绩效中心

> 状态：已确认（2026-08）｜ 对应需求：健康与报警 / 绩效总览 / 账户绩效页面交互复杂，总体设计
> 真相源说明：本文档为前端「绩效中心」信息架构的唯一真相源；涉及页面级实现细节以代码为准。

## 1. 背景与问题

用户反馈：策略健康与报警、绩效总览、账户绩效等页面交互复杂。

代码实证发现三大复杂感来源：

1. **入口分散**：绩效总览在「策略中心」、账户绩效在「交易与持仓」、健康与报警在「风险监控」——"绩效相关"跨三个菜单。
2. **三套数据口径并存**：回测口径（`backtest_tasks`）／实盘策略口径（`strategy_daily_performance`）／账户口径（资产快照），同一指标数值对不上，用户无法判断哪个"是真的"。
3. **职责交叉/死代码**：绩效总览 script 内存在未渲染的 `accountNav`（账户总资产）与 `aggregateStats` 死代码（模板未使用），且 scoped 定义 `.text-up`(绿)/`.text-down`(红) 违反全站 A 股红涨绿跌规范。

## 2. 设计原则

1. **一页一职**：每页只回答一个问题，不混数据。
2. **口径唯一**：三套绩效口径显式命名 + 页面角标标注（`SourceBadge`），杜绝"对不上"。
3. **2 跳内到达**：总览 → 详情 → 钻取，不超过两级。
4. **红涨绿跌全站统一**：任何页面不得 scoped 覆盖颜色类语义。

## 3. 决策记录（用户确认 2026-08）

| 决策点 | 结论 |
|---|---|
| 新分区命名 | **绩效中心** |
| 报警中心 | **并入**策略健康页 tab（不独立成页），默认过滤 info 级通知（保留计数） |
| 绩效总览 accountNav | **删除死代码**（模板未渲染的账户总资产计算 + aggregateStats 死 computed） |

## 4. 目标菜单结构

```
数据中心          （不变）
  ├ 市场概览 / 数据同步

策略中心          （瘦身：绩效入口移出，回到"研究流"4 项）
  ├ 因子研究 / 策略构建 / 模型训练 / 回测验证

交易与持仓        （3 项：账户绩效移出）
  ├ 交易驾驶舱 / 信号管理 / 组合实盘

绩效中心          （唯一入口「绩效中心」→ /performance 绩效驾驶舱大页）
  └ ★ 绩效中心（驾驶舱一屏总览：指标条 + 净值回撤 + 健康卡 + 回测 Top5 + 报警 + 月度热力图）

风险监控          （4 项：健康/报警移出，回归"风控执行"）
  ├ 风控规则 / 实时监控 / 事件查看 / 黑名单

系统管理          （不变）
```

驾驶舱内钻取（路由保留，不占菜单，页面内"查看全部/详情"进入）：

| 钻取页 | 路由 | 来源 |
|---|---|---|
| 回测排行（完整版） | `/performance/rank` | 原绩效总览 PerformanceHub 迁移 |
| 账户绩效 | `/performance/account` | 不变 |
| 策略健康与报警 | `/performance/health` | 不变 |

旧路由 `/performance` 由回测排行页改为绩效驾驶舱首页；`/risk/strategy-health-alerts` → 301 重定向 `/performance/health`；菜单高亮按 `/performance` 前缀匹配，钻取页访问时「绩效中心」保持高亮。

## 5. 三套绩效口径规范

| 口径 | 数据源 | 用途 | SourceBadge 角标 |
|---|---|---|---|
| 回测口径 | `backtest_tasks` | 选策略（历史模拟） | `回测·` |
| 实盘策略口径 | `strategy_daily_performance` | 策略体检（近段 vs 历史基准） | `实盘策略·` |
| 账户口径 | 账户日资产快照 | 看资金（净值/回撤/持仓） | `账户·` |

落地：通用组件 `SourceBadge.vue`（样式走 design-tokens，禁硬编码颜色）。

## 7. 明确不做

- 不移动 `StrategyHealthAlerts.vue` 文件位置（保留 `views/Risk/`，避免 git 历史断裂与无关重构）
- 不拆报警独立页（并入 tab）
- 不改 `styles/` 与 `naive-theme.ts`（SourceBadge 仅消费现有 design-tokens）
- 零后端改动
