## 一、模块定位

system 模块（config.yaml 中 `enabled: true`、`auto_start: true`、无依赖）承担三类职责：

1. **JWT 认证** — 登录/注册/刷新/登出、token 黑名单、密码校验（AES/BCRYPT 兼容迁移）；
2. **用户管理** — 用户/角色/细粒度权限（RBAC）CRUD、在线会话与登录锁定；
3. **系统配置** — 系统状态/设置/日志/连接状态查询，运行时配置读写（DB 配置表）。

认证基础设施（JWT 签发校验、密码管理）位于共享层 `shared/security/`，system 模块负责编排，API 层通过 `api/dependencies/auth.py` 注入。

## 二、认证体系

### 2.1 JWT 签发与校验（shared/security/jwt_handler.py）

| 配置项 | 代码默认值 | 实际来源 | 实证 |
|:---|:---|:---|:---|
| 算法 ALGORITHM / JWT_ALGORITHM | `HS256` | `Settings().API.*`（默认 + .env `APP_*`） | config_manager.py L117/L120 |
| access 有效期 | 30 分钟 | 同上 | L115；**config.yaml 的 `ACCESS_TOKEN_EXPIRE_MINUTES: 600` 仅经 ConfigManager 加载，JWTManager 实例化 `Settings()` 时不会读到 YAML 值**（差异见 2.3，待确认） |
| refresh 有效期 | 7 天 | 同上（REFRESH_TOKEN_EXPIRE_DAYS=7） | L121 |
| SECRET_KEY | `"your-secret-key-here-change-in-production"` | 同上 | L114（生产必须覆盖） |

- 载荷：`create_access_token` 注入 `exp/iat/type=access`，可选 `iss/aud`（JWT_ISSUER/JWT_AUDIENCE 为空则不签发/不校验）；refresh 同理 `type=refresh`。
- 校验：`verify_token()` 先校验格式（`token.count('.') == 2` 且三段非空），再 `jwt.decode(..., verify_exp=True, algorithms=[algorithm])`，最后按 `token_type` 匹配；过期抛 `TokenExpiredError`、其余抛 `InvalidTokenError`（core/exceptions/security_exceptions.py）。
- 刷新：`refresh_access_token()` 用 refresh token 换新 access token 对。

### 2.2 认证开关 AUTH_ENABLED（api/dependencies/auth.py）

`_is_auth_enabled()` 延迟读取 `get_config().settings.API.AUTH_ENABLED` —— **config.yaml `defaults.api.AUTH_ENABLED: false`（开发默认）**，即默认跳过 JWT 验证：

```mermaid
flowchart TD
    A[请求进入 get_current_user] --> B{API.AUTH_ENABLED?<br/>config.yaml=false}
    B -->|false 开发模式| C[查 sys_users 第一个 admin 角色用户]
    C -->|存在| D[直接返回该用户<br/>permissions=*:* can_sync_data=true]
    C -->|不存在| E[创建种子用户 superadmin<br/>password=dev-no-auth-mode]
    E -->|DB 异常| F[回退硬编码 developer<br/>id=cd2f4a88-... role=super_admin]
    B -->|true 生产模式| G[HTTPBearer 取 Authorization 头]
    G -->|无凭证| H[401 需要认证令牌]
    G --> I[JWTManager.verify_token 校验]
    I --> J[exp 双重检查 + 取 sub 用户ID]
    J --> K[查库 sys_users 用户]
    K -->|不存在/停用| L[401 用户不存在 / 403 账户禁用]
    K --> M[update_last_login + 加载 sys_permissions]
    M --> N[返回 user_info<br/>permissions=[module:read/write/execute]<br/>can_sync_data]
```

- **AUTH_ENABLED=false 是开发/测试专用**（config.yaml 注释「设为 false 可跳过 JWT 验证（仅开发/测试）」），生产必须为 true。
- 权限码生成：`f"{perm.module}:read" / ":write" / ":execute"`（按 can_read→can_write→can_execute 优先级）；`can_sync_data` = admin/super_admin/superadmin 或权限码含 "data"。
- 导出依赖：`get_current_user`、`require_permission`（精确匹配权限码，缺失 403）、`require_superuser`（仅 super_admin/superadmin）、`optional_auth`（无 token 返回 None）、`PermissionRequired(*perms)` 工厂。

### 2.3 模块内认证组件（modules/system/auth/）

| 组件 | 职责（实证） |
|:---|:---|
| `jwt_handler.py`（模块内） | `get_token_from_header` / `verify_access_token`（FastAPI 依赖注入，含黑名单检查）/ **token 黑名单**：优先 Redis（key `token_blacklist:{sha256(token)[:16]}`，TTL 86400s），降级内存 set + TTL 映射，`clear_expired_blacklist` 清理 |
| `authentication.py` | `AuthenticationManager.authenticate_user`：UserRepository 查用户 → PasswordManager 验证（**兼容旧 AES 密码并自动迁移为 BCRYPT**）→ is_active 检查 → update_last_login；`create_token_pair` / `refresh_access_token` / `change_password`（验证旧密码+强度校验）/ `validate_password_strength` |
| `authorization.py` | `ADMIN_ROLES = {admin, super_admin, superadmin}`、`is_admin`；`AuthorizationManager` 标注 **DEPRECATED**（职责与 managers/permission_manager.py 重叠，新代码应使用带缓存的 PermissionManager） |

**差异实证（待确认）**：JWTManager 通过 `Settings()` 读 token 有效期（默认 30 分钟 / .env `APP_ACCESS_TOKEN_EXPIRE_MINUTES` 可覆盖），而 config.yaml 声明 600 分钟、system 模块常量 `ACCESS_TOKEN_EXPIRE_MINUTES = 60`（constants.py L37）、main.py 将 `settings.API.ACCESS_TOKEN_EXPIRE_MINUTES`（YAML=600）注入 system 模块 config —— 三条路径数值不一致，实际生效值待确认。

## 三、用户管理

### 3.1 数据表（docs/sql/create_table.sql）

- **sys_users**（L30）：id VARCHAR(36) / username UNIQUE / password / email / phone / real_name / role CHECK(admin,user,guest) / is_active / last_login / created_at / updated_at。
- **sys_roles**（L58）：role_code UNIQUE / role_name / permissions JSONB / is_default。
- **sys_user_roles**（L80）：用户-角色多对多（UNIQUE(user_id,role_id)）。
- **sys_permissions**（L97）：user_id / module / can_read / can_write / can_execute（UNIQUE(user_id,module)）—— 细粒度权限（如 strategy/trade/data 模块）。
- **sys_audit_logs**（L1575）：审计日志（AuthService 通过 shared/security/audit.py 记录登录失败/登录成功/注册/改密等）。

### 3.2 服务与管理器

- `services/user_service.py` / `managers/permission_manager.py`：用户 CRUD 与带缓存权限检查（`check_permission` / `check_any_permission`）。
- `managers/user_manager.py`：**在线会话**（内存 Dict，登录/登出/活动时间戳）、**登录失败锁定**（`_max_login_attempts=5` 次、`_lockout_minutes=30` 分钟、滑动窗口）、**空闲会话清理**（`_session_idle_timeout_minutes=60`）。
- `services/role_service.py`：角色 CRUD。
- 角色常量（constants.py）：admin / super_admin / superadmin / user / viewer；密码策略 `PASSWORD_MIN_LENGTH=8`、`MAX_LENGTH=128`（注册时强度校验代码已注释，实际仅长度等基础校验，待确认）。

## 四、配置体系（双层 + 运行时）

### 4.1 双层配置（config.yaml + .env）

`shared/config/config_manager.py` 实证：

| 层 | 内容 | 加载方式 |
|:---|:---|:---|
| `quant_server/config.yaml` | 非敏感：system/server/engines/modules/api | `ConfigManager._load_yaml`（合并 `defaults` + `environments.<env>`，development/production 均继承 defaults）→ `_load_settings` 映射为各 Settings 类 |
| `quant_server/.env` | 敏感凭证/环境变量 | pydantic-settings `env_file=".env"`、`env_nested_delimiter="__"`；模块顶部 `load_dotenv(override=False)` 显式注入进程环境（v2.1 修复，注释见 config_manager.py L20-35） |

- 配置优先级（`ConfigManager.get()`）：环境变量（key 点号转大写下划线，如 `API.PORT` → `API_PORT`）> 配置对象 > 默认值；`get_config()` 为 `lru_cache` 单例，`reload_config()` 清缓存重载。
- 敏感脱敏：`ConfigSettings.get_all_settings()` 将含 PASSWORD/SECRET/TOKEN/KEY 的字段替换为 `***REDACTED***`。

### 4.2 环境前缀与数据库切换（model_validator 实证）

- `resolve_database_config`：**development 读 `DB_DEV_HOST/PORT/USER/PASSWORD/NAME`**（NAME 默认 `quant_signals_dev`），非 development 读 `DB_PROD_*`（NAME 默认 `quant_signals`）—— 注意代码前缀是 `DB_DEV_*`/`DB_PROD_*`，与 CLAUDE.md/任务说明中的 `DEV_DATABASE__*` 命名**不一致**（待确认：.env 实际键名以 pydantic 嵌套 `DATABASE__HOST` 语义为准，两者可能并存）。
- `resolve_datasource_config`：development 读 `DEV_DATA_MODE`/`DEV_MOCK_*`，Tushare Token 优先 `DEV_TUSHARE_TOKEN`、回退 `PROD_TUSHARE_TOKEN`（开发共用生产数据源凭证）；生产读 `PROD_DATA_MODE`/`PROD_TUSHARE_TOKEN`/`PROD_TUSHARE_ENABLED`。
- 关键字段默认值：`ENVIRONMENT=development`、`DATA_SOURCE.DATA_MODE="simulated"`、`TRADE.SIMULATED_TRADING=True`、`TRADE.BROKER="XTP"`（默认值，config.yaml trade 段实际 `broker: "sim"`）、`API.HOST=127.0.0.1`、`API.PORT=8080`（yaml `server.port` 会同步覆盖 API.PORT）。

### 4.3 运行时配置（DB 表）

`services/config_service.py` 通过 `ConfigRepository`（DB 配置表，表名待确认）读写运行时配置：`get_all_configs/get_config/get_config_value/set_config/update_settings/delete_config`，支持 int/float/bool/json/string 类型推断与转换；`is_public` 控制公开可见性。即存在 **config.yaml（静态）+ .env（敏感）+ DB 配置表（运行时）** 三层。

### 4.4 系统模块配置注入（main.py L696-700）

system 模块启动配置 = `{secret_key: settings.API.SECRET_KEY, access_token_expire_minutes: settings.API.ACCESS_TOKEN_EXPIRE_MINUTES（YAML=600）, algorithm: settings.API.ALGORITHM(HS256)}`。

## 五、安全红线

1. **SIMULATED_TRADING 总开关**：`TradeSettings.SIMULATED_TRADING=True`（默认值），由 `.env` 控制，`trade` 模块配置（config.yaml `simulated_trading: true`）与 main.py 均读取；**开发/测试环境严禁设为 false**（AGENTS.md/CLAUDE.md 安全红线），否则产生真实资金交易。相关默认参数：`SIM_INITIAL_CAPITAL=1000000`、`MAX_POSITION_RATIO=0.8`、`STOP_LOSS_PERCENT=0.1`。
2. **AUTH_ENABLED 开发/生产差异**：config.yaml 默认 `false`（跳过 JWT、自动管理员、创建种子用户 superadmin、DB 异常时回退硬编码 developer 用户）—— 仅限开发/测试；生产必须 `true` 并更换 SECRET_KEY（默认值注释明确要求）。
3. 其他：`get_all_settings()` 敏感脱敏；token 黑名单（登出/失效）Redis 优先；.env 文件禁止写入（守卫规则）。

## 九、关键结论与待确认项

1. 认证链路完整：JWT（HS256，双 token）+ 黑名单（Redis→内存降级）+ AUTH_ENABLED 开关（开发直通/生产强校验）+ 密码 AES→BCRYPT 自动迁移。
2. **token 有效期存在三处不一致**（JWTManager 默认 30 分钟 vs config.yaml 600 vs 模块常量 60），实际生效值待确认；SECRET_KEY 默认值为占位符，生产必须覆盖。
3. 数据库环境变量前缀在代码（`DB_DEV_*`/`DB_PROD_*`）与 CLAUDE.md（`DEV_DATABASE__*`）间存在命名差异，待确认 .env 实际键名。
4. 密码重置/邮箱验证/重发验证三个端点代码内抛 `NotImplementedError`（HTTP 501），属未实现能力。
5. 事件枚举多于已实现事件类（如 system.user.deleted、system.role.* 无构造器），发布侧待补全。
