## 一、模块定位

分析模块（analysis）提供**绩效指标计算、风险分析、归因分析、策略对比、交易分析、报告生成**六类能力，全部由无状态 Service 委托纯计算 Analyzer/`FinancialCalculator` 完成。

**AnalysisEngine**（analysis_engine.py）职责：
- 初始化组件：`AttributionService`、`AnalysisIntegrationService`、`AnalysisEventHandler`（analysis_engine.py:42-54）；
- 订阅外部模块事件：`strategy.executed`、`backtest.task.completed`、`trade.order.completed`（analysis_engine.py:64-85），由 `AnalysisIntegrationService` 自动触发对应分析（策略执行→月初至今绩效、回测完成→区间绩效+风险、交易完成→近 30 天绩效，integration_service.py:29-33）；
- 提供 `analyze_strategy(strategy_id, ..., analysis_type)`（performance/risk/attribution，归因默认 Fama-French 模型）与 `analyze_portfolio(portfolio_id, ..., attribution)` 两个同步分析入口（analysis_engine.py:123-201）。

**AnalysisIntegrationService**（integration_service.py）：中央调度器，分析完成后通过 EventEngine 发布 `PerformanceAnalysisCompletedEvent / RiskAnalysisCompletedEvent / AttributionAnalysisCompletedEvent`。

## 二、绩效指标体系

### 2.1 指标清单与公式来源

核心实现 `PerformanceService.calculate_strategy_performance`（performance_service.py:109-300），计算公式与来源：

| 类别 | 指标 | 公式/实现（来源） |
|:---|:---|:---|
| 收益 | total_return | `(end_value - start_value) / start_value`（performance_service.py:183） |
| 收益 | annual_return | `FinancialCalculator.annualized_return(returns)`（performance_service.py:184） |
| 收益 | cagr | `(end/start)^(1/years) - 1`，years=自然日/365.25（performance_service.py:185） |
| 风险调整 | sharpe_ratio | `FinancialCalculator.sharpe_ratio(returns, risk_free_rate=0.03)`（策略级） |
| 风险调整 | sortino_ratio | `FinancialCalculator.sortino_ratio(returns, risk_free_rate=0.03)` |
| 风险调整 | calmar_ratio | `FinancialCalculator.calmar_ratio(equity)` |
| 风险调整 | information_ratio | 需基准：`FinancialCalculator.information_ratio(returns, benchmark)` |
| 风险 | volatility | `FinancialCalculator.annualized_volatility(returns)`（std×√252） |
| 风险 | max_drawdown | `FinancialCalculator.maximum_drawdown(equity)`（净值峰值回撤） |
| 风险 | var_95 / var_99 | `FinancialCalculator.value_at_risk(returns, confidence=0.95/0.99)` |
| 风险 | expected_shortfall | `FinancialCalculator.conditional_value_at_risk(returns, confidence=0.95)`（CVaR） |
| Alpha/Beta | alpha / beta / tracking_error / r_squared | 需基准：`FinancialCalculator.alpha/beta/tracking_error`；r² = 策略与基准日收益相关系数平方（performance_service.py:201-220） |
| 交易统计 | win_rate / profit_factor / average_win / average_loss | 基于 trade.pnl 正负分类：胜率=盈利交易/总交易，盈亏比=总盈利/总亏损（performance_service.py:855-917） |

> 公式实现位于 `utils/core_utils/math_utils/financial_calculator.py`（PerformanceService 委托，本设计未逐行核对其中实现，公式语义以 performance_service.py 调用处注释为准）。

**数据链路**：策略净值曲线从交易记录重建（`_reconstruct_equity_curve`，平均成本法：BUY 增加成本基础、SELL 按成本比例减少，无行情时按成本计价，equity=cash+cost_basis，performance_service.py:694-805）；无交易时回退读 `backtest_equity_curves` 表（performance_service.py:647-692）；账户绩效从日资产快照（`account_daily_performance`）重建（`calculate_account_performance`，performance_service.py:305-486，不含 Alpha/Beta 与交易统计）。

### 2.2 扩展指标（分析器层，Analyzer 为独立纯计算类）

- **ReturnAnalyzer**（analyzers/performance/return_analyzer.py）：总收益/年化（几何，252 交易日）/CAGR/月度/年度/滚动收益（30/60/90/180/360d）、收益统计（均值/中位数/偏度/峰度/分位数）、正态性检验与分布识别（normal/student_t/fat_tailed）、稳定性（年化波动率/变异系数/下行风险）、周期性（FFT 主频率，需≥50 样本）；`compare_returns_with_benchmark` 输出超额收益/信息比率/跟踪误差/Beta/Alpha/R²/配对 t 检验/Wilcoxon；
- **RiskAnalyzer**（analyzers/performance/risk_analyzer.py）：VaR 四法（历史分位/参数正态/Monte Carlo(10000 次)/Cornish-Fisher 修正）、CVaR/ES、最大回撤详情（持续时间/恢复时间/滚动回撤/主回撤期）、压力测试（2008 股灾 -5%、2010 闪崩 -9%、2020 疫情 -8%、2σ/3σ）、集中度（HHI/CR1/CR3/CR5/Gini/熵指数/行业集中度）、流动性（价差与冲击按市值对数插值、L-VaR）、GARCH(1,1) 波动率预测（arch 库，可选）；
- **CostAnalyzer / ExecutionAnalyzer**（analyzers/trade/）：成本分解（佣金/税/滑点，滑点估算为交易额 0.1%）、执行质量（成交率、执行时间=filled_at−submitted_at、价格改进）——由 `TradeAnalysisService` 汇总（trade_analysis_service.py:90 起）。

### 2.3 策略日绩效超表（strategy_daily_performance）

- 表结构（business_models.py:209-228）：`strategy_id / trade_date / daily_return / total_return / max_drawdown / sharpe_ratio / created_at`，索引 `(strategy_id, trade_date)`；
- **TimescaleDB 超表**：`docs/sql/create_table.sql:3597-3602` `create_hypertable('strategy_daily_performance','trade_date', chunk_time_interval=>'180 days')`，Repository 继承 `HyperRepositoryBase`（strategy_daily_performance_repo.py:22，含 `batch_create_performance` 批量写入）；
- **写入方（跨模块）**：由 **strategy 模块** 的 `PerformanceTrackerEngine`（strategy/engines/performance_tracker.py）写入——它订阅账户模块的 `account.settlement.completed` 事件，遍历 RUNNING/PAUSED 策略，调用 strategy 模块 `PerformanceService` 计算指标后写入；即链路为：账户日终结算完成 → 策略日绩效回填；
- **analysis 模块当前不直接读写该表**：绩效计算走"交易记录重建净值曲线 → backtest_equity_curves 回退"两条路径（performance_service.py:590-693）；且 backtest_engine.py:1427 注释表明回测结果已不再写入该表（v6.13 移除）；
- **潜在事件字段不一致（待确认）**：`PerformanceTrackerEngine` 从 `event.data.get("trade_date")` 取结算日，而 `AccountSettlementCompletedEvent.data` 写入的是 `settlement_date` 字段（settlement_events.py:228），取不到时回退 `date.today()`。

## 三、归因分析

### 3.1 Brinson 归因（`AttributionService.perform_brinson_attribution`，attribution_service.py:95-214）

- **行业级**（传 `sectors` 参数，`_perform_sector_brinson`）：行业内股票等权平均收益率，分解公式：
  - 配置效应 = Σ(w_ps − w_bs) × r_bs；选择效应 = Σ w_bs × (r_ps − r_bs)；交互效应 = −配置 − 选择（代码注释：交互为近似，精确公式不同，attribution_service.py:662-665）；
- **个股级**（不传 sectors，`_perform_stock_brinson`）：对组合/基准股票并集逐只计算
  配置 = (w_pn − w_bn) × r_b、选择 = w_bn × (r_p − r_b)；注释说明当前用 **Brinson 非 Fachler 变体**（不减基准总收益，attribution_service.py:751-755）；
- **数据源**：组合持仓权重=各股持仓市值占比（`_get_portfolio_positions`，strategy_ 前缀解析策略→账户）；基准成分股**优先 index_weight 表真实成分+权重**，缺失时回退 stock_basic 前 N 只等权（`_get_index_constituents`，attribution_service.py:419-486）；支持基准仅 `000300.SH`（沪深300）与 `000905.SH`（中证500）；
- 单股区间收益 = 区间末日收盘/首日收盘 − 1（`_get_stock_return`）。

**BrinsonAttribution 分析器**（analyzers/attribution/brinson_attribution.py）：提供标准三效应分解（`calculate_brinson_with_interaction`，交互=(w_p−w_b)×(r_p−r_b)，并校验 配置+选择+交互 = 主动收益，归因误差 attribution_error 输出）、多期 Brinson（`perform_multiperiod_brinson`）、Fachler 变体（`calculate_brinson_fach_attribution`）。注意：**Service 层当前实现的是近似交互式分解，未调用该分析器**（待确认是否后续替换）。

### 3.2 因子归因（`AttributionService.perform_factor_attribution` + `FactorAttribution`）

- 模型：Fama-French 三因子（MKT/SMB/HML）、Carhart 四因子（+UMD）；至少需 10 个交易日（service 层校验，attribution_service.py:252-253）；
- **因子数据（关键限制）**：`_get_factor_returns` 仅能从 `000300.SH` 行情计算 MKT（收盘价 pct_change），SMB/HML/UMD **无真实数据源 → 直接返回 None → 抛"无法获取因子收益率"**，代码 TODO 注明需对接真实因子数据源（如 Barra CNE5，attribution_service.py:847-907）。即**因子归因当前在无外部因子数据时不可用**；
- 算法（analyzers/attribution/factor_attribution.py）：OLS（`np.linalg.lstsq`）/岭回归/WLS（两步可行 GLS）估计因子暴露 β；因子贡献 = β × mean(因子收益)；特异性收益 = 实际收益 − 预测收益；归因质量（相关系数/R²/MAE/RMSE/IC/跟踪误差解释度）；`_validate_attribution` 校验归因误差 ≤ 1e-6；另含滚动归因（window=252、step=22）与 Barra 风格归因（风险贡献分解）。

### 3.3 归因流程 mermaid

```mermaid
flowchart TD
    A[API/引擎触发归因] --> B{归因类型}
    B -->|Brinson| C[取组合持仓: 市值权重<br/>+ 基准成分: index_weight 优先/等权回退]
    C --> D[计算组合与基准区间收益]
    D --> E[行业级/个股级 Brinson 分解]
    E --> F[配置效应 + 选择效应 + 交互效应]
    F --> G[AttributionAnalysis 结果<br/>sector/stock_attributions]
    B -->|因子归因| H[组合日收益序列 ≥10 交易日]
    H --> I[因子收益率: MKT 从 000300.SH 计算<br/>SMB/HML/UMD 无源→退出]
    I --> J[OLS/WLS/Ridge 估计因子暴露 β]
    J --> K[因子贡献 = β × mean(factor_return)<br/>+ 特异性收益 + 质量指标]
    K --> L[factor_attributions/exposures]
    G & L --> M[compare_attribution_models 多模型对比]
```

## 四、报告生成

### 4.1 报告管理（`ReportManager`，managers/report_manager.py）

`generate_report(report_data, report_type, user_id, title)` 按类型 `performance / attribution / comparison / trade_analysis / comprehensive` 分别附加图表（`ChartGenerator` + `ReportGenerator`，visualizers/），状态 generating→completed，保存至 `report_storage_path`（默认 `./reports`）并有内存缓存；`analysis_reports` 持久化由 `AnalysisReportRepository` 完成。

### 4.2 analysis_reports 表（business_models.py:1342-1373）

字段：`report_type`（daily/weekly/monthly/performance/risk/custom）、`report_name`、`report_config(JSON)`、`report_data(JSON)`、`format`（json/html/pdf/excel）、`status`（pending/generating/completed/failed）、`generated_by`、`file_path`、`file_size`、`is_public`、`tags(JSON)`；关联 `analysis_tasks`（AnalysisTask，business_models.py:1376-1405，含 progress/result/error_message）。

### 4.3 报告事件与跨模块写入

- 事件：`ReportGenerationStartedEvent / CompletedEvent / FailedEvent`（analysis.report.{started,completed,failed}）；
- 每日任务 `DailyAnalysisTasks.run_daily_analysis`（daily_analysis_tasks.py:62-100）：非交易日跳过，并发执行 绩效/风险/交易分析/日报生成/风险告警 五任务；
- **跨模块**：账户模块 `ReconciliationManager` 将对账差异报告（balance_discrepancy/position_discrepancy/discrepancy_fix/reconciliation）写入同一张 `analysis_reports` 表（reconciliation_manager.py:756-916），报告管理为共享能力（符合"模块间仅数据共享"的现状，跨模块调用方式待确认）。
