                       │    │  策略衍生    │    │  ← 核心资产层

### 2.2 各层详细说明

#### 第一层：基础数据层（市场原始数据）

**定位**：外部获取的原始数据，未经加工。这是所有上层分析的原材料。

| 数据类别 | 核心表 | 数据源 | 更新频率 | 保留策略 |
|:---|:---|:---|:---|:---|
| A股日线 | `stock_daily` [超表] | Tushare | 每日盘后 | 10年 |
| A股分钟线 | `stock_minutes` [超表] | Tushare | 每日盘后 | 3年 |
| A股周线/月线 | `stock_weekly/monthly` [超表] | Tushare | 每周/月 | 永久 |
| 复权因子 | `stock_adj_factor` [超表] | Tushare | 每日 | 永久 |
| 每日基础指标 | `stock_daily_basic` [超表] | Tushare | 每日 | 永久 |
| 涨跌停价格 | `stock_daily_limit` [超表] | Tushare | 每日 | 永久 |
| 资金流向 | `stock_moneyflow` [超表] | Tushare | 每日 | 2年 |
| 股票基础信息 | `stock_basic` / `stock_company` | Tushare | 按需 | 永久 |
| 财务利润表 | `financial_income` | Tushare | 季/年 | 永久 |
| 财资负债表 | `financial_balance` | Tushare | 季/年 | 永久 |
| 财资现金流表 | `financial_cashflow` | Tushare | 季/年 | 永久 |
| 财报披露日期 | `financial_disclosure_dates` | Tushare | 按季度 | 永久 |
| ETF数据 | `etf_basic` / `etf_daily` / `etf_minute` | Tushare | 每日 | 10年 |
| 指数数据 | `index_basic` / `index_daily` [超表] | Tushare | 每日 | 永久 |
| SW行业分类 | `index_sw_classify` / `index_sw_member` | Tushare | 按需 | 永久 |
| 交易日历 | `trade_calendar` [超表] | Tushare | 每年 | 永久 |
| 宏观数据 | `macro_cpi` / `macro_ppi` / `macro_gdp` | Tushare | 月/季 | 永久 |
| 北向资金 | `stock_moneyflow_hsgt` | Tushare | 每日 | 永久 |
| 分析师预测 | `stock_forecast_pro` | Tushare | 按需 | 永久 |

**数据量估算**：
- 日线：约 5500 只股票 × 250 天/年 × 10 年 ≈ 1375 万行
- 分钟线：约 5500 只 × 240 分钟/天 × 250 天/年 × 3 年 ≈ 9.9 亿行（自动分区+压缩）
- 财务三表：约 5500 只 × 4 期/年 × 20 年 ≈ 44 万行/表
- **总计**：约 93 张表，日均新增约 5-10 万行

#### 第二层：衍生数据层（计算加工数据）

**定位**：从第一层数据计算出的中间产品，可直接被策略和回测消费。

| 数据类别 | 核心表 | 计算方式 | 依赖第一层 |
|:---|:---|:---|:---|
| 因子数据 | `factor_data` [超表] | `factor_calculators.py` | stock_daily + financial_income/balance |
| 复权价格 | `stock_adjusted_prices` [超表] | `adjusted_price_generator.py` | stock_daily + stock_adj_factor |
| 技术指标(基础) | `stock_factor_daily` | Tushare stk_factor 接口 | stock_daily |
| 技术指标(专业) | `stock_factor_pro_daily` | Tushare stk_factor_pro 接口 | stock_daily |
| 行业指数日线 | `index_sw_daily` [超表] | Tushare | index_sw_classify |
| 指数估值 | `index_dailybasic` | Tushare | index_basic |

**关键设计 — Point-in-Time 正确性**：

```
v3.1 修复前（存在未来函数）：
  查询时点 2023-04-15，查询 financial_income
  → 返回 end_date=2023-03-31 的 Q1 数据（4月28日才实际披露）
  → 回测用了"未来"才知道的数据 → 结果虚高

v3.1 修复后（PIT 正确）：
  查询时点 2023-04-15，查询 financial_income
  → 条件 f_ann_date <= '2023-04-15'（只取已公告的）
  → 只返回 end_date=2022-12-31 的年报（3月底已披露）
  → 回测使用该时点真实可见的数据 → 结果可信
```

> **v3.1 新增**：`_get_financial_data()` 在查询 `FinancialIncome` 和 `FinancialBalance` 时，
> 均增加 `f_ann_date <= query_date` 约束，确保回测/因子计算不会泄漏未来数据。

#### 第三层：策略衍生层（核心资产层）

**定位**：策略运行和回测产生的数据。这是**你独有的、别人没有的**数据——真正的护城河。

| 数据类别 | 核心表 | 产生方式 | 价值 |
|:---|:---|:---|:---|
| 策略定义 | `strategies` | 策略编辑器 + 模板 | 策略知识编码 |
| 策略版本 | `strategy_versions` | 每次保存 | 回溯任意版本 |
| 策略参数 | `strategy_parameters` | 策略配置 | 参数空间定义 |
| 回测任务 | `backtest_tasks` | 回测执行 | 全部回测历史 |
| 回测净值 | `backtest_equity_curves` [超表] | 回测每日盯市 | 收益曲线来源 |
| 回测交易 | `backtest_trades` | 回测撮合 | 每笔模拟交易 |
| 回测持仓 | `backtest_positions` | 回测每日快照 | **v3.1 新增** 持仓分析 |
| 交易信号 | `signals` [超表] | 策略 on_bar 输出 | 信号→决策链路 |
| 订单/成交 | `orders` / `trades` | 实盘执行 | 真实交易记录 |
| 持仓快照 | `position_snapshots` | 每日结算 | 实盘持仓追溯 |
| 风控事件 | `risk_events` [超表] | 风控引擎 | 风险识别能力 |
| 策略绩效 | `strategy_daily_performance` [超表] | 每日计算 | 策略资金曲线 |

**v3.1 溯源链路**：

```
strategy_versions (V1.3, 2026-07-01)
    ├── backtest_tasks.strategy_version_id → 回测用的是 V1.3
    │       └── backtest_equity_curves   → 净值曲线
    │       └── backtest_trades          → 交易明细
    │       └── backtest_positions       → 持仓快照（v3.1 新增）
    │
    └── signals.strategy_version_id → 实盘信号源于 V1.3
            └── orders → trades → positions
                    └── account_daily_performance

查询："2026年7月的这笔买300750.SZ的信号，是基于哪个版本的策略？
       那个版本的回测夏普是多少？"
↓ 一条SQL即可追溯全部链路
```

#### 第四层：洞察分析层

**定位**：对策略绩效的深度分析，形成可操作洞察。

| 分析类型 | 表/服务 | 输入数据 | 输出 |
|:---|:---|:---|:---|
| 绩效评估 | `analysis_reports` + `PerformanceService` | 策略净值 + 交易明细 | 夏普/回撤/胜率/Alpha |
| 归因分析 | `AttributionService` (Brinson + FF) | 持仓 + 基准 | 选股贡献 vs 行业配置贡献 |
| 策略对比 | `analysis_comparisons` | 多策略绩效 | 相关性矩阵 + 排名 |
| 市场状态分析 | `market_state_daily` [超表] **v3.1 新增** | 策略输出 | 牛市/震荡/熊市判断 |

**v3.1 新增：market_state_daily 超表**：

```
用途示例：
  SELECT regime, AVG(daily_return)*252 AS ann_ret
  FROM strategy_daily_performance sp
  JOIN market_state_daily ms ON sp.trade_date = ms.trade_date
  WHERE sp.strategy_id = 'xxx'
  GROUP BY regime;

结果：
  BULL    年化 +45%  (策略在牛市中表现优秀)
  NEUTRAL 年化 +12%  (震荡市中等)
  BEAR    年化 -8%   (熊市亏损 → 需要改进风控)
```

#### 第五层：知识决策层（未来目标）

当前状态：架构就绪，数据积累中。需要 2-3 个完整市场周期的数据后才能真正激活。

| 能力 | 依赖数据 | 当前状态 |

## 四、数据资产"护城河"评估

### 4.1 不可替代性矩阵

| 资产 | 可替代性 | 护城河深度 | 说明 |
|:---|:---|:---|:---|
| 第一层：市场数据 | **高可替代** | 浅 | Tushare / Wind / 东方财富都能获取，无独占性 |
| 第二层：衍生数据 | **中可替代** | 中 | 别人也能算，但你的历史回填 + PIT 正确性不易复制 |
| 第三层：策略衍生 | **低可替代** | **深** | 回测历史 / 交易记录 / 信号链路 — **只有你有** |
| 第四层：洞察分析 | **低可替代** | **深** | 归因结论 / 市场理解 — 基于你的策略和数据 |
| 第五层：知识 | **极低可替代** | **最深** | 策略失效判断 / 环境自适应知识 — **任何人都复制不了** |

### 6.2 数据保留策略

| 策略 | 表 | 配置 |
