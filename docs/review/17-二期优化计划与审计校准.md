- **影响**：任何一次权重调整需改 5 处；漏改即静默落到"未知 ID → 权重 0 → 归一化后等权"的 fallback（`capital_allocator.py:216-226`），且**无告警**。回测与实盘权重口径可背离而不被察觉。事件旁路违反 `audit.md`「模块间通信仅通过 EventEngine」。
- **建议**：抽 `shared/portfolio/`（纯计算，无 DB / 无事件依赖）：`RegimeService`（唯一判定入口）+ `AllocationPolicy` 接口（等权 / Regime 查表 / 逆波动率 / 风险平价）+ `constraints`（组合层约束）。回测与实盘只保留"权重 → 资金落地方式"的差异。默认权重单源落 DB，前端只读。补 `PortfolioRebalanceEvent`。
- **验收**：全仓 `REGIME_BASE_ALLOCATION` 字面量只剩 1 处；同一 regime 下回测与实盘输出同一权重（可加断言测试）。
- **优先级**：P1（架构级）。**前置是 8-4 先把 regime 标准定下来**，否则公共化只是把错口径集中到一处。

### 8-2 regime 判定 band 三处不一致

- **现状**：`capital_allocator.py:73` `DEFAULT_PARAMS["regime_gate_band"] = 0.0`；`:186` 取值 `.get("regime_gate_band", 0.03)`；实盘 `composite_service.py:576` **硬编码 0.03**；高波动策略 `high_vol_momentum_strategy.py:126` `annual_gate_band = 0.03`。
- **影响**：组合回测走**二元**判定（band=0）、实盘走 **±3% 三态** → 贴着年线的震荡行情下，回测判 BEAR 取 0.9/0.1 权重行，实盘判 RANGE 取 0.2/0.8。**组合回测结论与实盘行为不可互换引用。**
- **建议**：统一到单一参数（建议 0.03，与策略年线门同源），前端与后端默认生成器都不再各自决定。
- **验收**：同一交易日回测与实盘输出同一 regime；该参数可从一处配置到三处。
- **优先级**：**P0（先行）**——不修则所有组合回测结论不可信；改动面小。

### 8-3 组合回测的 CSI500 无预热 → 窗口前 250 日恒 RANGE

- **现状**：`backtest_engine.py:963` 调 `_load_benchmark_data("000905.SH", start_date, end_date)`，该函数（`:1324-1358`）严格 `BETWEEN :start AND :end`，**不向前多取**；`compute_regime`（`shared/market_regime.py:40-41`）在可用交易日 <250 时返回 RANGE。
- **影响**：① 回测窗口 <250 交易日 → **全程 RANGE**，分配器退化为固定权重；② 窗口 ≥250 时前 249 个交易日仍为 RANGE，且 MA250 只含窗口内数据，与实盘"含完整历史"的 MA250 不是同一个数 → **路径依赖策略的滚动起始日分析被系统性污染**。
- **建议**：加载基准时向前多取 250 个交易日（预热段不参与撮合，只供 regime 判定）；或在 `run_composite` 前单独预取并传入 `csi500_closes`。
- **验收**：回测首日即得到与实盘同源的 regime；6 个滚动起始日首日 regime 不再恒为 RANGE。
- **优先级**：**P0（先行）**，与 8-2 同批。

### 8-4 regime 判定口径本身不准

- **现状（4 条）**：
  1. **两套 regime 并存**：`shared/market_regime.py:11`（CSI500 vs MA250）与 `modules/data/services/market_state_classifier.py`（沪深300 MA20/MA60/slope20 → 写 `market_state_daily.regime`）。后者仍在被消费：`market_router.py:320` 大盘状态雷达、`breadth_service.py:272`、`market_state_service.py:40`、`etf_factor_daily.py:176-207`（映射成 `market_regime` 因子）。2026-08-27 实盘曾切到后者**当天翻车**并改回（`composite_service.py:560-563` 有登记），**但第二套未下线**。
  2. **单指数代表全市场**：CSI500 是中盘指数，而策略实际交易小盘股 / ETF / 全球资产——2024-01 的 54% 回撤根因即为该错配。`shared/market_regime.py:54` 的 `breadth_to_regime()`（全市场站上 MA250 比例）**已写好但全仓零调用**。
  3. **无确认、无 hysteresis**：只有 MA250 ±band 一个条件，无斜率 / 广度 / 量能；`capital_allocator.py:153` regime 一变即重算权重 → 贴年线反复穿越时**资金来回搬**。
  4. **静默降级**：数据不足 250 条 → RANGE（`:40-41`）；`closes[-250:]`（`:43`）取的是"最近 250 条**记录**"而非 250 个**交易日**，缺日会使均线口径漂移且不被拦截。
- **影响**：组合资金方向由单一中盘指数的一年均线决定，与策略实际持仓域错配；两套 regime 并存导致"前端雷达显示的 regime ≠ 组合实际使用的 regime"。
- **建议**：① 明确唯一 regime 标准（多指数 / 广度 / 斜率 / 确认延迟 / 阈值带）；② 给 `breadth_to_regime` 接线或删除；③ 第二套明确降级为"展示用"或合并；④ 加 hysteresis 与缺日检测。
- **验收**：全仓 regime 判定只有一个入口；同一交易日所有消费者得到同一值；缺日 / 数据不足有 WARNING，不静默。
- **优先级**：P1（**是 8-1 公共化的前置**）。

### 8-5 风险平价 P1 全程未实现

- **现状**：`capital_allocator.py:288-301` `_blend_with_risk_parity()` 为 `# P1 TODO`，直接返回原权重；`_vol_buffers`（`:128-131`）创建后**从未被填充**；`risk_parity_enabled` 默认 False（`:67`）→ `_should_rp_rebalance()`（`:264-285`）永不触发，`rp_rebalance_freq` / `rp_blend_strength` / `vol_lookback` 均为**死参数**。设计文档中的"主动再平衡"亦未实现。

- **建议**：作为 8-1 的 `AllocationPolicy` 插件实现（逆波动率 → ERC），同时引入策略间相关性（至少做集中度上限）。

### 8-6 组合层风控缺失

- **现状**：`_compute_allocation()`（`capital_allocator.py:194-258`）只做归一化 + clamp，**无**总敞口上限、无重叠标检测、无组合级回撤熔断、无相关性 / 集中度约束。实盘组合模式下 `available_capital = account_total × 权重` 是**分配额而非真实可用现金**（已登记于 `docs/01-业务设计/策略资金与仓位契约.md` §2.4）。
- **影响**：两腿经同一标的或同质风格同时满仓时，组合实际敞口可超 100%（实盘仅靠 broker 资金校验兜底）；回撤熔断只在策略层（各策略自带 ATR 止损），组合层无兜底。
- **建议**：`shared/portfolio/constraints.py` 实现总敞口上限 + 重叠标的检测 + 组合级回撤熔断，回测与实盘共用。
- **验收**：构造"两策略同买同一标的"用例，组合层能识别并约束。
- **优先级**：P2。

### 8-7 注释 / 日志与实现不符（易误导后续判断）

### 8-8 `_normalize_and_clamp` 的 [5%, 95%] 钳制不成立

- **现状**：`capital_allocator.py:234-258` 顺序为「归一化 → clamp 到 [0.05,0.95] → **再归一化**」，第二次归一化会使被抬到 5% 的值重新低于 5%。例：`{0.01,0.01,0.98}` → clamp 后 `{0.05,0.05,0.95}` 和为 1.05 → 最终 `{4.76%, 4.76%, 90.48%}`。
- **影响**：docstring 承诺的上下界不生效；小权重策略实际拿到的份额低于设计的 5% 下限。
- **建议**：改为单次带约束的归一化（先 clamp 再按比例分配剩余额度），或放弃下限语义并改注释。
- **优先级**：P3。

## 十、本文档的方法论备注

本次审计的**核心教训**：独立审计 Agent 能高效定位代码结构问题，但其**结论性判断**（尤其「因果链」推断）需要回原始数据核验——
本文档第零部分 7 条中有 5 条被推翻或修正，其中 1 条（0-4 僵尸持仓）若直接执行会**删除系统有意保留的数据**。

**因此纪律**：
1. 凡涉及改数据/改代码的结论，先回原始数据（查库 / 读原始代码）核验；
2. Agent 的推断不得直接作为执行依据；
3. 裸 SQL 查询**不等于**系统口径——仓储层（如 `include_zero`）才是契约。
