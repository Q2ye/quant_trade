- **现状**：热更新规范写了「退市风险过滤 + 实盘失效监控（**何时该停用**）」，但**无阈值、无自动动作**；`strategy-review` C3 亦只设问不给数。运行期唯一告警是「实盘 vs 回测偏差每周对比 > 2σ」（需人工响应）。
- **影响**：失效识别依赖人工偶然发现 —— 而本项目「回撤大」不构成可执行的停用信号（跨市场 7.6 年口径 84.5% 的交易日处在某段回撤中）。

### 8-5 风险平价 P1 全程未实现

- **现状**：`capital_allocator.py:288-301` `_blend_with_risk_parity()` 为 `# P1 TODO`，直接返回原权重；`_vol_buffers`（`:128-131`）创建后**从未被填充**；`risk_parity_enabled` 默认 False（`:67`）→ `_should_rp_rebalance()`（`:264-285`）永不触发，`rp_rebalance_freq` / `rp_blend_strength` / `vol_lookback` 均为**死参数**。设计文档中的"主动再平衡"亦未实现。
- **影响**：权重与策略风险完全脱钩（不区分波动 / 近期表现），风险贡献天然失衡；多个同质动量策略各拿同等资金 = 隐性加倍杠杆（组合层也无相关性输入，见 8-6）。
- **建议**：作为 8-1 的 `AllocationPolicy` 插件实现（逆波动率 → ERC），同时引入策略间相关性（至少做集中度上限）。
- **验收**：策略波动差异能反映到权重；同质策略并存时有相关性约束。
- **优先级**：P2。

### 8-6 组合层风控缺失

- **现状**：`_compute_allocation()`（`capital_allocator.py:194-258`）只做归一化 + clamp，**无**总敞口上限、无重叠标检测、无组合级回撤熔断、无相关性 / 集中度约束。实盘组合模式下 `available_capital = account_total × 权重` 是**分配额而非真实可用现金**（已登记于 `docs/01-业务设计/策略资金与仓位契约.md` §2.4）。
- **影响**：两腿经同一标的或同质风格同时满仓时，组合实际敞口可超 100%（实盘仅靠 broker 资金校验兜底）；回撤熔断只在策略层（各策略自带 ATR 止损），组合层无兜底。
- **建议**：`shared/portfolio/constraints.py` 实现总敞口上限 + 重叠标的检测 + 组合级回撤熔断，回测与实盘共用。
- **验收**：构造"两策略同买同一标的"用例，组合层能识别并约束。
- **优先级**：P2。

### 8-7 注释 / 日志与实现不符（易误导后续判断）

- **现状**：`backtest_service.py:588` docstring 与 `:522` 日志写「熊 0.7/0.3、震 0.5/0.5、牛 0/1」，实现是 `(0.9,0.1)/(0.2,0.8)/(0,1)`（`:600`）；`capital_allocator.py:73` 注释称「与高波动 `annual_gate_band` 对齐」，实际一个是 0.0 一个是 0.03；`capital_allocator.py:179` docstring 写「带 3% 带」，实际取值 0.0。
- **影响**：本次分析中有三处结论曾被注释误导，须回代码核实才纠正；后续审计会重复踩。
- **建议**：注释 / 日志改为与实现一致；更优解是由 8-2 消除参数分叉后删除重复描述。
- **优先级**：P0（与 8-2 同批，改注释零风险）。

### 8-8 `_normalize_and_clamp` 的 [5%, 95%] 钳制不成立

- **现状**：`capital_allocator.py:234-258` 顺序为「归一化 → clamp 到 [0.05,0.95] → **再归一化**」，第二次归一化会使被抬到 5% 的值重新低于 5%。例：`{0.01,0.01,0.98}` → clamp 后 `{0.05,0.05,0.95}` 和为 1.05 → 最终 `{4.76%, 4.76%, 90.48%}`。
- **影响**：docstring 承诺的上下界不生效；小权重策略实际拿到的份额低于设计的 5% 下限。
- **建议**：改为单次带约束的归一化（先 clamp 再按比例分配剩余额度），或放弃下限语义并改注释。
- **优先级**：P3。

### 8-9 组合事件未实现（架构约束）

- **现状**：`modules/strategy/events/__init__.py:35` 为 `# 组合事件 (暂未实现)`，`PortfolioRebalanceEvent` 被注释；实盘 rebalance 直接调 `strategy_manager.update_strategy_capital()` 改运行中策略的内存态。

- **建议**：随 8-1 一并事件化。
- **优先级**：P3（并入 8-1）。

## 十、本文档的方法论备注

本次审计的**核心教训**：独立审计 Agent 能高效定位代码结构问题，但其**结论性判断**（尤其「因果链」推断）需要回原始数据核验——
本文档第零部分 7 条中有 5 条被推翻或修正，其中 1 条（0-4 僵尸持仓）若直接执行会**删除系统有意保留的数据**。

**因此纪律**：
1. 凡涉及改数据/改代码的结论，先回原始数据（查库 / 读原始代码）核验；
2. Agent 的推断不得直接作为执行依据；
3. 裸 SQL 查询**不等于**系统口径——仓储层（如 `include_zero`）才是契约。
