# REQ-20261114-highvol-moneyflow-select 设计

> 阶段 S2 ｜ 档位 T3 ｜ 起草 2026-11-14 ｜ 对象 `high_vol_momentum_strategy.py`（`dc862847`）
> 上游：`01-需求.md`（AC-1~AC-6）｜ 研究：`_hv_newdata_probe.py`、`_mf_ic_panel.csv`

## 方案概述

把「资金流」做成**行情 DataFrame 上的一列**（`mf_ratio`），由数据层一次性算好，策略只读列——回测与实盘同一条通路，策略侧零新增查询。

三层改动：

1. **仓库层**：新增 `StockMoneyflowRepository.get_mf_ratio_batch()`，按 `(ts_code, trade_date)` 返回 `net_mf_amount / circ_mv`。
2. **数据层**：`data_feed_engine` 在组装每只股票的 DataFrame 时贴上 `mf_ratio` 列。
3. **策略层**：`_score_candidate` 读取当日 `mf_ratio`，按 A（打分乘子）或 B（硬门槛）生效，默认关闭。

## 契约

### 1. 策略参数（`DEFAULT_PARAMS`）

| 名称 | 类型 | 默认 | 语义 |
|:--|:--|--:|:--|
| `enable_moneyflow_factor` | bool | `False` | A 接法开关：动量分 × 资金流分位 |
| `moneyflow_weight` | float | `0.0` | 乘子强度：`0.5 + w × pct`；w=0 等价关闭 |
| `moneyflow_min` | `Optional[float]` | `None` | B 接法门槛：`mf_ratio ≤ 此值 → 剔除`；None=关闭 |

> `enable_moneyflow_factor=False 且 moneyflow_min=None` → 与改动前**逐笔一致**（AC-3）。

### 2. 因子定义

```
mf_ratio(t) = stock_moneyflow.net_mf_amount(t) / daily_basic.circ_mv(t)
              # 两者单位均为万元，比值为无量纲
pct(t)      = 当日在「候选池内」的百分位秩 ∈ [0,1]
score'      = score × (0.5 + moneyflow_weight × pct)      # A 接法
若 mf_ratio ≤ moneyflow_min → return None                  # B 接法
```

- 分位以**当日候选池**为分母（不是全市场），避免池外股票影响排序。
- `mf_ratio` 为空 → **fail-open**：A 不调整（乘 1.0）、B 不剔除。

### 3. 仓库契约

```python
# shared/database/repositories/market/quote/stock_moneyflow_repo.py（一表一仓库）
async def get_mf_ratio_batch(
    symbols: List[str], start_date: date, end_date: date
) -> Dict[Tuple[str, str], float]:
    """返回 {(ts_code, trade_date): net_mf_amount / circ_mv}；circ_mv<=0 或缺失 → 不返回该键。"""
```

SQL：`stock_moneyflow m LEFT JOIN daily_basic b USING (ts_code, trade_date)`，`WHERE m.ts_code = ANY(:symbols) AND m.trade_date BETWEEN :start AND :end`。

### 4. 数据层契约

`data_feed_engine` 在逐股票组装 DataFrame 后：

```python
df["mf_ratio"] = [mf_map.get((code, str(d))) for d in df["trade_date"]]
```

- 列可空；缺失为 `None`/`NaN`。
- 不改变现有列顺序与类型；`limit` 分页逻辑不动。

### 5. 错误码

无 HTTP 面。数据层 join 失败 → `logger.warning` + 该列全 `NaN`（等价于因子关闭），**不阻断行情加载**。

## 数据流与依赖

```
[数据层，异步]
StockMoneyflowRepository.get_mf_ratio_batch（模块 shared，一表一仓库）
  → data_feed_engine 批量加载 → 每股票 DataFrame 增加 mf_ratio 列

[策略层，同步]
_score_candidate(code) 读 df["mf_ratio"].iloc[-1]
  → 当日候选池百分位 pct
  → score' = score × (0.5 + w×pct)  或  mf ≤ min → None
```

依赖方向：`modules/strategy/data_feed → shared/repositories → shared/database`，无反向；策略不新增 DB 调用。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|:--|:--|:--|:--|
| **A 数据层贴列** | 回测/实盘同源；策略零查询；一次 SQL 批量 | 动共用数据通路 | ✅ |
| B 策略内自载 | 不动数据层 | `on_bar_batch_end` 是同步函数，无法做 async 查询；逐日查询 1,400 次极慢 | ❌ |
| C 预计算落表（新增 `mf_ratio` 列到 `stock_daily`） | 最快 | 动 DDL + 同步链路，且 `circ_mv` 日更 | ❌ 后续若 A 通过再评估 |
| D 只在回测脚本里注入 | 不动生产代码 | 实盘与回测不同源，验证结论不可迁移 | ❌ |

## 回滚方案

- **一级（参数）**：`enable_moneyflow_factor=False`、`moneyflow_min=None` → 恢复现状，无需退代码。
- **二级（数据层）**：`mf_ratio` 列可空、无消费方时可移除贴列代码；行情加载不受影响。
- **三级（仓库）**：新仓库为纯新增，删除不影响其它模块。
- **判定条件**：默认参数回测与 `assets/baseline.json` 不逐笔一致 / MDD 恶化 >1pp / `check_all.py` 红。
- **时间窗**：S4 发现即当日回退。
