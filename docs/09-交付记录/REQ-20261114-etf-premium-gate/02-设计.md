# REQ-20261114-etf-premium-gate 设计

> 阶段 S2 ｜ 档位 T3（含 T2 的 DDL/数据面）｜ 起草 2026-11-14 ｜ 对象策略 `cross_market_momentum_strategy.py`（`strategies.id = 07651265-…`）
> 上游：`01-需求.md`（AC-1~AC-5）｜ 相关标准：`docs/06-标准规范/03_因子研究标准流程.md`（PIT）、`05_策略过拟合检验标准.md`

## 方案概述

把「折溢价」变成 `etf_daily` 上的派生列，让它在回测与实盘走**同一条数据通路**，策略侧只加一道默认关闭的门。

三层改动：

1. **数据层**：`etf_daily` 新增 `nav_pit`、`premium_rate` 两列，由 data 模块在 ETF 日线同步后幂等派生。
2. **仓库层**：ETF 批量查询把两列带出来（`etf_repo.py:525` 的 SELECT 增加两列）。
3. **策略层**：`_score_candidate` 填入 `metrics["premium_rate"]`，`_apply_filters` 增加一道「溢价」门，默认 `enable_premium_gate=False`。

**关键取舍：不换选股信号**。动量仍用 ETF 调整后价格，净值只用于「风险门」。换信号会让 7.6 年验证历史作废，另立 REQ。

## 契约

### 1. DDL（`docs/sql/create_table.sql`，`etf_daily` 定义后追加）

```sql
ALTER TABLE etf_daily ADD COLUMN IF NOT EXISTS nav_pit      NUMERIC(20,6);
ALTER TABLE etf_daily ADD COLUMN IF NOT EXISTS premium_rate NUMERIC(20,6);
COMMENT ON COLUMN etf_daily.nav_pit      IS '当日可知的最新单位净值（PIT：ann_date<=trade_date）';
COMMENT ON COLUMN etf_daily.premium_rate IS '折溢价率 = close/nav_pit-1；nav_pit 为空时为 NULL';
```

约束：两列可空、默认 NULL；不改主键、不建索引（按 (ts_code, trade_date) 已有主键，回填按单只 ETF 顺序扫描）。
⚠️ `etf_daily` 是 TimescaleDB 超表，执行前须 `\d etf_daily` 确认；加可空列不重写历史 chunk。

### 2. 派生规则（data 模块）

```
nav_pit(t)      = max{ unit_nav : ann_date <= t 且 nav_date <= t }   （取 nav_date 最大者；无 → NULL）
premium_rate(t) = close(t) / nav_pit(t) - 1                          （nav_pit 为 NULL 或 <=0 → NULL）
```

- 输入表：`etf_daily`（`close`）、`fund_nav`（`ann_date`/`nav_date`/`unit_nav`）
- 幂等：按 `(ts_code, trade_date)` 批量 `UPDATE`，重跑结果不变；只更新 `premium_rate IS NULL` 或日期窗口内的行
- 失败策略：单只失败 `logger.warning` 后跳过，不阻断 `etf_daily` 主同步；失败清单落 `data_sync_tasks` 备注

### 3. 仓库契约

| 位置 | 新增/变更 | 签名 |
|:--|:--|:--|
| `shared/database/repositories/market/quote/etf_daily_repo.py` | 新增 | `async def upsert_premium_batch(rows: List[Dict[str, Any]]) -> int` |
| 同上 | 新增 | `async def get_premium_nulls(ts_codes, start_date, end_date) -> List[Tuple[str, str]]` |
| `shared/database/repositories/market/basic/etf_repo.py:525` | 变更 SELECT | `get_etf_adjusted_daily_batch` 返回值新增 `nav_pit`、`premium_rate` 两个键（浮点或 None） |

兼容性：返回值**只增不改**，现有消费方（`data_feed_engine.py:684`、`strategy_manager.py:1399/1547`、3 个脚本）无需改动。

### 4. 策略参数（`cross_market_momentum_strategy.py` `DEFAULT_PARAMS`，`ma_threshold` 之后）

```python
# ETF 折溢价风险门：溢价过高不买入。默认 False = 与引入前逐位等价。
# 机制：跨境 ETF 受额度限制，二级市场价可长期高于净值（2026-11 实测 513100 +25%），
#       溢价回落时持仓者会承受净值之外的第二重亏损。
# 取值范围 0.02~0.30；调小 → 更严（可能把整个全球池挡掉）。
"enable_premium_gate": False,
"premium_max": 0.10,
```

### 5. 策略行为

```python
def _passed_premium_gate(self, m: Dict) -> bool:
    """溢价门：只拦「未持仓的买入」；已持仓不在此杀（出场由均线/风控门负责）。"""
    _p = m.get("premium_rate")
    if _p is None:                      # 无净值 → fail-open，不阻断
        return True
    if m["etf"] in self._holdings:      # 已持仓 → 不在入场门二次杀
        return True
    return float(_p) <= self.premium_max
```

- `metrics` 新增键 `"premium_rate": Optional[float]`（与 `passed_ma` 同级，`:1614` 附近）
- `_apply_filters`（`:1639` 附近）在「均线」之后追加：`("溢价", self._passed_premium_gate, self.enable_premium_gate)`
- 破坏性检查：该门**只影响未持仓标的**，因此不会与 `min_hold_days`、`_exit_pending`、T+1 锁定产生交互

### 6. 错误码

本变更无 HTTP 面。数据侧不新增异常类型；`premium_rate` 缺失一律按 NULL → 策略 fail-open。

## 数据流与依赖

```
[data 同步，同步调用]
Tushare → sync_service._sync_etf_daily (:3332) → EtfDailyRepository → etf_daily(原始列)
        ↓（同一次任务内，同步、幂等）
        _derive_etf_premium：etf_daily × fund_nav(PIT) → UPDATE nav_pit / premium_rate

[策略，同步]
EtfDailyRepository/etf_repo.get_etf_adjusted_daily_batch (:525)
  → data_feed_engine._load_etf_batch (:684) → on_bar → strategy._data_cache[code]["premium_rate"]
  → _score_candidate (:1532) → metrics["premium_rate"]
  → _apply_filters (:1623) → _passed_premium_gate
```

依赖方向：`modules/data → shared/database/repositories → shared/database`；`modules/strategy → shared/`。策略**不直接读** `fund_nav`，不新增跨模块事件。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|:--|:--|:--|:--|
| **A 加列到 `etf_daily`** | 回测/实盘同一条通路；策略零新增 I/O；无 JOIN | 动 DDL（超表） | ✅ |
| B 独立表 `etf_premium_daily` | 与行情表解耦 | 多一张表 + 每次查询多一次 JOIN；策略端仍要新增数据通路；回填与同步多一套状态机 | ❌ 复杂度高于收益 |
| C 策略内实时查 `fund_nav` | 不改 DDL | 回测不可复现（回测引擎不提供该表）；策略层做 DB I/O 违反分层；逐标的 N 次查询 | ❌ |
| D 用底层指数替代（`index_global_daily`） | 信号更干净，可同时解决打分污染 | 只覆盖 11 只中的 7 只；`backtest_engine` 只加载 `etf_daily`/`index_daily`（`:1358-1381`），需新增数据通路；且解决不了 159985/159980 等商品 | ❌ 本次不做，另立 REQ |

## 回滚方案

- **一级（参数）**：`enable_premium_gate=False` 即恢复现状，无需回退代码。判定条件：默认参数回测与 `assets/baseline_trades.csv` 不一致。
- **二级（数据）**：停止 `_derive_etf_premium` 调用即可；两列保持 NULL，不阻断任何现有读取。判定条件：ETF 日线同步耗时增加 > 20%，或派生失败率 > 1%。
- **三级（DDL）**：`ALTER TABLE etf_daily DROP COLUMN premium_rate, DROP COLUMN nav_pit;`——执行前须确认无消费方（`grep -rn "premium_rate" quant_server` 为零）。判定条件：S4 发现该列影响既有查询计划或迁移。
- **时间窗**：任一级触发后当日完成回退，回退后重跑 `check_all.py`。
- **无状态残留**：派生只写两列，不新增表、不新增同步 state；策略侧只有内存字段。
