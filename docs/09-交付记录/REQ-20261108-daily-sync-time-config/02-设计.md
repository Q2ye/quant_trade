# REQ-20261108-daily-sync-time-config 设计

> 阶段 S2 ｜ 前置：`01-需求.md` 已确认 ｜ 退出：契约 + 影响面 + 取舍齐全 ｜ **写法见 `docs/06-标准规范/00-2_S2设计规范.md`**

## 方案概述

在 `config.yaml` 的 `defaults.system` 增加 `daily_sync_time: "19:20"`；`StartupConfig` 读取后放进 `get_system_config()["system"]`；`MainEngine._start_daily_scheduler` 用纯函数 `resolve_daily_sync_time()` 校验 HH:MM，非法值回退 `19:20` 并告警。只改配置来源与校验，不改调度类型/交易日门。

## 契约

| 项 | 内容 |
|:---|:---|
| 入口 | `config.yaml` → `system.daily_sync_time`；`resolve_daily_sync_time(raw) -> str` |
| 输入 | `daily_sync_time`：字符串 `HH:MM`（00:00–23:59），缺省/空/非法均回退 `19:20` |
| 输出 | `EngineConfigEntity.config["system"]["daily_sync_time"]`；`ScheduleJob.schedule_config["time"]` |
| 错误码 | 非法值：`logger.warning` + 回退，不抛异常；无 API 错误码 |
| 兼容性 | 默认 `19:20` 与当前行为一致；不新增 `.env` 键；旧配置缺少该键时回退默认 |

## 数据流与依赖

- 数据流：`config.yaml` → `ConfigManager.get_config("server")` → `StartupConfig._apply_config_data` → `get_system_config()` → `EngineConfigEntity.config` → `MainEngine._start_daily_scheduler` → `ScheduleJob.schedule_config["time"]`。
- 依赖方向：`main.py → core`（启动层）；`core` 不反向 import `main`。
- 复用：沿用 `serve_frontend` / `frontend_dir` 的 `system` 配置读取范式。

## 影响面

| 文件/模块 | 改动 | 风险 |
|:---|:---|:---|
| `quant_server/config.yaml` | `defaults.system` 新增 `daily_sync_time: "19:20"` | 低：新增键，默认值不变 |
| `quant_server/main.py` | `_apply_config_data` 读取；`get_system_config()` 输出 `daily_sync_time` | 中：配置契约多一个字段 |
| `quant_server/core/engines/system/main_engine.py` | 新增 `resolve_daily_sync_time()`；调度器读取配置；日志/注释对齐 | 中：调度器启动路径 |
| `quant_server/tests/test_daily_sync_time_config.py` | 新增：合法/非法/空值单测 | 低 |

- 跨模块影响：`system` 配置多一个键，其他消费者忽略即可。
- 数据影响：无 DDL/数据变更。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|:---|:---|:---|:---|
| A（采纳）`config.yaml` + `StartupConfig` 透传 | 与现有 `system` 配置同源；可随环境覆盖 | 需改 3 个文件 | ✅ |
| B 只读 `.env`（`os.getenv`） | 改动最小 | 不在配置契约里，难发现；`.env` 有写入红线 | ❌ 因可维护性 |
| C 保持硬编码 | 无改动 | 改时间必须发版；三处文案不一致 | ❌ 因问题本身 |

## 回滚方案

- 纯配置/代码变更，无 DDL/数据；回滚 = revert 本 REQ 提交。
- 判定条件：AC-2/AC-3 失败或调度器启动日志时间与配置不符 → 回滚。
- 时间窗：立即。
