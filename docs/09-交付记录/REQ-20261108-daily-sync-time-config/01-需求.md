# REQ-20261108-daily-sync-time-config 需求卡

> 阶段 S1 ｜ 档位 T2 ｜ 起草 2026-11-08 ｜ 确认人 用户 ｜ **写法见 `docs/06-标准规范/00-1_S1需求澄清.md`**

## 问题与证据

- 现象：日终流水线触发时间硬编码在 `core/engines/system/main_engine.py:406` 的 `schedule_config={"time": "19:20"}`；同一函数内日志却写「22:42」，docstring 写「16:00 / 20:00」，三处不一致。
- 证据：`grep -n "19:20\|22:42\|16:00\|20:00" core/engines/system/main_engine.py` 命中 400-413 行；`ScheduleManager` 用 `time_str.split(":")` 解析，非法值会让调度器静默不启动（异常被 `except` 吞成「非致命」）。
- 不做的后果：调整日终时间必须改代码并重新发版；改错格式时调度器不报错、当日流水线不执行。

## 目标

把日终流水线触发时间改为 `config.yaml` 的 `system.daily_sync_time` 配置（HH:MM，默认 `19:20`）；非法值回退默认并告警。

## 范围

- 包含：`config.yaml` 新增 `system.daily_sync_time`；`StartupConfig` 读取并透传到 `get_system_config()`；`MainEngine._start_daily_scheduler` 读取、校验、使用；单测。
- **不包含**：
  - 不改 `ScheduleType.TRADING_DAY` 的交易日门，不改其他任务时间。
  - 不新增 `.env` 键（走 config.yaml）。
  - 不改 `ScheduleManager` 的解析逻辑。

## 验收标准

- AC-1：`cd quant_server && grep -n "daily_sync_time" config.yaml main.py core/engines/system/main_engine.py` → 三处均有命中
- AC-2：`cd quant_server && .venv/Scripts/python.exe -c "from core.engines.system.main_engine import resolve_daily_sync_time as f; print(f('16:30'), f('25:00'), f(None))"` → 输出 `16:30 19:20 19:20`
- AC-3：`cd quant_server && .venv/Scripts/python.exe -m pytest tests/test_daily_sync_time_config.py -q` → passed
- AC-4：`cd quant_server && .venv/Scripts/python.exe -m pytest -q` → 0 failed

## 约束与红线

- 默认值必须保持 `19:20`（不改变当前行为）。
- 非法格式不得让调度器静默不启动；必须回退并打 WARNING。
- 只改 config 契约与调度时间，不碰交易/风控/策略逻辑。

- 未知：无。
