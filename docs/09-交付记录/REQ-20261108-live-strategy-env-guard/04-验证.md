## 未覆盖与风险

- **集成测试是 fake 级，不是真起 dev 进程**：新增测试用 fake repo/session/event 断言「拒绝发生在写库/加载之前」；没有启动完整 dev 服务并插一条 `dev.strategies` running/live 行做端到端演练。若需要，可在 dev 插临时行验证日志「跳过 live 策略恢复」后再删除。
- **API 403 未用真实 live 策略触发**：dev 没有 live 策略；403 分支由 `_result_error_code` + 单元/代码审查保证。
- **`.env` 的 `ENVIRONMENT=production` 残留风险**：若 dev 进程用 `uvicorn ... --factory` 启动且不带 `--mode development`，环境变量仍是 production、数据库也连 public，本门会按 production 放行。**必须用 `python -m quant_server.main --mode development` 启动 dev**；门无法区分「本想 dev 但配置成 production」。
- **其他入口**：`/trigger` 已补门；`scripts/ops/*` 若直接写 `status='running'` 仍可绕过脚本层，本 REQ 覆盖 API / Manager / Service 三个主入口。
- **未知 run_mode**：按 live 处理（production-only），`simulation`/脏值不会在 dev 放行。
- **生产行为**：`public.strategies` 的 1 条 running/live 未改动；production 下 `can_run_live` 恒 True，行为与之前一致。
