# REQ-20261108-live-strategy-env-guard 设计

> 阶段 S2 ｜ 前置：`01-需求.md` 已确认 ｜ 退出：契约 + 影响面 + 取舍齐全 ｜ **写法见 `docs/06-标准规范/00-2_S2设计规范.md`**

## 方案概述

用一个**纯函数环境门** `modules/strategy/utils/env_guard.py` 作为唯一判据，在 live 策略的四个入口统一拦截：
1. `StrategyManager` 启动恢复（`_recover_running_strategies`）；
2. `StrategyManager` 每日驱动（`run_daily_strategies` / `_run_live_strategies`）；
3. `ExecutionService` 手动启动/恢复（写 DB 之前）；
4. API start/resume（把服务层的拒绝映射为 HTTP 403）。

development/test 只拦 `live`，`paper`/`backtest` 行为不变；production 行为不变。**不改任何数据**。

## 契约

| 项 | 内容 |
|:---|:---|
| 环境源 | `os.getenv("ENVIRONMENT", "development").strip().lower()`（与 `session_manager._assert_environment_safety` 同源；`main.py --mode` 会写入该变量） |
| 纯函数 | `is_production_env(env=None) -> bool`；`can_run_live(run_mode, env=None) -> bool`；`should_restore_strategy(run_mode, env=None) -> bool` |
| 判定 | `production` → live 允许；`development`/`test`/`testing` → live 拒绝；`paper`/`backtest` 一律允许 |
| run_mode 归一 | 接受 `RunMode` 枚举、字符串、`None`；`None` 按 `live`（与现有 `getattr(..., 'live')` 一致） |
| 错误码 | `ErrorCode.LIVE_PRODUCTION_ONLY = 1012` |
| 服务层返回 | `start_strategy`/`resume_strategy` 非生产 + live 返回 `{"success": False, "error": "...仅允许在 production...", "error_code": ErrorCode.LIVE_PRODUCTION_ONLY}`，**不创建 run 记录、不写 running、不发事件** |
| API 返回 | start/resume 检测到 `error_code == LIVE_PRODUCTION_ONLY` → `HTTPException(403, detail)`；其他错误保持现有 400/500 |
| Manager 恢复 | `_recover_running_strategies` 对 `run_mode=live` 且非生产：`logger.warning` 并 `continue`；`paper` 仍恢复 |
| Manager 驱动 | `run_daily_strategies` 非生产：`logger.warning` 并 `return []`；`_run_live_strategies` 顶层再兜底一次 |
| 事件入口 | `_on_strategy_start_requested` 对 live 且非生产：告警并 return，不加载实例 |
| 兼容性 | production 行为不变；dev 的 paper/backtest 不变；不改 DB/DDL/前端 |

## 数据流与依赖

- **手动启动**：API → `handlers.start_strategy` → `ExecutionService.start_strategy` → `env_guard.can_run_live` 拒绝 → 返回 `LIVE_PRODUCTION_ONLY` → API 403。**在写 `strategy_runs`/`strategies` 之前拒绝**。
- **手动恢复**：API → `handlers.resume_strategy` → `ExecutionService.resume_strategy` 读取 `strategy.run_mode` → `can_run_live` 拒绝 → 返回错误码 → API 403。
- **重启恢复**：`StrategyManager._on_start` → `_recover_running_strategies` → 逐行 `should_restore_strategy(run_mode)`；非生产 live 跳过。
- **每日驱动**：`run_daily_strategies` → `is_production_env`；非生产直接返回空，不加载 bars、不产生信号。
- **依赖方向**：`modules/strategy/{engines,services}` → `modules/strategy/utils/env_guard.py`，同模块内；`api/` → `modules/strategy/constants.py`（错误码）已有方向，不反向。

## 影响面

| 文件/模块 | 改动 | 风险 |
|:---|:---|:---|
| `quant_server/modules/strategy/utils/env_guard.py`（新建） | 3 个纯函数 + 文档 | 低 |
| `quant_server/modules/strategy/engines/strategy_manager.py` | 恢复/驱动/事件入口加门 | 中：漏一个入口仍可能驱动 live |
| `quant_server/modules/strategy/services/execution_service.py` | start/resume 写 DB 前拒绝 live | 中：拒绝路径不能留下半写状态 |
| `quant_server/modules/strategy/constants.py` | 新增错误码 | 低 |
| `quant_server/api/routers/strategy_router.py` | start/resume 映射 403 | 低 |
| `quant_server/tests/modules/test_strategy/test_live_env_guard.py`（新建） | 纯函数矩阵测试 + 错误码 | 低 |

- **跨模块影响**：仅 strategy 模块与 strategy API；不改 data/trade/risk/account。
- **数据影响**：无；不写 `public`/`dev` 的 `strategies`/`signals`/`positions`。
- **生产影响**：production 下 `can_run_live` 恒 True，行为与现在一致。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|:---|:---|:---|:---|
| A（采纳）纯函数门 + Manager/Service/API 三层 | 唯一判据、可单测；覆盖恢复/驱动/手动/事件 | 需改 5 个文件 | ✅ |
| B 只在 Manager 加门 | 改动少 | API 仍可把 dev 策略写成 running（DB 脏状态），事件/其他入口绕过 | ❌ |
| C 只在 API 加门 | 前端体验直接 | 启动恢复、事件、内部调用仍可驱动 live | ❌ |
| D 依赖 dev schema 为空 | 零代码 | 克隆/手动启动/误连 public 立即失效 | ❌ |
| E 用配置开关 | 可运维 | 默认值/误配风险；多一套状态 | ❌ |

## 回滚方案

- **判定条件**：production 启动后 `can_run_live` 误判为 False，或 paper 策略在 dev 被误拦。
- **动作**：`git revert` 本 REQ commit；无 DDL/数据变更，无需迁移。
- **时间窗**：上线后观察一个交易日；若有异常立即 revert。
- **数据**：本 REQ 不修改任何行情/策略/账户数据；回滚不影响生产 running 策略。

## 与现有设计的关系

- `REQ-20261108-db-env-isolation` 只禁止 dev 的行情同步/派生任务，明确允许 account/strategy 在 dev 运行（写 dev schema）。本 REQ 在该设计上补一条：**strategy 可以在 dev 运行 paper/backtest，但 live 必须 production-only**。
- 当前 `dev.strategies` 为空、`public.strategies` 有 1 条 running/live；本 REQ **不动**这条生产策略。
