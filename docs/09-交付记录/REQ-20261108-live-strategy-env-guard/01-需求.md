# REQ-20261108-live-strategy-env-guard 需求卡

> 阶段 S1 ｜ 档位 T2 ｜ 起草 2026-11-08 ｜ 确认人 用户 ｜ **写法见 `docs/06-标准规范/00-1_S1需求澄清.md`**

## 问题与证据

- **现状事实**：当前 dev schema 里没有 running 策略——`quant_dev` 连接（`search_path=dev, public`）实测 `dev.strategies` 为空；dev 进程日志为 `重启恢复: 没有需要恢复的运行中策略`。唯一 `running/live` 在 `public.strategies`（生产），由 `quant_trade_release` 进程驱动。**所以当前没有 dev 错误信号**。
- **但代码没有硬门，风险真实存在**：
  - `StrategyManager._recover_running_strategies` 查询所有 `status='running'`（`modules/strategy/engines/strategy_manager.py:2242-2247`），**不判断 `ENVIRONMENT`**；
  - `run_daily_strategies`（`:1288-1305`）与 `_run_live_strategies`（`:1735-1759`）驱动 `run_mode=live` 策略，**无环境判断**；
  - `ExecutionService.start_strategy`（`modules/strategy/services/execution_service.py:64-181`）把策略写成 `status=running, run_mode=live`，**无环境判断**；`resume_strategy`（`:434-494`）同样；
  - 因此以下任一情况都会让 dev 产出错误信号：
    1. 有人通过 API 在 dev 启动/恢复一个 `run_mode=live` 策略；
    2. `dev.strategies` 被从 public 克隆/复制了 running 行；
    3. 用 `uvicorn quant_server.api.main:create_app --factory --reload` 启动时没带 `--mode development`，`.env` 的 `ENVIRONMENT=production` 让进程连到 public（最危险，直接写生产 signals）。
- **不做的后果**：dev 可能生成与生产不一致的信号、触发告警/人工误操作；若 dev 误连 public，会直接污染生产 `signals`/`positions`。db-env-isolation 的设计只禁止 dev 行情同步，**未禁止 dev 驱动 live 策略**。

## 目标

给 live 策略加**环境硬门**：
- 只有 `ENVIRONMENT=production` 可以恢复/驱动/启动/恢复 `run_mode=live` 策略；
- development/test 环境保留 `paper`/`backtest` 能力，但 live 一律跳过/拒绝并打 WARNING；
- 不修改 `public` 现有 running 策略，不改任何业务表数据。

## 范围

- **包含**：
  - 新增 `modules/strategy/utils/env_guard.py`：`is_production_env` / `can_run_live` / `should_restore_strategy` 纯函数；
  - `StrategyManager`：`_recover_running_strategies` 跳过非生产的 live 行；`run_daily_strategies` 与 `_run_live_strategies` 非生产直接返回空并告警；
  - `ExecutionService.start_strategy` / `resume_strategy`：非生产 + live 返回 `success=False, error_code=LIVE_PRODUCTION_ONLY`，不写 running/不发事件；
  - `api/routers/strategy_router.py`：start/resume 对 `LIVE_PRODUCTION_ONLY` 返回 HTTP 403；
  - `modules/strategy/constants.py`：新增 `ErrorCode.LIVE_PRODUCTION_ONLY`；
  - 新增 `tests/modules/test_strategy/test_live_env_guard.py`。
- **不包含**：
  - 不改 `public` 的 `strategies` 数据、不停止生产 running 策略；
  - 不改 `dev` schema 结构或种子（当前 `dev.strategies` 为空；本 REQ 用代码硬门兜底）；
  - 不改前端页面（403 由现有错误处理展示）；
  - 不改 data 模块同步、不改 DDL；
  - 不改 paper/backtest 的现有执行路径。

## 约束与红线

- **不得**停止或修改 `public.strategies` 的生产 running 策略；本 REQ 只加代码门。
- 非生产环境的 live 启动/恢复必须**在写 DB 之前**拒绝，不能先写 `status=running` 再回滚。
- `paper`/`backtest` 在 dev 必须保持可用；不得用「dev 全部禁止」的粗粒度方案。
- 环境判定统一用 `os.getenv("ENVIRONMENT", "development")`（与 `session_manager._assert_environment_safety` 同源，`--mode` 已在 `main.py` 写入该环境变量）。
- API 拒绝必须是 403，不得落到 500。

## 假设与未知

- **假设**：`run_mode` 的取值是 `live`/`paper`/`backtest`（`modules/strategy/constants.py` 的 `RunMode`）；`simulation` 若存在按 paper 处理。实现前以枚举为准。
- **假设**：`StrategyManager` 与 `ExecutionService` 可 import `modules/strategy/utils/env_guard.py`，不构成循环依赖。
- **未知**：是否需要在前端隐藏 dev 的 live 启动按钮；本 REQ 先做后端 403，前端现有错误提示即可。
- **未知**：是否有其他入口直接写 `status='running'`（如脚本 `scripts/ops/*`）；本 REQ 覆盖 API/Manager/Service 三个主入口，脚本入口后续按需补。
