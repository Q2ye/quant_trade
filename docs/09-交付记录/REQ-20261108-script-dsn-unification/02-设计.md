# REQ-20261108-script-dsn-unification 设计

> 阶段 S2 ｜ 前置：`01-需求.md` 已确认 ｜ 退出：契约 + 影响面 + 取舍齐全 ｜ **写法见 `docs/06-标准规范/00-2_S2设计规范.md`**

## 方案概述

新增 `scripts/_db_env.py`，用 `shared.config.config_manager.resolve_database_env` 统一解析 DSN；各脚本通过 `sys.path` 引入该模块，替换模块级 `DB = {...}` / `_get_db_config()` / URL 拼接。默认按 `ENVIRONMENT` 解析（当前 `.env=production` → `quant_prod` / `quant_signals`），拒绝 `postgres` 超管。业务逻辑、回填范围、回测口径均不变。

## 契约

| 项 | 内容 |
|:---|:---|
| 入口 | `scripts/_db_env.py`：`db_kwargs(env=None) -> dict`、`db_url(env=None) -> str` |
| 输入 | `env`：`None`（按 `ENVIRONMENT`）/ `"dev"`（`DB_DEV_*`）/ `"prod"`（`PROD_DB_*`）；其余值报错 |
| 输出 | `db_kwargs`：`{"host","port","user","password","database"}`；`db_url`：`postgresql+asyncpg://user:pass@host:port/db` |
| 错误码 | 缺生产配置 / `user == "postgres"` → `SystemExit(1)`；非法 env → `SystemExit(1)` |
| 兼容性 | 脚本 CLI 参数不变；`backfill_sw_member_history.py` 保留 `--database`，默认值改为统一配置；无 DDL/表结构变更 |

## 数据流与依赖

- 数据流：脚本 → `sys.path.insert(0, scripts/)` → `_db_env.db_kwargs/db_url` → `shared.config.resolve_database_env` → psycopg2/asyncpg/SQLAlchemy。
- 依赖方向：`scripts → shared.config`（脚本层，不违反 `modules → shared → core`）。
- 复用：`shared.config.config_manager.resolve_database_env`（REQ-20261108-db-env-isolation 已实现），不重复造解析逻辑。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|:---|:---|:---|:---|
| A（采纳）`scripts/_db_env.py` 共享 helper | 一处维护；18 个脚本一致；复用已测的 `resolve_database_env` | 需每个脚本加 3 行 `sys.path` 引入 | ✅ |
| B 每个脚本内联解析 | 无新文件 | 18 份重复逻辑，后续再漂移 | ❌ 因维护成本 |
| C 保留硬编码 | 无改动 | 违反安全红线；dev 库退役后全失败 | ❌ 因问题本身 |

## 回滚方案

- 纯代码变更，无 DDL/数据迁移；回滚 = `git revert` 本 REQ 的提交。
- 判定条件：AC-1/AC-3 失败或脚本 `--help` 触发 DB 连接 → 回滚。
- 时间窗：立即。
