# REQ-20261108-sync-tiering 设计

> 阶段 S2 ｜ 前置：`01-需求.md` 已确认 ｜ 退出：契约 + 影响面 + 取舍齐全 ｜ **写法见 `docs/06-标准规范/00-2_S2设计规范.md`**

## 方案概述

把日终同步拆成两条独立的调度链：
- **19:20**：只保留策略执行/门禁/派生任务真正需要的 **7 类**；
- **00:00**：新增 `night_data_sync` 任务，用 `CRON` 每天触发，任务内先判断「前一天是否交易日」，再同步其余 **102 类**。

两条链共用 `DataSyncService.sync_market_data` 与同一套 repository/取数逻辑，只改「同步哪些类型、什么时候触发」，不改任何表的取数方法。

## 契约

| 项 | 内容 |
|:---|:---|
| 配置键 | `system.night_sync_time`（HH:MM，默认 `00:00`）、`system.night_sync_enabled`（bool，默认 `true`） |
| 19:20 清单 | `DAILY_STRATEGY_TYPES = (DAILY_QUOTES, ADJ_FACTOR, DAILY_BASIC, DAILY_LIMIT, ETF_DAILY, FUND_ADJ_FACTOR, INDEX_DAILY)` |
| 00:00 清单 | `NIGHT_SYNC_TYPES = 全部 DataType 去掉 7 个日终 + 4 个排除（MINUTE/TICK/ETF_MINUTE/FINANCIAL_DATA）`，共 102 |
| 19:20 job | `daily_data_sync`，`ScheduleType.TRADING_DAY`，`schedule_config={"time": daily_sync_time}`（不变） |
| 00:00 job | `night_data_sync`，`ScheduleType.CRON`，`schedule_config={"cron": "<MM> <HH> * * *"}` |
| 夜班守卫 | 按 Asia/Shanghai 取 `prev_day = today - 1 day`；`prev_day` 为周末 → 跳过；`prev_day` 是 A 股节假日但为工作日 → 仍跑（跨市场数据）；日历查询失败/无记录 → 退化为工作日并告警 |
| 夜班滚动窗口 | `by_month`/`frequency=monthly` 回看 62 天；`by_quarter` 回看 200 天；`by_range`/`by_range_daily` 回看 7 天；其余只查 `prev_day` |
| 注册 API | `MainEngine.register_night_task(name, fn, order=0)`；`fn(prev_day) -> None` |
| 夜间任务 | `modules/data/__init__.py::_task_sync_night(prev_day)`，遍历 `NIGHT_SYNC_TYPES`，每类型独立 session + try/except |
| 兼容性 | 19:20 的 job id、时间、交易日门、pre_gate/post_gate 顺序不变；只缩小 `_daily_types` |

### 19:20 七类依据

| 类型 | 表 | 消费方 |
|:---|:---|:---|
| `DAILY_QUOTES` | `stock_daily` | 数据完整性门、`market_state`、高波动（stopped）数据源 |
| `ADJ_FACTOR` | `stock_adj_factor` | 股票复权数据源（高波动恢复时必需） |
| `DAILY_BASIC` | `stock_daily_basic` | 数据完整性门、`market_state`、微盘（draft） |
| `DAILY_LIMIT` | `stock_daily_limit` | `market_state` |
| `ETF_DAILY` | `etf_daily` | 当前 running 跨市场策略、ETF 因子、数据完整性门 |
| `FUND_ADJ_FACTOR` | `fund_adj_factor` | ETF 复权价格（跨市场策略） |
| `INDEX_DAILY` | `index_daily` | 跨市场 regime、`market_state`、恐慌（draft）、数据完整性门 |

### 00:00 一百零二类构成

| 组 | 数量 | 说明 |
|:---|--:|:---|
| 56 张新增表 | 56 | 从 `DATA_CONTRACTS` 的 key 派生，避免手写漏项 |
| 现有非日终类型 | 46 | 财务、因子（含 `STK_FACTOR`/`STK_FACTOR_PRO`/`IDX_FACTOR_PRO`）、目录、治理/股东、周月线、宏观、事件 |
| 合计 | 102 | 113 个 DataType − 7 个 19:20 − 4 个排除 |

> **不纳入夜班的 4 个**：`MINUTE_QUOTES`、`TICK_QUOTES`、`ETF_MINUTE`（分钟/tick，按既有决定不做）、`FINANCIAL_DATA`（三表合并旧类型，无独立同步方法；用 `FINANCIAL_INCOME`/`FINANCIAL_BALANCE`/`FINANCIAL_CASHFLOW` 分别同步）。

## 数据流与依赖

- **19:20**：`ScheduleManager(TRADING_DAY)` → `_run_daily_pipeline` → `_task_sync_daily` → `sync_market_data(7 类)` → `market_state` → `etf_factor` → 数据完整性门 → post_gate 策略。
- **00:00**：`ScheduleManager(CRON 0 0 * * *)` → `_night_sync_job` → 前一交易日守卫 → `_run_night_pipeline(prev_day)` → `_task_sync_night(prev_day)` → 逐类型 `sync_market_data`（102 类）→ 写 `data_sync_tasks`/日志。
- **依赖方向**：`main_engine`（core）不 import `modules.data`；data 模块在 initialize 时调用 `main_engine.register_night_task`，与现有 `register_daily_task` 同为依赖反转。
- **复用**：`DataSyncService`、`_sync_method_map`、`sync_market_data` 的 task/event/persistence 链路全部复用；不新造同步执行器。
- **夜班与日终互斥**：00:00 在 19:20 后约 4h40m，正常不重叠；夜间任务不触发数据完整性门与策略。

## 影响面

| 文件/模块 | 改动 | 风险 |
|:---|:---|:---|
| `quant_server/modules/data/sync_schedule.py`（新建） | 两个类型清单 + 依赖注释 | 低：纯常量 |
| `quant_server/modules/data/__init__.py` | 19:20 改 7 类；新增 `_task_sync_night` 并注册 | 中：漏类会导致策略缺数据或夜间漏同步 |
| `quant_server/core/engines/system/main_engine.py` | `hhmm_to_cron`、`register_night_task`、`_run_night_pipeline`、`_night_sync_job`、第二个 ScheduleJob | 高：调度器/日终时序；错误会让夜班不跑或误跑 |
| `quant_server/main.py` | `StartupConfig` 读取 `night_sync_time`/`night_sync_enabled` 并暴露到 `get_system_config` | 中：配置契约 |
| `quant_server/shared/config/config_manager.py` | SystemConfig 字段 + `get('SYSTEM.night_sync_time')` 映射 | 中：配置默认值 |
| `quant_server/config.yaml` | `system.night_sync_time: "00:00"`、`system.night_sync_enabled: true` | 低：可回滚 |
| `quant_server/tests/modules/test_data/test_sync_schedule.py`（新建） | 7/102/无交集/并集断言 | 低 |
| `quant_server/tests/test_daily_sync_time_config.py` | 夜班时间/cron 断言 | 低 |
| `docs/02-功能设计/市场模块/日频数据底座补全-设计文档.md` | §5.3 改为两层清单 | 低：文档 |

- **跨模块影响**：只新增 `register_night_task` 一个 core→module 反向注册点；不影响事件/交易/风控/账户。
- **数据影响**：19:20 从 39 类降到 7 类；00:00 新增 102 类；不新增/删除表。
- **性能影响**：19:20 明显缩短；00:00 新增约 1.5–2h 后台负载（含重表）。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|:---|:---|:---|:---|
| A（采纳）两条独立 ScheduleJob + 前一交易日守卫 | 19:20 轻量；00:00 可独立启停；周六也能跑周五数据 | 新增一个 core 注册 API | ✅ |
| B 00:00 用 `TRADING_DAY` | 复用现有类型 | 它按「当天」判断，周六 00:00 会跳过周五数据；错误 | ❌ |
| C 把夜班写进 `_run_daily_pipeline` | 改动少 | 夜班在 19:20 的同一流水线里，仍会拖住策略驱动；且无法独立调度 | ❌ |
| D 在 data 模块自建 APScheduler | 不动 core | 与 MainEngine 的 ScheduleManager 两套调度，冲突 | ❌ |

## 回滚方案

- **判定条件**：00:00 任务导致生产库锁/磁盘告警，或 19:20 因清单缩减出现策略缺数据。
- **动作 1（快速停夜班）**：`config.yaml` 设 `system.night_sync_enabled: false` → 重启后不注册 `night_data_sync`；19:20 不受影响。
- **动作 2（恢复 19:20）**：把 `DAILY_STRATEGY_TYPES` 恢复为原 39 类（或 revert 本 REQ 的 commit）。
- **动作 3（完全回滚）**：`git revert` 本 REQ commit；无 DDL/数据变更，无需迁移。
- **时间窗**：夜班首晚观察；若超时/失败，次日配置开关关闭。
