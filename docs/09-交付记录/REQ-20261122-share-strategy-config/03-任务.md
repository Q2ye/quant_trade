## 偏差记录

### 2026-11-22 · 共享范围 3 → 6 张表（外键链逼出）

**发现**：`dev` schema 的表**有外键**（我先前"dev 无外键"的判断是查询写法错误——`regclass` 在 search_path 下省略 schema 前缀，`like 'dev.%'` 全部漏掉）。
`dev.strategy_versions` / `dev.portfolio_strategies` 的外键指向 `dev.strategies`（改名前的那张），新建策略时插入版本行 → 外键失败。

**处置**（追加共享，均改名不删）：
| 表 | 原因 |
|:--|:--|
| `strategy_versions` | 新建策略写版本，FK → strategies |
| `portfolio_strategies` | 组合成员关系，FK → strategies |
| `sys_users` | `strategies.user_id` FK → sys_users，dev 用户不在 public |

**GRANT**：`quant_dev` 获得 `public.strategies / strategy_parameters / strategy_templates / strategy_versions / portfolio_strategies` 的 SELECT+INSERT+UPDATE+DELETE（`sys_users` 仅 SELECT）。

**历史数据归属**：dev 的 `accounts`(1) / `backtest_tasks`(17) / `account_daily_performance`(5) 的 `user_id` 由 `dev00000` 改为 `superAdmin`（`cd2f4a88`）。

**新增风险（已告知用户并接受）**：配置表写权限从"物理禁写"降为"服务层守卫"，绕过 API 的 SQL 可直改生产配置。

**回滚**：对 6 张 `*_devbak_20261122` 反向改名 + 回收 GRANT 即可。
