# REQ-20261122-share-strategy-config 设计

> 阶段 S2 ｜ 档位 T2 ｜ 起草 2026-11-22
> 上游：`01-需求.md`（AC-1~AC-7）

## 方案概述

**不改代码路由、不改 GRANT、不改 search_path**——只把 `dev` schema 里的三张**配置表**改名让位，
使 `search_path=dev,public` 的未限定表名自然回落到 `public`。再在服务层加两道写守卫防误伤生产。

```
改前：dev.strategies(5) 遮蔽 public.strategies(51) → dev 只见 5 条
改后：dev.strategies 改名为 strategies_devbak_20261122
      → 未限定 "strategies" 回落到 public → 两环境看到同一份 51 条
```

## 契约

### 1. 迁移（DDL 级，只在 dev schema）

```sql
ALTER TABLE dev.strategies            RENAME TO strategies_devbak_20261122;
ALTER TABLE dev.strategy_parameters   RENAME TO strategy_parameters_devbak_20261122;
ALTER TABLE dev.strategy_templates    RENAME TO strategy_templates_devbak_20261122;
```

- **不 DROP**：可 `ALTER ... RENAME TO ...` 逆恢复；
- 迁移前先导出三表（`COPY (SELECT ...)`，避开超表导出坑）到 `assets/`；
- 回滚 = 反向改名。

### 2. 写守卫（服务层）

| 守卫 | 位置 | 规则 |
|:--|:--|:--|
| W1 保护在跑实例 | `StrategyService.update_strategy` / `delete_strategy` / 启停 | `ENVIRONMENT=development` 且目标行 `status='running'` 或 `run_mode='live'` → `HTTP 409` |
| W2 强制 dev 语义 | `StrategyService.create_strategy` | `ENVIRONMENT=development` 时强制 `status='draft'`、`run_mode='backtest'`（忽略请求值并 `logger.info` 记录被覆盖的字段） |

实现：新增模块级判断 `_is_dev()`（读 `settings.ENVIRONMENT`），守卫集中在 service 层，router 不改逻辑只透传异常。

### 3. 错误码

| 场景 | 码 |
|:--|:--|
| dev 改 running/live 策略 | **409**（`detail` 说明"生产在跑实例不可在开发环境修改"） |
| dev 删 running/live 策略 | 409 |
| dev 新建时被强制降级 | 200（响应体回显实际落库的 status/run_mode） |
| 生产环境 | 不变（原有 404/409 逻辑） |

## 数据流与依赖

```
dev 进程（quant_dev, search_path=dev,public）
  ├─ strategies / strategy_parameters / strategy_templates → 回落 public（共享）
  └─ backtest_* / accounts / positions / orders / trades / signals / strategy_runs / 绩效 → dev（隔离）

写路径：router → StrategyService（守卫）→ Repository → search_path 解析 → public
```

依赖方向不变。

## 影响面

| 文件 | 变更 | 风险 |
|:--|:--|:--|
| `dev` schema（DB） | 3 张表改名备份 | **高**（结构变更） |
| `quant_server/modules/strategy/services/strategy_service.py` | 两道守卫 | 中（写路径） |
| `quant_server/tests/modules/test_strategy/test_shared_strategy_config.py` | 新建 | 低 |
| `quant_server/scripts/_diag/_verify_dev_reads_prod_params.py` | 新建（验收脚本） | 低 |
| 文档 | 隔离 REQ 的边界说明需同步（3 表移出隔离范围） | 低 |

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|:--|:--|:--|:--|
| **A 改名让位 + 写守卫** | 零代码路由改动；可逆；search_path 天然生效 | 需 DDL；dev 的 draft 会进生产列表 | ✅ |
| B 代码里对 3 表显式查 public | 不动 dev 表 | 要改多个 Repository + 所有未限定调用点，易漏 | ❌ |
| C 把 search_path 改成 public,dev | 一行配置 | **dev 的回测/账户写入会落到 public**（灾难） | ❌ |
| D 双向同步/复制 | 两环境各自独立 | 双写不一致、维护成本高 | ❌ |

## 回滚方案

1. **代码**：`git revert`（守卫与脚本）。
2. **结构**：反向改名——
   ```sql
   ALTER TABLE dev.strategies_devbak_20261122 RENAME TO strategies;
   -- 其余两张同理
   ```
3. **判定条件**：生产列表出现 dev 的 draft 且无法按状态筛选 / dev 写入命中 public 的回测表 / `check_all.py` 红。
4. **时间窗**：任一条件触发即当日回退。
