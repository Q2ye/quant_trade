# REQ-20261122-dev-list-prod-strategies 设计

> 阶段 S2 ｜ 档位 T1 ｜ 起草 2026-11-22
> 上游：`01-需求.md`（AC-1~AC-5）

## 方案概述

只在**列表读路径**上，为 development 环境额外并入 `public.strategies`（只读、带标记）。
写路径完全不改，靠"生产行在 dev 不存在"这一事实天然隔离；再加一道 409 守卫防误操作。

## 契约

### 1. 列表响应新增字段

| 字段 | 类型 | 语义 |
|:--|:--|:--|
| `is_prod_reference` | bool | `True` = 来自 `public.strategies`（只读参考）；dev 自己的行与生产环境下的行均为 `False` |

### 2. 列表查询（`StrategyService.get_strategy_list`）

```
if ENVIRONMENT == development:
    dev_rows   = SELECT * FROM strategies WHERE <filters>        -- 解析到 dev.strategies
    prod_rows  = SELECT * FROM public.strategies WHERE <filters> -- 显式限定，只读
    merged     = prod_rows + dev_rows   （按 id 去重，dev 优先）
    total      = count(dev) + count(public)
else:
    merged     = SELECT * FROM strategies WHERE <filters>        -- 与现状逐字一致
    total      = count(...)
```

- 分页：对合并后的 id 列表分页（先合并再切片），避免两边分页错位；
- 排序：`created_at DESC` 统一排序（与现有行为一致）；
- 去重：理论上不会有同 id（dev 行由 dev 生成），仍按 id 去重、dev 优先。

### 3. 写路径守卫

在 `PUT/DELETE/POST /strategy/{id}/*` 的入口增加：

```
if ENVIRONMENT == development and id ∈ public.strategies:
    raise HTTPException(409, "生产策略在开发环境为只读参考，不可修改")
```

实现位置：`StrategyService` 的更新/删除方法前置检查（一处集中，避免散落）。

### 4. 错误码

| 场景 | 码 |
|:--|:--|
| dev 修改生产策略 | **409**（原为 200/404，会静默无效） |
| 生产策略不存在 | 404（不变） |
| public 查询失败 | 降级为只返回 dev 行 + `logger.warning`（不阻断列表） |

## 数据流与依赖

```
GET /quantTrade/strategy
  → strategy_router.get_strategies_api（同步依赖注入）
  → StrategyService.get_strategy_list（异步）
      ├─ development: dev 查询（search_path）+ public 显式查询 → 合并
      └─ production : 单查询（与现状一致）
  → Repository（StrategyRepository，同一模型，SQL 加表前缀）
```

依赖方向不变：`api → modules/strategy → shared/repositories`。不新增跨模块依赖。

## 影响面

| 文件 | 变更 | 风险 |
|:--|:--|:--|
| `quant_server/modules/strategy/services/strategy_service.py` | 列表合并 + 写守卫 | 中（列表主路径） |
| `quant_server/api/routers/strategy_router.py` | 响应模型加 `is_prod_reference` | 低 |
| `quant_server/shared/database/repositories/strategy/strategy_repo.py` | 新增按 schema 限定的查询方法 | 中（Repository 单源） |
| `quant_server/tests/modules/test_strategy/test_strategy_list_dev_prod.py` | 新建 | 低 |
| 前端 | **不改**（本轮只返回字段，UI 不识别也不影响正确性） | 低 |

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|:--|:--|:--|:--|
| **A 显式 public 查询 + 合并** | 不改 GRANT/search_path；生产零变化 | Repository 出现一处 schema 限定，破坏"全限定名统一"惯例 | ✅ |
| B dev 建视图指向 public | 无需改代码 | 视图不可写，与"dev 写入落 dev"冲突 | ❌ |
| C 改 search_path 顺序为 public,dev | 一处配置搞定 | **dev 写入会落到 public**（灾难），直接违反隔离 | ❌ |
| D 前端加环境切换查询两个后端 | 不改后端 | 需要跨环境 API 访问（生产未开放给 dev 前端） | ❌ |

## 回滚方案

- 代码回滚：`git revert`；无 DDL、无数据写入，无状态残留。
- 行为回滚：把 `ENVIRONMENT` 判断去掉即恢复现状（也可加开关 `enable_dev_prod_strategy_ref`，默认关闭）。
- 判定条件：生产列表出现 `is_prod_reference: true` 行 / dev 侧出现写 public 的语句 / `check_all.py` 红。
