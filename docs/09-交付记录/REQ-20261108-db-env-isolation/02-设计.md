# REQ-20261108-db-env-isolation 设计

> 阶段 S2 ｜ 前置：`01-需求.md` 已确认 ｜ 退出：契约 + 影响面 + 取舍齐全 ｜ **写法见 `docs/06-标准规范/00-2_S2设计规范.md`**

## 方案概述

一个数据库 `quant_signals`，两个 schema：`public` 存行情 + 生产应用状态，`dev` 存开发应用状态。两个非超管角色：`quant_prod`（public 全量读写，含日终同步）与 `quant_dev`（public 只读、dev 读写）。应用通过角色级 `search_path` 自动路由，不改 224 个 Repository 调用点。关键取舍：用 schema 隔离替代第二份数据库，用角色隔离替代应用层多环境分支。

## 契约

| 项 | 内容 |
|:---|:---|
| 入口 | ① `shared.config.config_manager.Settings.DATABASE` 按 `ENVIRONMENT` 解析；② `shared.database.session.session_manager.get_session_manager()` 初始化时执行安全断言；③ `scripts/ops/init_dev_schema.py` / `sync_dev_schema.py` / `grant_roles.py` / `verify_env_isolation.py`；④ 3 个账户脚本新增 `--env dev\|prod` |
| 输入 | `.env`：`ENVIRONMENT`、`DB_DEV_HOST/PORT/USER/PASSWORD/NAME`、`PROD_DB_HOST/PORT/USER/PASSWORD/NAME`（已有键，补值）；可选 `DB_RO_*`。脚本输入：`DEV_APP_TABLES`（74 张）与 `MARKET_TABLES`（61 张）清单（脚本按「public 全部表 − MARKET_TABLES」动态推导）；`--dry-run` / `--apply` / `--recreate` |
| 输出 | PostgreSQL 角色与授权、`dev` schema 与 74 张表、启动断言日志、脚本退出码。断言失败抛 `RuntimeError` 并阻止应用启动 |
| 错误码 | CLI：`0` 成功、`1` 失败（含安全断言失败）；应用启动：`RuntimeError`（消息含 `current_user` / `search_path` / `current_database` / 期望值） |
| 兼容性 | production 行为不变（`quant_prod` 对 public 全量读写）；development 写入从 `quant_signals_dev` 改为 `quant_signals.dev`；3 个账户脚本接口增加必填 `--env`；不改 public DDL、不改 API 路由 |

## 数据流与依赖

- 数据流：
  - 应用启动：`main.py` → `StartupConfig` → `settings.DATABASE`（按 `ENVIRONMENT`）→ `SessionManager` → async engine → DB。
  - 请求/策略/交易：`modules/*` → `shared/database/repositories`（同步）→ `public`（prod）或 `dev`（dev）。
  - 日终同步：`modules/data/__init__.py` → `register_daily_task`（**仅 production 注册**）→ `DataSyncService` → `public`。
  - 开发写入：dev 进程 → `quant_dev` → `search_path=dev, public` → `dev.strategies` / `dev.backtest_*` / `dev.accounts`。
- 依赖方向：`modules → shared → core`，未反向；REQ 不新增模块间直接 import。
- 复用：沿用 `shared/config/config_manager.py` 已有的 `DB_DEV_*` / `PROD_DB_*` 解析；沿用 `shared/database/session/session_manager.py` 的 `get_session_manager()`；不新建连接池。

## 影响面

| 文件/模块 | 改动 | 风险 |
|:---|:---|:---|
| `shared/database/session/session_manager.py` | 新增 `assert_environment_safety()`：启动时校验 `current_user` / `search_path` / `current_database` / `has_table_privilege('public.accounts','INSERT')` | 高：所有连接都经过 |
| `shared/config/config_manager.py` | 补 `DB_RO_*` 可选解析；dev 缺省库名改 `quant_signals` | 中：配置契约 |
| `modules/data/__init__.py` | `register_daily_task` 增加 `ENVIRONMENT == production` 守卫，dev 不注册 `sync_daily`/`coverage_validate`/`market_state_update`/`etf_factor` | 高：日终同步 |
| `modules/data/services/market_state_classifier.py` | 删除 `postgres/123456/quant_signals_dev` 回退，统一走 `settings.DATABASE` | 中：市场状态派生 |
| `modules/strategy/services/training_service.py` | 删除 `quant_signals_dev` 默认值与 `DB_*` 直读，统一走 `settings.DATABASE` | 中：模型训练 |
| `scripts/ops/merge_accounts.py` | 去硬编码 DSN；加 `--env`；加 `current_user != postgres` 断言 | 高：账户余额 |
| `scripts/ops/setup_composite.py` | 同上；移除硬编码策略 ID | 高：组合/账户 |
| `scripts/ops/add_strategy_to_composite.py` | 同上 | 高：组合/账户 |
| `scripts/ops/init_dev_schema.py` | 新增：建 `dev` schema、克隆 74 张应用表、显式补建 FK（应用域→dev / 市场→public）、重建触发器与超表、种子 dev 用户/账户/参考数据 | 中：一次初始化 |
| `scripts/ops/sync_dev_schema.py` | 新增：比对 public 与 dev 的列/类型，默认 dry-run | 中：结构漂移 |
| `scripts/ops/grant_roles.py` | 新增：按 `MARKET_TABLES` / `DEV_APP_TABLES` 生成授权 SQL，默认 dry-run | 高：权限 |
| `scripts/ops/verify_env_isolation.py` | 新增：跑 AC-1~AC-4 的 SQL 断言 | 低：只读 |
| `.env` | 补 `DB_DEV_*`、可选 `DB_RO_*`；移除应用 `postgres` DSN | 高：不提交 git |
| `docs/sql/create_table.sql` | 不改 | 无 |
| `quant_server/tests/test_env_config.py` | 新增：单测 `ENVIRONMENT` 到 DSN 的解析逻辑（不连真库） | 低 |

> 口径：dev 只禁止**行情同步/派生**任务（data 模块 4 个）；account/strategy/system 的日终任务允许在 dev 运行（写 dev schema，属开发工作流）。

- 跨模块影响：account / strategy / trade / backtest / data 均通过 `get_session_manager()` 继承角色；无事件契约变更。
- 数据影响：不改 public DDL；`dev` schema 为运行时新建；`quant_signals_dev` 在 REQ-B 前保持不动。
- 幂等与锁：`init_dev_schema.py` 默认 `IF NOT EXISTS`；`--recreate` 才 `DROP SCHEMA dev CASCADE`。`CREATE TABLE ... (LIKE ...)` 对 public 取 ACCESS SHARE 锁，建议在非日终窗口执行。
- 数据五门：本 REQ 不写行情/因子，不涉及停牌、缺失、回填；相关门禁仍由 data 模块负责。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|:---|:---|:---|:---|
| A（采纳）dev schema + 角色 search_path | 一个库、一份行情；零 Repository 改动；dev 写入隔离 | 需克隆 74 张应用表并重建触发器/超表；依赖 `search_path` 断言 | ✅ |
| B 独立 dev 库 + FDW 读 prod | 物理隔离更彻底 | FDW 跨库回测百万行慢；61 张外部表维护成本高 | ❌ 因回测性能与运维成本 |
| C 同表 + `env` 列 / RLS | 单 schema，细粒度 | 50+ 表加列、所有查询加过滤；漏一处即污染生产 | ❌ 因改动面与泄露风险 |
| D 数据微服务 | 部署边界清晰 | 224 个文件直连仓储；回测需批量数据；不解决“一份数据” | ❌ 因重构成本高于收益 |
| E 维持两库双同步 | 无改动 | 数据漂移、双份存储、结论不可迁移（现状） | ❌ 因问题本身 |

## 回滚方案

> T2 必填：回退步骤 + 判定条件 + 时间窗。

- **Phase 0（角色/配置/脚本）**：把 `.env` 的 `DB_DEV_*` / `PROD_DB_*` 改回原值，`DROP ROLE quant_dev`（可选），应用重启即恢复。数据未动，时间窗：立即。
- **Phase 1（dev schema）**：`DROP SCHEMA dev CASCADE`；dev 的 DSN 改回原值。`public` 未改动，时间窗：1 个工作日内。
- **判定条件**：AC-4 失败（`quant_prod` 无法写 `public.accounts` 或 `public.stock_daily`）→ 立即回滚 Phase 0；prod 启动断言失败 → 先保留旧 DSN 并排查，不得把 `postgres` 长期留在应用配置。
- **无 DDL 变更**：本 REQ 不改 `public` 表结构，不存在数据迁移回滚。
- **超表注意**：`DROP SCHEMA dev CASCADE` 会删除 dev 的 `signals`/`account_daily_performance`/`backtest_equity_curves`/`risk_events`/`strategy_daily_performance`；回滚前先 `pg_dump --schema=dev` 备份实验数据（若需要）。
