# REQ-20261108-db-env-isolation 需求卡

> 阶段 S1 ｜ 档位 T2 ｜ 起草 2026-11-08 ｜ 确认人 用户 ｜ **写法见 `docs/06-标准规范/00-1_S1需求澄清.md`**

## 问题与证据

- 现象：dev 与 prod 各存一份行情；dev 停在 2026-09-18，prod 到 2026-11-06；dev 有 `stock_limit_list`，prod 没有；两个环境的应用 DSN 都用 `postgres` 超管。
- 证据：
  - `SELECT max(trade_date) FROM stock_daily`：dev = `2026-09-18`，prod = `2026-11-06`。
  - `pg_tables` 对比：dev 136 张、prod 134 张；prod 缺 `stock_limit_list`。
  - `.env`：`DB_USER=postgres`、`PROD_DB_USER=postgres`。
  - 硬编码 DSN：`scripts/ops/merge_accounts.py:20-21`、`scripts/ops/setup_composite.py:19-22`、`scripts/ops/add_strategy_to_composite.py:23-25`；`modules/data/services/market_state_classifier.py:39-43`（回退默认值）；`modules/strategy/services/training_service.py:40`（默认 `quant_signals_dev`）。
  - 另有一批 `scripts/backtest/*`、`scripts/data/backfill_*` 硬编码 `postgres` / `123456` / `quant_signals_dev`（如 `backtest_etf_bottom.py:22`、`backfill_above_ma.py:35`、`backfill_top100_factors.py:21`），列入 REQ-C，不在本 REQ。
- 不做的后果：dev 可写生产账户与策略；两份数据继续漂移；回填要做两遍；数据体检结论不可迁移到生产。

## 目标

让 dev 与 prod 共用一份 prod 行情数据，同时把 dev 的策略/回测/账户写入隔离到 `dev` schema，prod 的运行、账户修改与日终同步不受影响。

## 范围

- 包含：PostgreSQL 角色（`quant_prod` / `quant_dev`，可选 `quant_ro`）、`dev` schema 初始化、`.env` 与配置切换、**硬编码 DSN 治理（3 个账户脚本 + `market_state_classifier` + `training_service`）**、启动断言、schema 漂移检查、dev 日终任务禁用。
- **不包含**：
  - 不迁移 dev 的 Tushare 因子历史（已确认：行情/因子以 prod 为准）。
  - 不退役 `quant_signals_dev`（另开 REQ-B）。
  - 不统一 `scripts/backtest/*` 与 `scripts/data/backfill_*` 的硬编码 DSN（另开 REQ-C；它们当前指向旧 dev 库，不触及 prod）。
  - 不改策略代码、交易执行逻辑、回测口径。
  - 不做 dev→prod 策略提升工作流（另开 REQ）。
  - 不拆微服务。

## 验收标准

> 每条必须「操作 → 期望」。写不成命令或明确操作的，不许进 S2。

- AC-1：`psql -h localhost -U quant_dev -d quant_signals -tAc "SELECT current_user, current_setting('search_path')"` → 输出 `quant_dev|dev, public`
- AC-2：`psql -h localhost -U quant_dev -d quant_signals -c "UPDATE public.accounts SET updated_at=updated_at"` → 报错 `ERROR: permission denied for table accounts`，且退出码非 0
- AC-3：`psql -h localhost -U quant_dev -d quant_signals -c "INSERT INTO dev.strategies (id,name,user_id,class_name,module_path,status) VALUES ('ac-test-strategy','AC test','dev00000-0000-0000-0000-000000000001','AcTest','ac/test.py','draft')"` → 输出 `INSERT 0 1`；随后 `psql -h localhost -U quant_prod -d quant_signals -tAc "SELECT count(*) FROM public.strategies WHERE id='ac-test-strategy'"` → 输出 `0`；`psql -h localhost -U quant_dev -d quant_signals -tAc "SELECT count(*) FROM dev.strategies WHERE id='ac-test-strategy'"` → 输出 `1`
- AC-4：`psql -h localhost -U quant_prod -d quant_signals -tAc "SELECT current_user, has_table_privilege(current_user,'public.accounts','UPDATE'), has_table_privilege(current_user,'public.stock_daily','INSERT')"` → 输出 `quant_prod|t|t`
- AC-5：`cd quant_server && .venv/Scripts/python.exe scripts/quality/check_delivery.py check` → 输出 `PASS`；`cd quant_server && .venv/Scripts/python.exe -m pytest` → 输出 `0 failed`

## 约束与红线

- 依赖方向 `modules → shared → core`，不得反向。
- 不改 `docs/sql/create_table.sql` 的现有表结构；本 REQ 不新增业务表。

- dev 的 `factor_definitions` 与 `trade_fees` 允许写（已确认）。
