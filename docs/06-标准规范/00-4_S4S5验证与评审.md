# S4 验证 / S5 评审 检查指南

> 配套：`模板/04-验证.md`、`模板/05-评审.md` ｜ 流程位置见 `00_交付流程总纲.md` §一
> **一句话**：S4 证明「做的是需求要的」（黑盒，对照 `01-需求.md`）；S5 证明「代码本身站得住」（白盒，对照 `02-设计.md` + `rules/`）。**作者不自审**。
> **出口**：S4、S5 各自独立审批（`approve S4 --yes` 后才进 S5；`approve S5 --yes` 才算交付），缺审批不得跳过。

## 一、S4：机器门 → 逐条 AC → 失败三分

### 1.1 机器门（先跑，绿了才谈 AC）

| 门 | 命令（CWD 见括号） | 何时必须跑 | 通过标准 |
|:---|:---|:---|:---|
| 交付预检 | `cd quant_server && .venv/Scripts/python.exe scripts/quality/check_delivery.py check` | 每次 | PASS（结构齐 + 反引号路径真实存在） |
| 阶段审批 | `check_delivery.py review` → `approve Sx --yes` | 每阶段结束 | `meta.json.approvals` 有该阶段记录；**机检 PASS 不等于审批通过** |
| 质量门 | `cd quant_server && .venv/Scripts/python.exe scripts/quality/audit_strategy.py` | 策略相关 | 0 阻断 |
| 回归 | `cd quant_server && .venv/Scripts/python.exe -m pytest` | 每次 | 0 failed（**基线是 0，不接受「本来就红」**；既有失败须在 04 里列清单并单开 REQ，见 §四） |
| 策略代码同步 | `cd quant_server && .venv/Scripts/python.exe scripts/quality/sync_strategy_code.py --diff <策略ID>` | 改策略必跑 | 无分叉（exit 0）—— 否则回测/实盘读的是 DB 里 `strategies.code` 旧副本 |
| 范围 | `cd quant_server && .venv/Scripts/python.exe scripts/quality/check_all.py` | 每次 | ③ 门 PASS 或 SKIP（未声明） |
| 前端 | `cd quant_web && npx vue-tsc --noEmit && pnpm test:unit` | 改前端 | 0 error / 0 failed |

### 1.2 逐条 AC：只记「操作 + 实际输出 + 结论」

规则：
- **贴原始输出**（命令行输出、JSON 片段、DB 查询结果），不要转述。
- 截图 / SQL 结果存 `assets/`，在表格里写相对路径。
- 结论只有 ✅ / ❌ / ⊘（不适用，需写理由）。
- **禁止**在「实际输出」列写「通过」「正常」「已修复」——那和没写一样。

示例行：

| AC | 操作 | 实际输出 | 结论 |
|:---|:---|:---|:---|
| AC-1 | `pytest tests/modules/test_strategy/test_high_vol_momentum.py -k stale_bar` | `1 passed, 3 warnings in 0.42s`（exit 0） | ✅ |
| AC-2 | `GET /quantTrade/market/dashboard/temperature`（Bearer） | `{"temperature":62.4,"zone":"偏热","sample_warning":false,"data_date":"2026-11-06","dimensions":{...4 键...}}`，见 `assets/ac2.json` | ✅ |

### 1.3 失败三分法（决定回哪个阶段）

| 现象 | 判定 | 动作 |
|:---|:---|:---|
| 代码没实现 AC 要求 | 实现错 | 回 S3，按任务修，不新增范围 |
| AC 本身写宽了 / 写错了（如「返回 200」测不出空数组） | 判据错 | 回 S1 改 AC 并记「判据变更」，再回 S4 重验 |
| 环境 / 数据 / 依赖问题（DB 未起、Token 过期、沙箱拦写） | 环境错 | 修环境后**重跑**，不得记为 ✅，也不得算进「已知失败」 |

### 1.4 未覆盖与风险（必须写，不许留空）

- 没测到的场景 + 为什么不测（例：DDL 回滚未演练 → 列入残余风险，T2 必须承认）。
- 并发 / 数据量 / 权限 / 时区 / 复权 —— 这五项是本项目高发区，逐项说明「测了 / 没测及原因」。

## 二、S5：白盒评审（8 项怎么查）

> 依据 `02-设计.md` + 按路径加载的 `.claude/rules/*`。每项给「怎么查」，不是「自我感觉」。

| # | 检查项 | 怎么查（可执行） | 判定 |
|:--:|:---|:---|:---|
| 1 | 依赖方向未反向 | `grep -rn "from modules\." quant_server/shared quant_server/core`（应为空）；`grep -rn "from core\." quant_server/modules` 允许，反向禁 | 有命中 = 阻塞 |
| 2 | 无跨模块直接 import | `grep -rn "from modules\.[a-z]*\." quant_server/modules --include=*.py`，跨模块命中（非 `modules.x` 自己的子包）= 阻塞 | 事件总线替代 |
| 3 | 契约与设计一致 | 逐个对照 `02-设计.md` §契约：路由、字段名、事件名、返回码 | 不一致 = 阻塞 |
| 4 | 边界与失败路径 | 看 diff 里每个 `/ %`、`[0]`、`.iloc`、`int()`、`json.loads`：除零 / 空列表 / None / 超时 / 异常被 `except: pass` 吞掉 | 吞异常 = 阻塞 |
| 5 | 无凭证硬编码 | `grep -rniE "(password|token|api_key|secret)\s*=\s*['\"]" <改动文件>`；`.env`/`.git` 无写入 | 命中 = 阻塞 |
| 6 | 只改任务表列出的文件 | `git diff --name-only HEAD~N..HEAD` 与 `03-任务.md` 对照 | 越界 = 阻塞（除非有偏差记录） |
| 7 | 领域专项 | 策略：未来函数 `.shift(-N)`、PIT、参数越界（`audit_strategy.py` 已覆盖）；交易/风控/账户：双开关真相源、T+1 状态机、资金死锁；数据：五门 | 按 `audit-strategy.md` / `trade-risk-account.md` |
| 8 | 前端状态覆盖 | loading / empty / error / 部分失败 四态是否都有；无 3D 滥用；无内联样式破坏主题 | 缺态 = 建议以上 |

### 2.1 发现项分级

| 级别 | 定义 | 处置 |
|:---|:---|:---|
| **阻塞** | 正确性 / 资金安全 / 契约破坏 / 越界改动 | 必须修，修完重评 |
| **建议** | 可维护性、性能、命名、缺测试 | 可记入后续 REQ |
| **提示** | 风格、注释、可选优化 | 不阻塞 |

### 2.2 裁定只有四种

`通过` / `有条件通过（列出条件与复核人）` / `退回 S3`（改代码）/ `退回 S2`（改设计）。
禁止「口头放行」「下次再说」。

### 2.3 怎么发起独立评审（作者不自审）

新建只读会话（或 `.claude/agents/` 下的只读 agent），prompt 模板：

```
你是独立评审者，只读，不改任何文件。
输入：docs/09-交付记录/<REQ>/01-需求.md、02-设计.md、03-任务.md、04-验证.md
      以及 git diff <base>..<head>（或改动文件清单）。
任务：按 docs/06-标准规范/00-4_S4S5验证与评审.md §二 的 8 项逐条检查，
      每项给「通过 / 有发现 / N/A」+ 证据（文件:行）。
输出：追加到 05-评审.md 的「发现项」与「裁定」两节；不要改其他章节。
约束：发现项必须带 文件:行；不得以「看起来没问题」作为结论。
```

## 三、反例

| 反例 | 后果 | 拦截点 |
|:---|:---|:---|
| 只跑 pytest 就写「验证通过」 | AC 未被验证，需求可能根本没实现 | S4 逐条 AC 表 |
| 「实际输出」列写「通过」 | 三个月后无法复现 | 表格要求贴原始输出 |
| 把既有失败算进基线 | 回归门永久失效 | 基线必须是 0 failed；既有失败先在 04-验证.md 列「既有失败清单（文件:类名:原因）」并单开 REQ 修，不得默认接受 |
| 作者自己勾 S5 清单 | 视而不见（尤其是边界与异常吞掉） | 独立只读 agent |
| 评审只写「建议优化」不给位置 | 无法修、无法复核 | 发现项必须 `文件:行` |
