## 一、门 1 完整性（最新日期 + 条数 + 空洞）

### 1.1 日线就绪门（实盘 · **既有明文**）

出处 `main_engine.py:252-284`，位于日终流水线 `_run_daily_pipeline`（`:219-250`）的 `pre_gate` 任务与 `post_gate` 策略驱动**之间**：

| # | 条件 | 判据 | 失败动作 |
|:--|:---|:---|:---|
| 1 | 最新交易日 | `MAX(stock_daily.trade_date) == today` | 跳过实盘策略驱动（防旧数据假信号） |
| 2 | 当日条数 | `COUNT(*) WHERE trade_date=today` **≥ 4000**（A 股全市场约 5000+） | 同上 |
| 3 | 异常兜底 | 门内异常 → `gate_ok=False` | 保守跳过驱动 |

**本次新增缺口**：门 1 **只覆盖股票日线**；ETF 主力策略（高波动 / 跨市场 / ETF 底部，见 `CLAUDE.md`「实际策略清单」）不在这道门内，建议按同口径补 `etf_daily`。

### 1.2 空洞检测（回测 · **既有明文**，判据引用）

以 `stock_daily` 为日期基准逐 `ts_code` 对比目标表覆盖；**覆盖 < 90% 且缺失 ≥ 20 个交易日** = 空洞。出处：`04_回测分析标准流程.md` §2.1；实现 `backfill_coverage_gaps.py:65-66`（`DEFAULT_THRESHOLD=0.90`、`DEFAULT_MIN_MISSING=20`）、`modules/data/__init__.py:283-284`（同阈值）。

> 核心纪律：**全局 `MAX(trade_date)` 无法发现内部空洞**——两端有数据、中间整段缺失会被误判为「最新」。`stock_daily_basic` 深市主板 2022-03~2026-04 空洞即因此漏检（`backfill_coverage_gaps.py:5-8`）。

### 1.3 工具与扩展

- 检测 + 回填：`scripts/data/backfill_coverage_gaps.py`（`--dry-run` 只检测；幂等 upsert；`TABLE_CONFIGS` 当前仅 `daily_basic`、`moneyflow`，`:59-62`）。
- **本次新增**：空洞检测须扩展到所有下游依赖的日频表（`etf_daily` / `index_daily` / `stock_daily_limit` / `factor_data`）。扩展时注意数据源覆盖限制：`moneyflow` 不含 `920xxx.BJ`（北交所）属数据源缺陷**不可回填**，须先排除再算覆盖率（`backfill_coverage_gaps.py:57-58,119`）。

### 2.2 单位约定（**既有明文 + 本次修正**）

`04_回测分析标准流程.md` §2.3 仅写「`amount`（千元）/ `total_mv`（万元）/ `circ_mv`（万元）」。**本次核对 DDL：该表述不完整——`amount` 单位随表而异**：

| 表 | 字段 | 单位 | 出处 |
|:---|:---|:---|:---|
| `stock_daily` | `amount` / `vol` | **千元** / **手**（1 手=100 股） | `create_table.sql:2871-2872` |
| `etf_daily` / `index_daily` | `amount` | **万元** ⚠️ | `create_table.sql:3194,3270` |
| `stock_minutes` / `stock_weekly` / `stock_monthly` | `amount` | **元** ⚠️ | `create_table.sql:2900,2937,2975` |
| `stock_daily_basic` | `total_mv` / `circ_mv` / `total_share` / `float_share` | 万元 / 万股 | `create_table.sql:3075-3079` |
| `etf_minute` | `amount` | 万元 | `create_table.sql:3221` |

**红线**：跨表拼接量额（尤其「股票成交额」与「ETF/指数成交额」同框，如跨市场轮动）**必须先统一单位**，否则 10× / 1000× 量级错配。**本次新增**：换算须在数据加载层一次性完成并留注释，禁止策略内散点换算。

### 2.3 极值与异常值判定（**既有实现有误 + 本次修正**）

既有实现 `quality_service.py:594-605`：`|close-open|/open <= 0.2` 判正常——**对 A 股不成立**（主板 10%、创业板/科创板 20%、ST 5%、新股首日无限制），会误删合法数据。
**本次新增（推荐判据）**：用 `stock_daily_limit`（`create_table.sql:3082-3106`，含 `up_limit` / `down_limit`）：
- `close > up_limit` 或 `close < down_limit` → **硬性异常**（一票否决）
- `up_limit == down_limit` 或价格全 NULL / 0 → 数据缺失，转门 1 处理
- 无 `stock_daily_limit` 记录时按「幅度 + 板块」判定，**不得用统一 20%**

### 2.4 NaN 覆盖率上限与处理（**本次新增**）

| 字段类别 | 上限 | 处理方式 |
|:---|:---|:---|
| 价格类 `open`/`high`/`low`/`close`/`pre_close` | **NaN 率 = 0** | 有 NaN → 该 bar 不可用于信号/成交 |
| 量额类 `vol`/`amount` | 零值率 ≤ 1% | **不得当脏数据**：`vol=0` 在 `stock_daily` 中代表「停牌」或「数据缺失」两类，须先用 `stock_suspend_info` 区分（§四） |
| 财务类（`financial_*`） | 单字段 Null 率 ≤ 5%，**必须保留原值不得填充** | 见门 3 |

**严禁**用 `0` / 均值 / 前值填充价格字段后**参与交易决策**。既有反例：`quality_service.py:577-587` 的 `fix_missing_values` 会把 `close` 填成 `open`、`volume` 填成 `0`；`sync_service.py:434-462` `_preprocess_records(..., fill_numeric=...)` 亦提供 null→0 填充（用途「防止 NOT NULL 约束」，`:457`）。二者仅允许用于**入库约束兼容**，填充字段**不得进入策略计算**。

## 四、门 4 停牌与不可交易标记

| 停牌信号 | 数据表现 | 可交易性 |
|:---|:---|:---|
| `stock_suspend_info.suspend_type='S'` | 有停牌公告行（`create_table.sql:4352-4364`） | ❌ 不可买不可卖 |
