# S1 需求澄清指南（怎么问、怎么算澄清完）

> 配套：产物模板 `模板/01-需求.md` ｜ 流程位置见 `00_交付流程总纲.md` §一、§二 ｜ 机检 `python quant_server/scripts/quality/check_delivery.py check`（仓库根执行；在 `quant_server/` 内则去掉 `quant_server/` 前缀）
> **一句话**：S1 的产出不是「需求描述」，而是**一组能跑的判断**。写不成判断 = 还没澄清，不许进 S2。
> **出口**：机检 PASS ≠ 可以进 S2 —— 必须 `review` 出复核包 → `approve S1 --yes`（你审批）后才进 S2。

## 一、什么时候算澄清完（四个问题，缺一不算）

| # | 问题 | 答不出的后果 |
|:--:|:---|:---|
| 1 | **不做会怎样？**（谁在痛、痛多少） | 做了也没人用；优先级靠猜 |
| 2 | **做完怎么验证？**（一条命令 / 一次点击看到什么） | 验收随结果漂移，S4 变成「跑通了」 |
| 3 | **明确不做什么？** | 范围在编码中膨胀，一个 REQ 改 15 个文件 |
| 4 | **动到哪一层？**（档位） | 该上 T2 独立复核的改动被当 T0 提交 |

四个问题各对应 `01-需求.md` 的一节：§问题与证据 / §验收标准 / §范围·不包含 / §档位。

## 二、四步（顺序不能换）

### 2.1 先取证，再说话

证据只有三类，写不出就先去拿：

| 类型 | 长什么样 | 本项目的取法 |
|:---|:---|:---|
| **现象** | 命令 / 点击路径 + 实际输出 | `cd quant_server && .venv/Scripts/python.exe -m pytest tests/modules/test_strategy/test_high_vol_momentum.py -k stale_bar` 的失败行；浏览器控制台报错；`quant_server/logs/quant_server.log` 的时间戳行 |
| **数据** | 具体数量、比例、阈值 | `SELECT count(*) ...` 结果；回测 trades 数 / 收益率；接口响应毫秒数 |
| **代码位置** | `文件:行`、路由、表名、策略类 | `grep` 命中的行；`docs/sql/create_table.sql` 的表名（真名带业务前缀：`stock_moneyflow`、`trade_calendar`，没有裸 `moneyflow`/`trade_cal`）；`strategies` 表里的实例名 |

反例（本仓库真实踩过）：只写「资金流数据有问题」→ 无法判断是接口返回空、字段缺失，还是回填逻辑跳过了停牌日。
正例：「`DataType.MONEYFLOW` 同步（`modules/data/handlers.py:1368` → `stock_moneyflow`）跑 2026-09-01~09-05 后，`stock_moneyflow` 这 5 天各 0 行，而 `trade_calendar` 中这 5 日 `is_open = TRUE`」。

> 表名、路由、事件名一律去代码/DDL 里抄，不要凭记忆写：`docs/sql/create_table.sql` 是表名真相源，`quant_server/api/main.py:197-215` 是路由前缀真相源。

### 2.2 六问（面向用户，一次问完，别挤牙膏）

| # | 问什么 | 为什么必须问 | 不答怎么办 |
|:--:|:---|:---|:---|
| 1 | 不做会怎样？多久必须好？ | 定优先级与档位（有时答案就是「先不做」） | 记为未知，按最低优先级排 |
| 2 | 你会在**哪里**看结果？（页面 / 接口 / 报表 / 日志 / 净值曲线） | 决定 AC 的观测点；也暴露「其实没有观测手段」 | 必须问出来，否则无法验收 |
| 3 | 明确**不要**什么？（这次不碰的模块/场景） | 非目标；防蔓延 | 由你提出候选非目标请用户确认 |
| 4 | 边界情况怎么算对？（空数据 / 只有 1 条 / 十年历史 / 停牌 / 复权 / 无权限 / 并发） | 这项目的 bug 大多在边界，不在主路径 | 写进 §假设与未知，S2 必须回答 |
| 5 | 兼容性要求？（老接口调用方 / 老数据 / 策略在 DB 的代码副本 / 已发布页面） | 决定是否需要兼容期与回滚方案 | 默认「必须兼容」，除非用户明确说可以破坏 |
| 6 | 谁验收、什么形式？（你自测 / 你点一遍 / 看截图 / 看回测报告） | 决定 04-验证.md 的证据形态 | 默认「作者自测 + 贴原始输出」 |

> 一次问 6 个问题 > 分 6 轮各问 1 个。信息缺失时**暂停**，不要替用户假设（`AGENTS.md` 行为约束）。

### 2.3 AC 只有一种格式

```
- AC-<n>：<操作> → <可观测输出>
```

**操作**三选一，必须是别人能照做的：

| 类型 | 写法 | 例 |
|:---|:---|:---|
| 命令 | 完整命令行 + 期望退出码 | `cd quant_server && .venv/Scripts/python.exe -m pytest tests/modules/test_strategy/test_high_vol_momentum.py -k stale_bar` → exit 0，且输出含 `1 passed` |
| HTTP | 方法 + 路径 + 关键字段 | `GET /quantTrade/market/dashboard/temperature`（带 Bearer）→ 200，`temperature` ∈ [0,100]，`dimensions` 恰含 valuation/emotion/capital/technical 四键，`data_date` = 最近交易日 |
| UI | 页面 → 控件 → 期望状态 | `/market/dashboard`（`views/DataCenter/Market/MarketDashboard.vue`）→ 首屏温度仪表显示 ℃ 数值与 zone 文案；Network 中 `dashboard/temperature` 返回 200 |

**期望**必须是能看见的东西：数字、字段值、元素、行数、退出码、日志关键字。

**禁止词**（出现即判 S1 未完成）：正常 / 合理 / 正确 / 符合预期 / 不报错 / 可用 / 优化好 / 流畅。

对照表：

| ❌ 写不成判断 | ✅ 改成判断 |
|:---|:---|
| 回测能正常跑 | `cd quant_server && .venv/Scripts/python.exe -m pytest tests/modules/test_strategy/test_high_vol_momentum.py -k stale_bar` → exit 0；回测脚本 → trades>0、无 NaN、收益率 ∈ [−95%, +500%] |
| 页面加载更快 | 同一数据下 `/market/dashboard` 首屏 LCP < 1.5s（DevTools Performance 截图存 `assets/`） |
| 资金流数据修好 | 重跑同步后 `SELECT count(*) FROM stock_moneyflow WHERE trade_date BETWEEN '2026-09-01' AND '2026-09-05'` → 5 个交易日均有数据，且这 5 天在 `trade_calendar` 中 `is_open = TRUE` |
| 接口加个字段 | `GET /quantTrade/strategy` 返回体新增 `win_rate`（float，0–1，缺数据为 null），旧字段一个不少（对比 `assets/before.json`） |

**条数**：1–5 条。超过 5 条通常该拆成两个 REQ（按「谁能独立验收」切）。

### 2.4 非目标至少一条

写法：`- 不包含：本次不改 X（因为 Y）`。例：
- 不包含：本次只修资金流「空返回被算成成功」的计数，不改 Tushare 限流重试策略（那属于另一个 REQ）。
- 不包含：本次只做温度页接口，不改前端图表库（仍用现有 ECharts 封装）。

### 2.5 档位：看「碰了什么」，不看「改了多少行」

判据表见 `00_交付流程总纲.md` §二。三个最常错的地方：

1. **T0 不是「小」**：只要碰 `core/`、`shared/`、`docs/sql/create_table.sql`、交易/风控/账户、认证 → 至少 T2，文件再少也一样。
2. **策略一律 T3**：改 `modules/strategy/strategies/**` 或 DB `strategies.code` / `strategy_parameters`，就走 R0–R3 + G0–G5，不存在「策略小改」。
3. **T0 不许建 REQ**，commit 带 `[T0]`；一旦发现要动第二类文件，立刻升级并补建 REQ。

## 三、判据变更（唯一合法改 AC 的时机）

- 时机：S4 发现「AC 本身写错了」，或用户中途改需求。
- 做法：回 `01-需求.md`，在 §验收标准 下追加：

```
- 判据变更 2026-11-09：AC-2 「返回 200」→「返回 200 且 items 非空」。理由：空数组也算 200，原判据测不出空数据 bug。
```

- **禁止**在 `04-验证.md` 里悄悄把 AC 改宽（那是造假，不是记录）。

## 四、提交 S1 前的自查

- [ ] 每条 AC 都有 `→`，且右侧是数字/字段/元素，不是形容词
- [ ] 至少 1 条非目标
- [ ] 档位理由写的是「碰了哪个敏感面」，不是「改动小」
- [ ] 未知项写清「谁去确认、什么时候确认」
- [ ] `check_delivery.py check` 显示 S1 ✅（结构层面：章节齐、AC ≥1、无占位符）

## 五、本项目常见的「澄清失败」开场白

| 用户原话 | 真正要问出来的 |
|:---|:---|
| 「接口加个字段」 | 给谁用？页面哪个位置显示？缺数据时显示什么？老调用方会不会因字段变多而挂？ |
| 「页面优化一下」 | 优化哪个指标（首屏时间/信息密度/操作步数）？现在是多少？目标是多少？ |
| 「策略再调调」 | 调哪个参数/机制？判据是年化、回撤还是单次进攻收益？用哪段区间、哪个基准？ |
| 「数据不对」 | 哪张表、哪个日期范围、期望多少行、实际多少行？哪一步写入的？ |
| 「加个定时任务」 | 失败要不要告警？重跑是否幂等？和现有日终任务（pre_gate/post_gate）什么顺序？ |
