# 量化交易系统详细设计

> 整合自 13 篇源文档 | 2026-07-26 | v4.0

## 第一部分：系统架构

### 1.1 核心架构约束

**依赖方向（严禁反向）**：
```
modules/ → shared/ → core/
modules/ → utils/
api/ → shared/
```

**通信机制**：
| 场景 | 方式 |
|:---|:---|
| Service → Repository | 同步直接调用 |
| 模块间（如 strategy → trade） | 仅通过 EventEngine 异步事件 |
| Engine 之间 | EventEngine 发布/订阅 |

**Engine vs Service（严禁混淆）**：
- Engine：有状态，继承 `EngineBase`，响应事件，协调 Service
- Service：无状态纯计算，不持有事件引擎引用

### 1.2 启动流程

```
QuantServer.__init__()
  → StartupConfig 加载 config.yaml (pydantic-settings 解析 .env)
  → initialize()
      → DB 连接池
      → FastAPI create_app()
      → EventEngine
      → MainEngine
          → 拓扑排序加载各模块 initialize()
          → SystemStartedEvent → 各引擎开始处理事件
  → Uvicorn ASGI
```

### 1.3 模块清单

| 模块 | 职责 | 可禁用 |
|:---|:---|:---|
| data | 数据同步（Tushare→DB）、因子计算、研究服务 | ✅ |
| strategy | 策略管理、信号生成（技术/AI/Alpha） | ✅ |
| trade | 信号→订单执行、仓位管理 | ✅ |
| backtest | 历史回测、绩效分析 | ✅ |
| account | 多账户管理、资金流水 | ✅ |
| risk | 风控检查（止损、仓位上限） | ✅ |
| analysis | 绩效归因、Sharpe/MDD 等指标 | ✅ |
| monitor | 系统监控、钉钉/微信通知 | ✅ |
| market | 实时行情、交易日历 | ✅ |
| system | JWT 认证、系统配置 | ✅ |

### 1.4 模块标准目录

```
modules/<name>/
  engines/        # 引擎类（有状态）
  events/         # 事件定义
  services/       # 服务类（无状态）
  handlers.py     # 请求处理器
  managers/       # 管理器
  schemas.py      # 数据模式
  models.py       # ORM 模型
  tasks/          # 异步任务
  utils/          # 工具函数
  constants.py    # 常量
```

### 1.5 事件命名规范

```
格式: {module}.{domain}.{action}.{status}
例:   trade.order.submitted
```

### 1.6 Repository 规范

一表一 Repository，继承 `BaseRepository`，纯 CRUD 不含业务逻辑。位置：`shared/database/repositories/`。

### 1.7 配置系统

双层配置：

| 文件 | 内容 | 加载方式 |
|:---|:---|:---|
| `config.yaml` | 非敏感参数（引擎参数、端口、日志） | `StartupConfig` 主动加载 |
| `.env` | 敏感凭证（DB 密码、Tushare Token） | pydantic-settings 自动解析 |

关键环境变量：
- `ENVIRONMENT` → `development` / `production`
- `SIMULATED_TRADING=true` — 安全总开关，**严禁设为 false**
- `DEV_DATABASE__NAME` / `PROD_DATABASE__NAME`

### 1.8 数据库

- PostgreSQL 14+ + TimescaleDB 2.10+
- DDL 入口：`docs/sql/create_table.sql`（93 张表，21 张超表）
- 开发库 `quant_signals_dev`，生产库 `quant_signals`
- 无迁移框架，直接执行 SQL 文件

### 1.9 分支策略

- `dev` — 开发分支
- `master` — 生产分支
- **严禁在 master 上直接提交**，所有变更经 dev 验证后合并

```
第五层: 知识决策（策略选择引擎、环境自适应、元学习）     ⬜ 待激活
```

## 第三部分：策略体系

### 3.1 基类与生命周期

```python
class BaseStrategy:
    DEFAULT_PARAMS: dict       # 所有可调参数
    strategy_type: StrategyType

    def __init__(name, parameters)
    def on_init()              # 加载模型/数据
    async def on_start()       # 重置状态
    def on_bar(bar) → List[TradingSignal]   # 主逻辑
    def on_stop()              # 清理
    def get_parameters() → dict
```

信号类型：`ENTRY` / `EXIT` / `STOP_LOSS` / `TAKE_PROFIT` / `EXIT`

### 3.2 策略代码管理（关键机制）

```
策略代码存储在 DB strategies.code 列，非 .py 文件。
加载方式: exec(_code, temp_module) → 提取 BaseStrategy 子类
```

**模板 seed 机制**（系统重启时）：
```
seed_builtin_templates()
  → import strategy .py 文件
  → inspect.getsource() 读取完整源码
  → 幂等写入 strategy_templates 表
```

**策略实例创建**（前端"基于模板创建"）：
```
create_instance_from_template()
  → 从 strategy_templates.code_template 复制源码
  → 写入 strategies.code
  → 复制 default_parameters → strategy_parameters 表
```

**关键约束**：
- 模板随重启自动更新，策略实例不自动更新
- 实盘策略代码 = 创建时的快照，不随 .py 文件修改而变化
- 策略实例升级 = 新建实例 + 验证 + 切换

### 3.3 ETF 底部策略 (LightGBMBottomStrategy)

**模型**：LightGBM 二分类，44 特征，27 棵树

**标签构造**（回归→分类的演化）：
```
原始三分标签: target = 2(高质量底) / 1(低质量底) / 0(非底)
  判定条件: 未来10日 max_return≥3% 且 min_return≥-5%

v2 合并为二分: target = (original >= 1) → 0/1
```

**训练**：
- 训练集：~2024-12-31（覆盖完整熊牛市）
- 验证集：2025-01-01 ~ 2025-06-30
- 测试集：2025-07-01 ~ 2026-07-25
- 参数：num_leaves=15, max_depth=4, lr=0.03, early_stopping=50

**入场**（v5 生效参数）：
```
1. 模型预测 proba ≥ 分市场阈值 (base 0.54 + regime_adj)
2. ATR/close ≥ 1.5%（波动率过滤）
3. 量能确认：vol ≥ MA(vol,20)
4. P4 确认：次日 close > 信号日 low
5. 仓位：线性映射 weight = (proba - threshold) × 40%
```

**出场**（v5 生效参数）：
```
1. ATR 动态止损: stop = max(regime_stop_loss, -2.5×ATR_ratio)
2. 智能时间止损: 持有到期但浮盈>2% → 延期
3. 分市场 Trailing Stop: 牛市 5%/8%, 震荡 4%/6%, 熊市 6%/10%
```

**分市场参数**：

| 参数 | BEAR(0) | RANGE(1) | BULL(2) |
|:---|:---|:---|:---|
| 阈值偏移 | -0.02 | +0.04 | -0.06 |
| 最大持仓 | 5 | 3 | 4 |
| 止损 | -8% | -6% | -7% |
| 移动止盈 | 6%/10% | 4%/6% | 5%/8% |
| 持仓上限 | 25d | 14d | 20d |

### 3.4 低吸轮动策略 (StockLowHighStrategy)

**选股六条件**：
1. 昨日收阳 + 涨幅 ≥ 0.7%
2. MA5 > MA20
3. 量比 ≥ 1.2
4. ROC(10) > 5
5. MACD 金叉（DIF > DEA 且 DIF > 0）
6. 价格低于 20 日新高 0.15%~8%

**三档行情判定**（csi500 MA 体系）：
- 上涨市：close > MA20 > MA60 且 MA20 斜率正
- 震荡市：近 20 日涨跌幅 ≤ 3%
- 下跌市：close < MA20 < MA60 且 MA20 斜率为负
- **年线门**：csi500 close < MA250 → 强制下跌市（停买）

**出场**：
- 池内股：只止损，不止盈（让利润奔跑）
- 池外股：止损 + 抛物线止盈（浮盈越高回落容忍越窄）
- 动态再平衡：浮盈 ≥ 100% → 卖半仓

### 3.5 策略版本演进总览

| 版本 | 收益 | 夏普 | 回撤 | 核心改动 |
|:---|:---|:---|:---|:---|
| v1 | +11.8% | 0.45 | 7.82% | 基线（42 特征，训练至 2022） |
| v2 回归 | -50~-77% | — | — | 回归模型失败 |
| v2 分类 | +4.11% | 0.60 | 2.23% | 74 特征 + 扩展训练 |
| v3 | +4.86% | 0.67 | 1.73% | 移除酒/旅游 ETF |
| v4 | +2.66% | 1.10 | 0.49% | +凯利(失败) +ATR +量能 |
| v5 | **+13.23%** | **1.08** | **2.44%** | 去凯利、线性仓位 |

### 3.6 因子研究管线

```
因子定义(factor_definitions) → 计算(factor_calculators) → 存储(factor_data)

```

IC 分析输出：

## 第四部分：回测体系

### 4.1 核心引擎

```
BacktestEngine.run()
  ├── BacktestBroker     ：虚拟券商，T+1 撮合
  ├── DataFeedEngine     ：历史数据加载 + 逐日迭代
  ├── StrategyManager    ：策略信号生成
  └── Sizer              ：信号 → 股数计算
```

### 4.2 Broker 撮合规则

模拟 A 股真实环境：
- **T+1**：当日买入，次日开盘方可卖出
- **涨跌停**：主板 ±10%，科创 ±20%，ST ±5%。涨停不买，跌停不卖
- **费用**：万一佣金（免五）、0.1% 印花税（仅卖出）、0.002% 过户费（双向）
- **滑点**：买入 ×(1+0.1%)，卖出 ×(1-0.1%)
- **最小交易单位**：100 股（1 手）

### 4.3 资金校验三层防护

```
L1: _validate_order()   — 宽松门（估算成本 > 现金×1.01 才拒绝）
L2: submit_order()      — 自动缩减数量
L3: match_orders()      — 按实际开盘价最终校验 + 二次缩减
```

### 4.4 Sizer 数量计算

| Sizer | 触发条件 | 计算方式 |
|:---|:---|:---|
| WeightSizer | signal.weight > 0 | `shares = weight × cash × 0.995 / price` |
| CloseAllSizer | CLOSE_LONG + qty=0 | 全部持仓 |
| HalfCloseSizer | CLOSE_LONG + half_exit | 一半持仓 |
| QuantitySizer | signal.quantity > 0 | 直接使用 |

### 4.5 绩效指标体系

- `total_return` / `annual_return` / `sharpe_ratio` / `max_drawdown`
- `win_rate` / `profit_factor` / `avg_trade_return`
- `alpha` / `beta`（vs 基准指数）
- `monthly_returns` / `daily_returns`

## 第五部分：实盘体系

### 5.1 信号处理链路

```
行情推送 → StrategyManager.handle_bar_batch()
  → 遍历所有 running 策略:
      strategy.on_bar(bar) → 产生信号
      strategy.on_bar_batch_end() → 批次结束信号（低吸轮动用）
  → 汇总所有信号
  → _publish_signals() → EventEngine
  → Broker 订阅 → submit_order()
```

### 5.2 生产环境部署

```
开发环境: IDEA :8080, DB=quant_signals_dev, 策略可编辑
生产环境: 独立进程 :8081, DB=quant_signals, 策略代码冻结
```

**策略热更新**：
```
1. 开发环境回测验证
2. 生产库新建策略实例（从模板取最新代码）
3. 生产库回测确认
4. 旧实例 → paused, 新实例 → running
5. 观察 1-2 周 → 稳定后删旧实例
```

**模型升级**：
```
1. 开发环境训练 → 回测 OK
2. 手动复制到生产 storage/models/
3. 策略 _find_latest_model() 自动发现
4. 出问题 → 删除新版文件 → 策略自动回退到旧版
```

### 5.3 风险矩阵

| 风险 | 缓解 |
|:---|:---|
| 实盘进程退出 | Windows 服务 + 心跳监控 |
| 策略实盘 vs 回测偏差 | 每周对比，超 2σ 告警 |
| 参数被前端误改 | running 策略禁止编辑 |
| SIMULATED_TRADING 误关 | production 模式硬编码 true |

## 第六部分：开发规范

### 6.1 不等式方向检查（强制）

对任何涉及比较的修改，执行三步：

```
1. 写出不等式:  估算值 > 现金门槛
2. 标注修改位置: 你要改哪一边？
3. 判断方向: 左侧增大→更严格  右侧增大→更宽松
```

### 6.2 边界条件检查

- None：`getattr(obj, "field", default)` 而非 `obj.field`
- 空集合：`df.empty` 检查后 `.iloc[0]`
- 除零：分母 `> 0` 保护
- NaN 传播：`**` 运算前检查底数 > 0

### 6.3 禁止项

- 禁止 `shift(-1)` / `.iloc[i+1]` — 未来数据泄露
- 禁止 `except Exception: pass`
- 禁止同一个字段写入多个存储位置
- 禁止在 `generate_signals()` 中执行网络请求
- 禁止策略代码变更后不同步 `strategies.code`

### 6.4 策略文件模板

```python
class MyStrategy(BaseStrategy):
    # 1. 所有可调参数
    DEFAULT_PARAMS = {...}

    # 2. 初始化
    def __init__(self, name, strategy_type, parameters):
        super().__init__(...)

    # 3. 加载模型/数据
    def on_init(self): ...

    # 4. 主逻辑
    def on_bar(self, bar) -> List[TradingSignal]: ...

    # 5. 出场检查
    def _check_exit(self, ts_code, bar) -> Optional[TradingSignal]: ...

    # 6. 工具方法
    def get_parameters(self) -> Dict: ...
```
