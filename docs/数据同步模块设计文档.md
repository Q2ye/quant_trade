# 数据同步模块设计文档

> **更新日期**：2026-06-07
> **数据源**：Tushare Pro（主）+ Baostock（辅）
> **数据库**：PostgreSQL 14+ + TimescaleDB 2.10+
> **频率定位**：中低频，日线/周线级别

## 二、同步类型分组与执行顺序

按**同步频率 + 数据依赖**分为 6 组，组内有明确的执行顺序，组间有先后依赖。

### 分组总览

| 组 | 名称 | 建议频率 | 说明 | 已实现 | 待补充 |
|:---|:---|:---|:---|---:|---:|
| **A** | 🟢 基础数据 | 首次 + 按需 | 优先同步，后续同步的数据依赖 | 6 | 3 |
| **B** | 🔵 日频行情 | 每日 | 每天必跑的核心行情 | 10 | 4 |
| **C** | 🟣 周月行情 | 每周/每月 | 低频行情 | 2 | 2 |
| **D** | 🟠 财务数据 | 每季度 | 财报季后集中更新 | 9 | 1 |
| **E** | 🟡 公司治理 | 每月 | 股东/管理层/质押/解禁 | 2 | 9 |
| **F** | ⚪ 高频特种 | 按需 | 分钟/Tick/宏观，数据量大或需积分 | 7 | 3 |

## 三、已完成同步数据类型（44 种，按业务域分组）

### 3.1 股票基础信息（4 种）

| 类型标识 | 目标表 | 同步方式 | 说明 |
|:---|:---|:---|:---|
| `STOCK_LIST` | `stock_basic` | 全量拉取 → 逐条 upsert | A 股全部上市股票基础信息（代码、名称、行业、上市日） |
| `COMPANY` | `stock_company` | 全量拉取 → 逐条 upsert | 上市公司基本信息（注册资本、员工数、主营业务） |
| `ST_LIST` | `stock_st_list` | 日期范围拉取 → 批量 upsert | ST/*ST 变更历史，仅保留 name 含 "ST" 的记录 |
| `CALENDAR` | `trade_calendar` | 日期范围拉取 → 按交易所+日期 upsert | SSE/SZSE 交易日历 |

### 3.2 股票行情（9 种）

| 类型标识 | 目标表 | 同步方式 | 说明 |
|:---|:---|:---|:---|
| `DAILY_QUOTES` | `stock_daily` (超表) | **逐股并行** + 智能日期推断 | 股票日线行情，OHLCV，~5000 只 × 250 天/年 |
| `WEEKLY_QUOTES` | `stock_weekly` | 逐股同步 + 智能日期推断 | 股票周线行情 |
| `MONTHLY_QUOTES` | `stock_monthly` | 逐股同步 + 智能日期推断 | 股票月线行情 |
| `MINUTE_QUOTES` | `stock_minute` (超表) | 逐股拉取 → 批量插入 | 股票分钟行情（默认 1min，最近 7 天，限 100 只） |
| `TICK_QUOTES` | tick 表 | 逐股按日拉取 | Tick行情，⚠️ 拉取后未入库 |
| `MONEYFLOW` | `stock_moneyflow` | 逐股同步 + 智能日期推断 | 股票资金流向（主力/散户净流入） |
| `ADJ_FACTOR` | `stock_adj_factor` | 逐股同步 + 智能日期推断 | 股票复权因子 |
| `DAILY_BASIC` | `stock_daily_basic` | 逐股同步 + 智能日期推断 | 股票每日指标（市盈率、市净率、换手率等） |
| `SUSPEND` | `stock_suspend_info` | 日期范围拉取 → 逐条 upsert | 每日停复牌（默认最近 30 天） |

### 3.3 ETF 数据（6 种）

| 类型标识 | 目标表 | 同步方式 | 说明 |
|:---|:---|:---|:---|
| `ETF_BASIC` | `etf_basic` | 全量拉取 → 批量 upsert | ETF 基金基础信息（过滤后 ~1000 只） |
| `ETF_INDEX` | `etf_index` | 全量拉取 → 批量 upsert | ETF 跟踪的基准指数 |
| `ETF_DAILY` | `etf_daily` | 逐 ETF 同步 + 智能日期推断 | ETF日线行情 |
| `ETF_MINUTE` | `etf_minute` | 逐 ETF 拉取 → 批量插入 | ETF分钟行情（默认最近 7 天，限 50 只） |
| `FUND_ADJ_FACTOR` | `fund_adj_factor` | 逐 ETF 同步 + 智能日期推断 | ETF复权因子 |
| `ETF_SHARE` | `etf_share` | 逐 ETF 拉取 → 逐条 upsert | ETF份额规模（反映资金净流入/流出） |

#### ETF 基础信息过滤规则

Tushare `fund_basic` 接口返回**全部公募基金**（~15000 只），需要通过 `name` 字段过滤：

| 规则 | 说明 |
|:---|:---|
| `name` 包含 `ETF` | 基金简称中含 ETF 标识 |
| `name` 不包含 `联接` | 排除 ETF 联接基金 |

### 3.4 指数数据（6 种）

| 类型标识 | 目标表 | 说明 |
|:---|:---|:---|
| `INDEX_BASIC` | `index_basic` | 沪深两市所有指数基本信息（~500 个） |

| `INDEX_WEEKLY` | — | 指数周线行情，⚠️ Source 和 sync 已实现，**缺建表 SQL 和 ORM 模型** |
| `CPI` / `PPI` / `GDP` | `macro_cpi/ppi/gdp` | CPI居民消费价格 / PPI工业出厂价格 / GDP国内生产总值 |

### 3.5 财务报表（4 种入口，共用 1 张表）

| `FINANCIAL_CASHFLOW` | `financial_statements` | 现金流量表（`report_type="cashflow"`） |

### 3.7 公司治理（2 种）

## 八、同步核心机制

### 8.1 智能日期推断

`_resolve_sync_date_range` 根据 DB 已有数据自动判断四种模式：

| 模式 | 触发条件 | 行为 |
|:---|:---|:---|
| **full** | DB 中无该股票任何记录 | 从上市日全量拉取 |
| **incremental** | DB 有记录 + 用户未指定起始日期 | 只拉新增数据 |
| **up_to_date** | 最后交易日 ≥ end_date | 跳过 |
| **overlap** | 用户显式指定了 start_date | 按用户范围拉取 |

### 8.2 同步生命周期（6 步）

```
create_sync_task() → publish(started) → run_sync_method()
→ 判断状态 → publish(completed/failed) → clean_cache()
```

### 8.3 批量同步

- **串行** (`batch_sync`)：共享 session，逐个执行
- **并行** (`batch_sync_data`)：Semaphore(3)，独立 session + DataSyncService 实例

### 8.4 取消机制

双重保障：asyncio.Event（内存，O(1)）+ DB 状态标记（持久化回退）。

### 8.5 写入层

- `_process_trade_date_data` Facade：9 个行情方法统一入口
- `bulk_upsert`：自动推断冲突键，分页 1000 条/批
- `_preprocess_records`：一趟完成 Timestamp→datetime + NaN→None + 日期转换 + 多余列过滤

def get_stk_holdernumber(self, ts_code: str = '') -> pd.DataFrame:
    """获取股东人数（Tushare stk_holdernumber 接口）

    Args:
        ts_code: 股票代码（空=全市场）
    Returns:
        DataFrame: columns: ts_code, ann_date, end_date, holder_num, ...
    """
    try:
        kwargs = {}
        if ts_code:
            kwargs['ts_code'] = ts_code
        df = self.pro.stk_holdernumber(**kwargs)
        if df is not None and not df.empty:
            for col in ('ann_date', 'end_date'):
                if col in df.columns:
                    df[col] = pd.to_datetime(df[col])
        return df if df is not None else pd.DataFrame()
    except Exception as e:
        logger.error(f"获取股东人数失败: {e}")
        return pd.DataFrame()

async def _sync_stk_holdernumber(self, start_date, end_date, ts_codes, task_id, user_id=None, **_kwargs):
    """同步股东人数（stock_stk_holdernumber 表，逐股拉取全历史）。"""
    source = self.source_factory.get_source(DataSource.TUSHARE)
    if not ts_codes:
        stocks = await self.stock_basic_repo.get_active_stocks()
        ts_codes = [s.ts_code for s in stocks]

    async def _process_one(session, ts_code):
        repo = StockHoldernumberRepository(session)
        source = self.source_factory.get_source(DataSource.TUSHARE)
        try:
            df = await self._cancellable_run_in_executor(source.get_stk_holdernumber, ts_code=ts_code)
            if df is None or df.empty:
                return {"added": 0, "updated": 0}
            data = _convert_records_datetime(df.to_dict("records"))
            _preprocess_records(data, date_fields=('ann_date', 'end_date'))
            data = list({(d.get('ts_code'), d.get('ann_date'), d.get('end_date')): d for d in data}.values())
            added = await repo.bulk_upsert(data)
            return {"added": added, "updated": 0}
        except Exception as e:
            logger.error(f"[股东人数] {ts_code} 同步失败: {_fmt_err(e, 150)}")
            return {"added": 0, "updated": 0, "failed": True}

    async with SyncTimingLogger(logger, "股东人数(holdernumber)", slow_threshold=30.0):
        logger.info(f"[股东人数] 并行同步 {len(ts_codes)} 只, 并发=8")
        result = await self._parallel_for_each(ts_codes, "股东人数", task_id, user_id, _process_one, rate_key="holdernumber")
        if not result.get("cancelled"):
            result["message"] = "股东人数数据同步完成"
        return result

### 13.3 三种同步模式的差异

新增类型按数据特征落入三种模式之一：

| 模式 | 适用场景 | 参考模板 | 涉及的 Step 差异 |
|:---|:---|:---|:---|
| **全量拉取** | 数据量小、无日期维度（如沪深港通列表、行业分类） | `_sync_etf_basic` | 无 `_resolve_sync_date_range`，无 `_process_one` |
| **逐股同步** | 按 ts_code 逐只拉取（如股东人数、质押统计） | `_sync_stk_managers` / `_sync_forecast` | `_parallel_for_each` + `_process_one` |
| **日期范围拉取** | 按日期段全市场拉取（如停复牌、限售解禁） | `_sync_suspend_info` / `_sync_st_list` | `source.get_xxx(start_date, end_date)` 单次拉取 |

### 13.5 可行性评估

| 维度 | 评估 |
|:---|:---|
| **技术可行性** | ✅ 高 — 所有新类型均可对标现有实现（全量拉取/逐股同步/日期范围拉取三种模式已成熟） |
| **工作量** | 约 12 步/类型 × 19 类型 = 228 个独立修改点，但大量重复模式可批量复制 |
| **积分** | P0+P1 共需 ~32,000 积分，分 4 天执行。单次执行不可超额（8130/天硬限制） |
| **存储** | 15 张新表，估约 2-5 GB（大表为股东人数/质押/因子，各 ~100 万行） |
| **风险** | Tushare 接口随时可能调整字段或限速策略，首次全量同步耗时长（P0 逐股项约 15-25min/项） |
| **依赖** | 申万行业成分依赖行业分类先完成；前十大股东/流通股东可并行；其余无硬依赖 |

**结论**：分 4 批执行，每批 3-5 天（含编码+测试+首跑验证），P0 全部完成预计 2-3 周。建议先从第 1 批（4 个全量拉取型）开始，验证流程后再推进逐股型。
