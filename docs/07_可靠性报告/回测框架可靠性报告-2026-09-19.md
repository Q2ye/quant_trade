# 回测框架可靠性报告

> **版本**：2026-09-19 ｜ **代码基线**：分支 `dev`
> **范围**：`quant_server/modules/backtest/`（引擎 / 券商 / 撮合 / 费用 / 优化器）
> **方法**：代码实证（路径:行号）+ 既有审计文档交叉核对 + 测试覆盖实测
> **口径**：只写**证据支持**的结论；未找到证据的项一律标注「未找到」

## 一、结论

### 1.1 分层判定

| 层 | 判定 | 依据 |
|:---|:---|:---|
| **撮合 / 成交价 / T+1 语义** | ✅ **可靠** | 与 A 股制度一致，经多轮缺陷加固（§三） |
| **费用模型（佣金 / 印花税 / 过户费 / 滑点）** | ✅ **可靠** | ETF 免征印花税已正确区分；有专项单测 |
| **风控隔离（回测不误杀）** | ✅ **可靠** | 账户级规则已显式排除，幽灵持仓根因已消 |
| **执行模型（Model A 日内止损 / Model B 收盘确认）** | ✅ **可靠** | 两条路径均有实现与注释锚点 |
| **结果可信度（可复现性）** | 🔴 **不可靠** | **回测与策略代码版本无绑定**（§五-1） |
| **参数优化器** | 🔴 **不可用** | grid 结果恒为首组合（§五-2） |
| **基本面因子类回测** | 🔴 **不可靠** | 前视 ~116 天（§五-3） |
| **测试保障** | 🔴 **极薄** | 引擎/券商仅 1 个测试文件（§四） |

### 1.2 一句话

> **框架的「交易模拟」部分是可靠的**（撮合、费用、T+1、风控隔离均已加固并有证据）；
> **框架的「结论可信度」部分不可靠** —— 主因是**回测与代码版本无绑定**、
> **测试覆盖极薄**、以及**参数优化器不可用**。
> → **框架可用于生成结论，但当前无法证明「某结论对应哪个代码版本」。**

## 三、框架已加固的可靠性要点（证据）

> 以下均为**代码内可验证**的加固点，构成框架「交易模拟可靠」的依据。

### 3.1 交易制度对齐 ✅

| 项 | 实现 | 证据 |
|:---|:---|:---|
| **T+1** | 次日开盘价成交；`t_plus_1 = True` 默认 | `backtest_broker.py:10-11, 29, 110-112, 207` |
| **隔日可卖校验** | 用 `available_quantity`，并修正过「过度收紧」 | `:339-349`、`:1302-1307` |
| **涨跌停** | 分板块判定（科创板 20% / ST 5% / 主板 10%）；trigger 分支跌停顺延 | `:1339-1374`、`:669-677` |
| **停牌 / 无 bar** | 无持仓可卖 → 订单作废，不崩 | `:764-772` |
| **同日两笔卖出超卖** | `pos.quantity < order.quantity` 抛错（防现金虚增） | `:1319-1330` |
| **买入现金充足性** | 负现金 → 拒绝（防净值幻影） | `:791-799` |

### 3.2 费用模型 ✅

```
commission_rate = 0.0001      最低佣金 0.0（账户为万一免五）
stamp_tax       = 0.001       ← ⚠️ 见 §五-8（口径过期）
transfer_fee    = 0.00002
slippage        = 0.001
```

- **ETF 免征印花税与过户费**：`stamp_tax_etf = 0.0` / `transfer_fee_rate_etf = 0.0`，
  由 `_fee_rates(ts_code)` 集中判别（`:203-204`、`:732-747`、`:778-788`）
- **实测量级**：修复前 ETF 被系统性多收印花税 410,740 元（= 初始资金 **41.1%**），
  跨市场策略 **209.02% → 286.72%**、夏普 0.972 → 1.157
- **专项单测**：`tests/modules/test_backtest/test_broker_etf_fees.py`
  （`TestIsEtf` / `TestFeeRates` / `TestExecuteFillFees`）

### 3.3 风控隔离 ✅

- **回测中排除账户级日终监控规则**（`capital_change` / `trade_count` / `limit_up_down` 等 5 条）：
  `backtest_broker.py:438-445`
- 根因链已闭环：回测循环不喂真实资金 → 超买 → 资金不足 → **幽灵持仓**（`docs/01-业务设计/策略资金与仓位契约.md:14`）

### 3.4 执行模型 ✅

| 模型 | 语义 | 锚点 |
|:---|:---|:---|
| **Model A** | 日内止损（`order_mode="trigger"`），跨日与当日两条路径 | `:670-693` / `:938-960` |
| **Model B** | 收盘确认买入（`order_mode="close"`） | `:930-936` |
| **T+1 开盘成交** | 策略层 `order_mode="open"`，对齐实盘「当天信号→次日成交」 | `:110-112` |

### 3.5 无未来函数（框架层）✅

`modules/strategy/` 与 `modules/backtest/` 全量搜索 `shift(-1)` / `.iloc[i+1]` —— **无命中**。

## 六、使用约束（在当前状态下如何用才可靠）

| 约束 | 理由 |
|:---|:---|
| **不得跨代码版本对比回测数字** | 无版本绑定（§五-1）—— 改代码前后两次数值不可比 |
| **不得使用参数优化器结论** | grid 恒为首组合（§五-2） |
| **不得用兜底宇宙回测结果做选池决策** | 前 1000 只兜底偏差可达 20×（§五-5） |
| **基本面因子类回测须自证无前视** | PIT 未修（§五-3） |
| **脚本回测与服务端回测结论不得互换** | 三处口径不一致（§五-6） |
| **路径依赖策略禁用单起始日结论** | 必须看滚动起始日的**中位/下四分位/最差**分布 |
