### 门 2 正确性 ✅

**2.1 复权因子一致性**（样本 3,519,990 对相邻日，2024-01-01 起）

| 指标 | 实测 |
|:---|:---|
| `hfq_t/hfq_{t-1} - 1 == pct_chg_t/100` 误差 **≤ 1e-6** | **99.405%** |
| 误差中位 / P99 | **2.43e-07** / 4.98e-07 |
| `pre_close == close_{t-1} × adj_{t-1} / adj_t` 吻合 | **99.9890%** |
| 不吻合（= 除权除息日） | 388 行（0.0110%） |

> 中位误差 2.4e-7 表明**复权因子与价格序列高度自洽**；
> 未达 100% 的部分为 `close` 仅存 2 位小数导致的舍入（该量级下界即 ~1e-5）。
> 两条独立判据（收益对拍 + 前收还原）**互相印证**。

> ⚠️ **在册异常**：26 行（0.00074%）误差 > 5%，分型为 `adj_factor` 漏记除权 11 /
> 多记除权 12 / 混合 3，其中 `2026-07-03` 单日占 11 行。**影响范围限于跨越该日的单个 return**。
> 已登记待查（见 §四）。

## 六、schema 漂移（本报告新增，影响面较大）

**实测**：活库 **39 个 NUMERIC 列**的精度**窄于**权威 DDL（`docs/sql/create_table.sql`），涉及 13 张表。
`create_table.sql` 与 SQLAlchemy 模型（`shared/database/models/data_models.py`）**两者一致且更宽**
→ **只有活库是错的一方**（CLAUDE.md 明载「表结构以该文件为准」）。

| 表 | 漂移列数 | 例 |
|:---|---:|:---|
| `stock_daily_basic` | 10 | `volume_ratio` 活库 `NUMERIC(8,4)` vs DDL `NUMERIC(18,6)` |
| `stock_moneyflow` | 9 | `buy_elg_amount` `(12,4)` vs `(18,6)` |
| `stock_daily` / `stock_weekly` / `stock_monthly` | 各 6 | `open`/`high`/`low`/`pre_close`/`change` |
| `stock_adjusted_prices` | 7 | `pct_chg` `(8,4)` vs `(18,6)` |
| 其余 7 张表 | 各 1–7 | `stock_dividends` / `stock_forecasts` / `stock_expresses` / `monitor_thresholds` / `system_health_metrics` … |

**后果（实测复现）**：窄列遇**合法大值**即整批失败 ——

```
Tushare daily_basic 对 000918.SZ 2009-04-30 返回 volume_ratio = 12,148.94
  （停牌复牌后量比，合法值）
stock_daily_basic.volume_ratio 活库上限 9999.9999  ← 溢出
→ asyncpg NumericValueOutOfRangeError → 该批 1000+ 行全部回滚
```

**根因**：活库建表用的是**旧版 DDL**；DDL 后来把比例列统一放宽到 `NUMERIC(18,6)`，
而本项目**无迁移框架**（DDL「直接执行」）→ 活库从未被 ALTER。

**处置**：迁移脚本已就绪 —— `scripts/data/sync_numeric_precision_to_ddl.py`
（**幂等**、默认 **dry-run**、**只加宽不收窄**，加宽在构造上不丢数据）。

> 🔴 **必须走停机窗口**：`ALTER TABLE ... ALTER COLUMN TYPE` 取 **ACCESS EXCLUSIVE** 锁，
> 且大表（`stock_daily_basic` 877 万行 / `stock_moneyflow` 1,393 万行，均为**压缩 hypertable**）
> 需解压-重写-再压缩 → **会在数分钟内阻塞运行中的服务**。
> 2026-09-19 首次尝试即被服务的 `idle in transaction` 会话锁住，已中止（完成 2 列，加宽无副作用）。
