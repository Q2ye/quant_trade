## v1.0 — 原始移植版

**优化方向**：从聚宽源策略移植到系统框架

**代码文件**：`modules/strategy/strategies/reference/stock_low_high_strategy.py`

**主要特性**：
- 全市场扫描选股（6 个条件：阳线 + 均线 + 量比 + ROC + MACD + 回踩）
- 最大持仓 3 只，每天调仓
- 固定 -4% 止损，抛物线止盈

**问题**：
- ❌ `_holdings` 自维护的持仓与 Broker 实际持仓不同步
- 发出卖出信号时 Broker 侧持仓已为 0，导致大量"订单验证失败: 持仓不足"错误
- 仓位计算全方位偏移

**结论**：❌ 有 Bug，不可用

## v3.0 — 总资金回撤止损

**优化方向**：基于持仓加权收益进行组合回撤保护

**核心逻辑**：
```python
_calc_portfolio_return() → 计算持仓加权收益
_check_portfolio_drawdown() → 从峰值回撤比例
回撤 > 15% → 降至 1 只
回撤 > 25% → 暂停买入
```

**一年期结果**：
| 指标 | 数值 |
|:---|:---:|
| 总收益 | +7.82% |
| 最大回撤 | 47.78% |
| 夏普 | 1.28 |

**失败原因**：Phantom drawdown。`_calc_portfolio_return()` 排除 `_exit_pending` 中的盈利股。当大赢家触发止盈进入待卖出队列后，其利润贡献从计算中消失，剩余亏损持仓拉低均值，产生虚假回撤信号，导致策略在最高权益时错误清仓。

**结论**：❌ Phantom drawdown 问题

## v3.1 — 连续止损计数器

**优化方向**：用计数器替代总资金回撤
- 连续止损 3 次 → 降至 1 只
- 连续止盈 2 次 → 恢复最大持仓

**一年期结果**：
| 指标 | 数值 |
|:---|:---:|
| 总收益 | -21.86% |
| 最大回撤 | 55.44% |

**失败原因**：策略胜率约 36%，意味着约 64% 的交易以止损结束。连续止损 3 次是常态（按 36% 胜率，约 26% 的概率出现），计数器频繁触发后策略被锁死在 1 只持仓，而 34% 的胜率下恢复条件几乎无法满足。

**结论**：❌ 低胜率策略下，连续止损计数器频繁误触发

## v4.0a — ATR 止损 + 时间止损 + 移动保本

**优化方向**：幽灵的礼物三规则
- ATR(20) 替代固定 -4% 止损
- 规则一：持仓 ≥5 bar 涨幅 < 1.5% → 时间止损
- 规则二：浮盈 ≥6% 止损移到成本 +1%

**一年期结果**：
| 指标 | 数值 |
|:---|:---:|
| 总收益 | +7.82% |
| 最大回撤 | 47.78% |
| 夏普 | 1.28 |

**失败原因**：时间止损切掉了大量本可以涨到 30%+ 的持仓（5 bar 内涨幅 <1.5% 就退出），移动保本在 6% 就把潜力股砍了。三层止损同时收紧，收益从 +42.75% 降到 +7.82%。

**结论**：❌ 任何持仓层级的离场逻辑改动都破坏收益

## v5.0 — 组合回撤保护（累计退出价值法）

**优化方向**：修复 Phantom drawdown
- 用 `_exited_entry_value` / `_exited_cash_value` 累积退出持仓的价值
- 回撤 > 15% → 降至 1 只，> 25% → 暂停买入

**核心算法**：
```
NAV 代理 = (_exited_cash_value + 当前持仓市值) / (_exited_entry_value + 总投入) - 1
```

**一年期结果**：
| 指标 | 数值 |
|:---|:---:|
| 总收益 | +25.24% |
| 最大回撤 | 57.91% |
| 交易笔数 | 72 |

**失败原因**：权重漂移。已退出交易的利润不断累积到 `_exited_cash_value`，虚拟资产池（600 万+）远超实际权益（100 万），后续新持仓的变化对 NAV 的边际影响越来越小，组合回撤保护逐渐失效——在一个有 600 万"累积退出价值"的账户中，亏 10 万的回撤比例只约 1.6%，永远不会触发 15% 的阈值。

**结论**：❌ 累计价值法有权重漂移问题

## v5.1 — 修复 P0（today_pool 包含当前持仓）

**优化方向**：池内池外区分止盈
- `today_pool = buy_list | (current_holdings - _exit_pending)`
- 池内股只止损，不止盈
- 池外股止损 + 抛物线止盈

**一年期结果**：
| 指标 | 数值 |
|:---|:---:|
| 总收益 | +53.07% |
| 最大回撤 | 45.81% |
| 夏普 | 1.23 |

**三年期结果**：
| 指标 | 数值 |
|:---|:---:|
| 总收益 | -32.42% |
| 最大回撤 | 76.60% |

**分析**：P0 池内不止盈大幅提升了一年收益。但三年期大幅亏损的核心原因是选股逻辑在 2023-2024 年的震荡市中频繁产生伪信号（短期反弹→买入→反弹结束→止损），同时下跌市时没有风控机制。

**结论**：✅ P0 逻辑（池内不止盈）有效；❌ 但缺市场状态过滤导致三年期亏损

## v6.0 — 源策略对齐（P0 + 差异二 + 差异三 + P1）

**优化方向**：
- P0：池内股只止损不止盈（修复 today_pool 为空）
- 差异二：半仓轮动（无空位时清仓最差池内股腾位）
- 差异三：两步合一步复检（用今日 bar 数据验证候选股）
- P1：买入价下限（不得低于 20 日新高 92%）

**一年期结果**：
| 指标 | 数值 |
|:---|:---:|
| 总收益 | +26.22% |
| 最大回撤 | 50.66% |
| 夏普 | 1.10 |
| 胜率 | 38.3% |

**分析**：P0 生效，但 `today_pool` 的定义有一行 Bug——候选股排除当前持仓，导致池内股全部被视为"池外"，池内不止盈的保护实际上没生效。

**结论**：⚠️ P0 未生效（Bug），半仓轮动 + 两步复检 + 买入价下限已在正确运行

## v6.10 — 拉高出货检测（❌ 失败）

**创建**: 2026-07-20 | **回测**: 2026-07-21 00:51:39 | **结论**: ❌ **收益腰斩，不采用**

### 5 年回测对比 (2021-07 ~ 2026-07)

```
指标              v7.0 基线(行业黑名单)    v6.10 P2拉高出货       Δ
──────────────────────────────────────────────────────────────────
总收益              +86.77%                 +45.86%              -40.91pp 🔴
年化收益            +13.92%                  +8.18%              -5.74pp
最大回撤             34.53%                  32.30%              -2.23pp (微弱改善)
Sharpe              0.72                     0.48               -0.24
胜率                 37.45%                   37.24%             -0.21pp (持平)
交易笔数             721                      709                -12 笔
耗时                  —                       5495s (91min)
```

### 分层分析

**第一层：为什么胜率没变？**

过滤器的预期效果是"去掉坏信号 → 胜率提升"。实际胜率 37.45% → 37.24%，完全没变。说明：
- 被拦截的 12 笔交易的胜率 ≈ 策略平均胜率（37%）
- 拦截的不是"更差的交易"，而是"同样质量的交易"
- 过滤没有区分度——好坏通杀

**第二层：为什么收益暴跌？**

收益 = 胜率 × 平均盈利 - (1-胜率) × 平均亏损。胜率没变，那问题出在：
- **拦截的 12 笔中包含了大赢家**。在只拦截 12 笔的情况下总收益少 41pp，说明拦截的少数交易中一定有盈利 +50%~+200% 的池内长跑股
- 策略的 α 来自"少数大赢家"——**每拦截 1 个大赢家，代价是 10~20 个小止损**
- 这正是 v4.0a/v4.0b/v6.0+15% 反复验证的规律

**第三层：为什么 P2 会拦截大赢家？**

```
真实的大赢家路径:
  涨停 → 涨停 → 缩量小回调(-3%) → 再涨50%+ 
  
P2 检测器看到的:
  S1: 末次涨停量可能略高于前次（正常的动量递增）
  S3: 连续涨停=2，未触发（pd_parabolic_consecutive=3）
  → score=1，放行 ✅
  
被拦截的是什么？
  S1 放量见顶 + S2 出货日 同时触发的情况
  → 涨停后的正常获利回吐也被标记为"出货"
  → 拦截了本该在回调后继续上涨的强势股
```

**第四层：0 条日志，究竟拦截了谁？**

整个 5 年回测中 `P2拦截` 日志为 0 条——因为 `verbose_logging` 在回测引擎中未被启用。但交易少了 12 笔说明确实有股票被 `return False` 拦截。

拦截路径有两种可能：
1. 在 `_passes_screen` 中（初筛阶段）→ 候选股减少
2. 在 `_recheck_buy_list` 中没有额外拦截

12 笔 ÷ 5 年 = 年均拦截 2.4 笔，看起来很少，但每笔都是潜在的复利贡献者。

**第五层：与行业黑名单的本质不同**

| 维度 | 行业黑名单 (v7.0) | P2拉高出货 (v6.10) |
|:---|:---|:---|
| 排除逻辑 | 排除整个行业（钢铁/汽车/建筑等） | 排除个股特征（涨停+放量+回落） |
| 优化信号 | ✅ 系统性的（某行业长期弱于大盘） | ❌ 个例性的（特定K线形态） |
| 可预测性 | 高（行业轮动有持续性） | 低（K线形态随机性强） |
| 副作用 | 错过该行业的大涨股（但行业整体弱） | 错过该形态的大涨股（形态≠未来） |
| 为什么成功/失败 | 牺牲了上限，换来了下限 | 上限和下限一起砍了 |

行业黑名单成功是因为它排除了**持续弱势**的板块，长期确实是拖累。P2 失败是因为K线形态的预测能力太弱——涨停后放量回调既可以是出货，也可以是上涨中继，只靠量价形态无法区分。

**核心教训**:
1. 技术上漂亮的检测器 ≠ 实盘有用的过滤器
2. 拦截的股票"平均差"（中位数 -6.16%）≠ 拦截它们能提高组合收益（因为拦截了少数超级大赢家）
3. 策略的 -4% 止损已经把烂股的伤害限定在单笔 4%，额外的入场过滤必须证明自己比止损更聪明
4. 和激进v1/v2 一样——"优化入场/退出"在这个策略数学结构下几乎总是负向的

**结论**: ❌ **不采用**。v7.0 行业黑名单仍是历史最优基线。P2 检测器代码保留在策略文件中但不启用（`pump_dump_filter_enabled: False`）。

### v6.10 升级 — 多信号拉高出货检测器（2026-07-20）

**升级原因**: 旧版 `_count_recent_limit_ups` 只数涨停个数——过于粗糙：
- ❌ "3 连板后缩量小回调"（强势股健康调整）→ 被误杀
- ❌ 没有区分"放量出货"和"缩量回调"
- ❌ 没有考虑连板位置（低位反转 vs 高位衰竭）

**新设计: 四维信号交叉验证**

```
信号      维度            检测内容                          触发条件
──────────────────────────────────────────────────────────────────
S1 放量见顶   量价背离      末次涨停量 / 前几次均量            > 1.5x
S2 出货日     量+价+振幅    涨停后出现: 放量(>20日均1.5x)    三者同时满足
                           + 收阴 + 振幅 > 5%
S3 抛物线衰竭 连板+回落     ≥3 个连续涨停                     两者同时满足
                           + 从高点回落 > 5%
S4 高位异常量 量能分位      近5日均量处于近60日的 top 10%     单独成立
```

**决策表**:
```
命中 0 个信号 → 正常候选，放行
命中 1 个信号 → 边缘情况，放行（verbose 日志记录）
命中 2+ 个信号 → 拉高出货确认 → _passes_screen 返回 False
```

**与旧版的核心区别**:
| 维度 | 旧版 (v6.10 初版) | 新版 (v6.10 升级) |
|:---|:---|:---|
| 判断依据 | 单维度: count(涨幅>=9.5%) | 四维度 × 独立阈值 |
| 误杀风险 | 高（2涨停就杀） | 低（需2+信号交叉确认） |
| 场景A 出货股 | ✅ 会拦截 | ✅ S2+S3 双信号确认 |
| 场景B 涨停+缩量回调 | ❌ 误杀！ | ✅ score=0 放行 |
| 场景C 无涨停强势股 | ✅ 放行 | ✅ score=0 放行 |
| 可解释性 | 差（为什么2个就杀？） | 好（日志输出具体信号） |

**冒烟测试结果**:
```
场景A (3连板+放量出货): score=2 → S2:出货日 + S3:抛物线衰竭 → 拦截 ✅
场景B (涨停+缩量回调):   score=0 → 放行 ✅（旧版会误杀）
场景C (正常强势股):      score=0 → 放行 ✅
```
