# 信号链路可视化追溯设计方案

> 2026-08-10 | 前端页面设计 | 涉及 `quant_web/src/views/Signal/` + `api/trade.ts`
> 关联：方案 C（信号全链路 parent_id 关联）· 信号生命周期管理

---

## 1. 背景与目标

### 1.1 背景

方案 C 引入 `signals.parent_id` 字段，串起完整链路：
```
候选(promoted) ──parent_id──→ 买入信号(pending_manual) ──order_id──→ 订单 → 成交
```

当前前端**无法看到这条链路**——候选、信号、订单是孤立的记录。

### 1.2 目标

在信号管理页面提供**可视化追溯面板**，一条链路（候选 → 信号 → 订单 → 成交）完整呈现，各环节可点击查看详情，支持双向跳转。

## 4. 链路结构

### 4.1 链路节点

```
┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐
│ 候选     │→ │ 买入信号 │→ │  订单   │→ │  成交   │
│ candidate│  │ signal  │  │ order   │  │ trade   │
└─────────┘  └─────────┘  └─────────┘  └─────────┘
```

| 节点 | 数据 | 状态 |
|:---|:---|:---|
| **候选** | signals（parent_id 源，signal_type=buy） | pending_confirm / promoted / expired |
| **买入信号** | signals（id=parent_id 目标） | pending_manual / confirmed / rejected |
| **订单** | orders（signals.order_id） | submitted / filled / partial / cancelled |
| **成交** | trades/positions | completed |

### 4.2 链路方向

- 从**候选**发起：候选 → 信号 → 订单 → 成交（顺向）
- 从**信号**发起：信号 → 候选（逆向）+ 信号 → 订单 → 成交（顺向）
- 从**订单**发起：订单 → 信号 → 候选（逆向）

### 6.4 交互细节

| 交互 | 行为 |
|:---|:---|
| 节点点击 | 切换下方详情区内容 |
| 连接箭头 | 固定，表示数据流方向（候选→信号→订单→成交） |
| 节点状态色 | 见 6.2，异常链路（如候选 expired 但信号仍发）标红 |
| 复制信号ID | 复制当前节点 id |
| 查看订单 | 有 order_id 时跳转订单详情 |
| 关闭 | 右上角 × / 点击遮罩 |

### 6.5 数据接口

```ts
// GET /quantTrade/signals/{id}/trace
interface SignalTrace {
  candidate?: {
    id, ts_code, signal_time, price, signal_status, reason
  };
  signal?: {
    id, signal_time, price, quantity, signal_status, order_id, reason
  };
  order?: {
    id, status, price, quantity, filled_quantity
  };
  trade?: {
    ts_code, quantity, price, trade_time, status
  };
}
```

async getSignalTrace(signalId: string): Promise<SignalTrace> {
