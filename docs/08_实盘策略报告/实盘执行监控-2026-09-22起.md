### ⚠️ V3 订正专条（2026-09-23）——「间隔路径」结构性不可达

> **结论**：V3 的**判据**（机制正确性）**不受影响**，仍由 `test_cross_market_exit_retry.py` 6 例钉死；
> 但**「真机间隔路径」这条路在实盘不可达**，**不应继续作为待办挂着等**。**非系统缺陷**。

**机制事实（代码实证）**

| # | 事实 | 出处 |
|:--|:---|:---|
| 1 | `_exit_pending: Dict[str, int]` 记录「上次发退出信号时的调仓序号」，**纯内存** | `cross_market_momentum_strategy.py:525` |
| 2 | `_should_retry_exit`：`last is None → 立即允许`；否则 `(_rebalance_seq - last) >= exit_retry_days` | `:1628-1631` |
| 3 | `exit_retry_days = 3`；`_rebalance_seq` **每进程从 0 起算**，每调用 `_run_rebalance` +1 | `:235` / `:565` / `:789` |
| 4 | `_exit_pending.clear()` + `_rebalance_seq = 0` 在初始化/重启路径执行 | `:564` / `:750` |
| 5 | **`load_live_state` 只恢复 `positions` 与 pending 信号，不恢复 `_exit_pending`** | `base_strategy.py:198-231` |

**推论**：要走到「+1/+2 跳过」或「+3 重发」，必须是**同一进程内**、某标的卖出信号连续跨 **≥3 个调仓日**仍未执行
（登记于 seq=N，最早 seq≥N+3 才允许重发）。**进程一旦更换，登记与序号同时清零 → 永远回到「未登记 → 立即允许」。**

**实盘实证：每一次驱动都跑在不同 PID 上**

| 日期 | 驱动时刻 | PID |
|:---|:---|:---|
| 2026-09-21 | 19:33:27 | 13848 |
| 2026-09-21 | 20:55:29（手动重跑） | **1664** |
| 2026-09-21 | 21:38:30（手动重跑） | **8008** |
| 2026-09-22 | 19:33:39 | **15520** |
| 2026-09-23 | 19:33:34 | **18064** |
| *(下次)* | — | **3064**（09-23 22:08 启动） |

→ **5 次驱动 = 5 个不同进程，无一次沿用上一进程的 `_exit_pending`** → 该分支**在实盘从未执行过**。

**对台账原表述的订正**

| 原表述（09-22 写入） | 订正 |
|:---|:---|
| 「**间隔路径**等自然触发（**任何一次卖出未及时执行即可复现**）」 | ❌ **前提错误**。仅"卖出未执行"**不够**，还需"**同一进程内连续 ≥3 个调仓日**"。在"每次驱动前进程都被更换"的现状下，该条件**永久不可达** |

**为什么不影响运营**：卖出意图实际由**信号层每日重发**兜住了（旧行 `superseded: 被新信号覆盖`，新行当日重新登记）
→ 持仓不会因退出信号丢失而冻结。V3 的策略侧重发只是**第二道兜底**，它不生效的代价是"少一道冗余"，不是"功能缺失"。

**建议**：① 台账 §三 V3 状态改为「判据 ✅ / 真机间隔路径 **不可达**（进程更替使其不可复现）」，
**不再列为待观察项**；② 若确需真机验证该路径，唯一可行方式是**让同一进程连跑 ≥4 个调仓日**（即观察期内刻意不重启）
—— 这属"为验证而改变运行方式"，需你决定是否值得（当前无运营必要）。
